# 工作流运行时新增接口列表

> 更新时间：2026-07-08
> 模块：Workflow Runtime
> 路由前缀：`/api/app/workflow`

## 0. 术语约定（2026-07 CodeSYS 四层对齐）

- `WorkflowDefinition`（工作流 / POU）：单个工作流，等价项目内可编排单元。
- `Task`（任务配置，原 `Binding`）：项目内工作流启用、执行顺序与触发类型（Immediate/Cyclic）配置，等价 CodeSYS 任务；路由由 `/bindings` 改为 `/tasks`。
- `Deployment`（部署 / 写入 PLC）：根据当前已启用任务配置发布的部署快照，冻结完整 `GraphData` 与变量定义；创建运行的强制前置。
- `Run`（运行，原 `Task`）：基于已激活部署快照创建的后台执行实例；路由由 `/tasks` 改为 `/runs`；已移除 legacy 回退。
- `Execution`：单个工作流运行/调试会话。

## 1. 项目任务配置接口

### 1.1 查询项目任务配置

- Method: `GET`
- Path: `/api/app/workflow/projects/{projectId}/tasks`
- 对应方法：`GetProjectTasksAsync`
- 说明：必须传入 `projectId`，返回该项目的任务配置对象（项目级触发配置 + 工作流行项）。

响应体：`WorkflowProjectTaskBatchDto`

结构：

- `projectId`
- `taskType`（项目级触发类型：0=Immediate, 1=Cyclic）
- `cycleIntervalSeconds`（仅 Cyclic 有效）
- `items: List<WorkflowProjectTaskDto>`

行项字段（`WorkflowProjectTaskDto`）：

- `id`
- `projectId`
- `workflowId`
- `workflowName`
- `isEnabled`
- `orderNo`

### 1.2 更新项目任务配置

- Method: `PUT`
- Path: `/api/app/workflow/projects/tasks`
- 对应方法：`UpdateProjectTasksAsync`
- 说明：提交 `WorkflowProjectTaskBatchDto` 整体覆盖项目任务配置；`taskType`/`cycleIntervalSeconds` 为项目级，`items` 控制各工作流的启用与顺序。返回值与 GET 一致。

请求体（`WorkflowProjectTaskBatchDto`）:

```json
{
  "projectId": "guid",
  "taskType": 0,
  "cycleIntervalSeconds": null,
  "items": [
    {
      "workflowId": "guid",
      "isEnabled": true,
      "orderNo": 10
    }
  ]
}
```

## 2. 项目部署接口

### 2.1 查询项目部署历史

- Method: `GET`
- Path: `/api/app/workflow/projects/{projectId}/deployments`
- 对应方法：`GetProjectDeploymentsAsync`

响应体：`List<WorkflowProjectDeploymentDto>`

关键字段：

- `id`, `projectId`, `revision`, `status`
- `isCurrentActive`
- `snapshotHash`, `itemCount`
- `activatedAt`, `activatedBy`, `creationTime`
- `canActivate`, `canReactivate`, `canRollback`

响应示例：

```json
[
  {
    "id": "8f5f6a61-9f02-44a4-9b58-bfe4f7b2ab31",
    "projectId": "b30f3c9d-c7c1-4a5f-aefb-8f8ab58d4f0d",
    "revision": 7,
    "status": 1,
    "isCurrentActive": true,
    "canActivate": false,
    "canReactivate": true,
    "canRollback": false,
    "snapshotHash": "c6de3f0e3f5d5e7ad6676bbf0b9f95df",
    "itemCount": 3,
    "activatedAt": "2026-07-07T09:25:10.000Z",
    "activatedBy": "f8f1db45-36a4-4de7-b2eb-9e8bc23ca95e",
    "creationTime": "2026-07-07T09:20:00.000Z"
  }
]
```

### 2.2 发布项目部署快照

- Method: `POST`
- Path: `/api/app/workflow/projects/{projectId}/deployments`
- 对应方法：`PublishProjectDeploymentAsync`
- 说明：根据当前已启用任务配置发布新的部署版本；快照冻结工作流名称、顺序、完整 `GraphData` 与项目变量定义默认值（存入 `FrozenGraphsJson`/`FrozenVariablesJson`）。

### 2.3 激活部署

- Method: `POST`
- Path: `/api/app/workflow/deployments/{deploymentId}/activate`
- 对应方法：`ActivateProjectDeploymentAsync`
- 说明：将指定部署切换为当前激活版本，并归档同项目其他已激活部署。

### 2.4 重新激活部署

- Method: `POST`
- Path: `/api/app/workflow/deployments/{deploymentId}/reactivate`
- 对应方法：`ReactivateProjectDeploymentAsync`
- 说明：对历史已发布或已归档版本重新激活；若目标已处于激活状态，直接返回当前版本信息。

### 2.5 回滚到历史部署

- Method: `POST`
- Path: `/api/app/workflow/deployments/{deploymentId}/rollback`
- 对应方法：`RollbackProjectDeploymentAsync`
- 说明：回滚到指定历史部署，本质上是激活旧 revision；若目标已是当前激活版本，则返回业务错误。

## 3. 项目运行接口（Hangfire）

### 3.1 创建并入队项目运行

- Method: `POST`
- Path: `/api/app/workflow/runs`
- 对应方法：`EnqueueProjectRunAsync`
- 说明：必须存在已激活部署快照（已移除 legacy 回退），从冻结快照执行工作流列表；`startType=1` 时为周期运行，需 `cycleIntervalSeconds`。

请求体（`WorkflowProjectRunEnqueueInput`）:

```json
{
  "name": "运行名称",
  "projectId": "guid",
  "startType": 0,
  "cycleIntervalSeconds": null,
  "onErrorAction": 0
}
```

响应体（`WorkflowProjectRunEnqueueResultDto`）关键字段：

- `runId`, `projectId`, `workflowCount`, `hangfireJobId`
- `deploymentId`, `deploymentRevision`

响应示例：

```json
{
  "runId": "a3d43b13-8b1b-4f6f-84fe-c525f0bcf5ab",
  "projectId": "b30f3c9d-c7c1-4a5f-aefb-8f8ab58d4f0d",
  "workflowCount": 3,
  "hangfireJobId": "21873",
  "deploymentId": "8f5f6a61-9f02-44a4-9b58-bfe4f7b2ab31",
  "deploymentRevision": 7
}
```

### 3.2 查询项目运行列表

- Method: `GET`
- Path: `/api/app/workflow/runs`
- 对应方法：`GetProjectRunsAsync`
- Query：`name`, `projectId`, `skipCount`, `maxResultCount`

### 3.4 请求取消项目运行

- Method: `POST`
- Path: `/api/app/workflow/runs/{runId}/cancel`

### 3.5 修改项目运行

- Method: `PUT`
- Path: `/api/app/workflow/runs/{runId}`
- 说明：仅允许修改运行名称和错误策略；执行中的运行不允许修改；若为周期运行，取消/删除将同时移除 RecurringJob。

### 3.6 删除项目运行

- Method: `DELETE`
- Path: `/api/app/workflow/runs/{runId}`

## 5. 联调建议

1. 先配置项目绑定，再发布 deployment，并显式激活目标 revision。
2. 创建任务后，优先检查返回中的 `deploymentId` / `deploymentRevision`，确认本次任务绑定的是哪个部署版本。
3. 若创建任务时报“发布后发生变化”，说明部署快照中的工作流 `GraphData` 指纹与当前库中版本不一致，需要重新发布部署。
4. 前端可直接使用 `canActivate`、`canReactivate`、`canRollback` 决定部署列表上的操作按钮是否可点击。
