# 工作流任务列表前端流程

> 更新时间：2026-07-08
> 依据：`Tools/workflow_runtime_regression.py` 回归链路（固定 19 项）
> 路由前缀：`/api/app/workflow`

## 0. 2026-07 重构变更

- 本页的「任务」现对应后端「运行 Run」，路由由 `/tasks` 改为 `/runs`（页面名称可保留“任务列表”习惯称呼）。
- 启动运行前项目必须已发布并激活部署快照；无激活部署时后端拒绝创建，前端应引导用户先去「任务配置/部署」页发布激活。
- `startType` 新增 `1 = Cyclic`（周期），需传 `cycleIntervalSeconds`。

## 1. 目标

本文描述任务列表页在前端的推荐实现流程，重点覆盖：

- 任务创建/启动/查询/管理
- 任务 Debug（执行会话）
- 参数组装与返回落地
- 页面状态流转与异常处理

## 2. 页面模块划分

- 任务列表区：查询、筛选、分页、刷新
- 任务详情抽屉：任务基础信息 + items 子项
- 任务操作区：创建、取消、修改、删除
- 调试区：会话列表、启动调试、单步、状态轮询、停止调试

## 4. 任务列表页接口编排

### 4.1 初始加载

1. 调用 `GET /api/app/workflow/runs`
2. Query 参数：

- `ProjectId`（可选）
- `SkipCount`
- `MaxResultCount`

1. 成功后渲染列表；失败显示错误 toast 并保留重试入口。

### 4.2 创建/启动任务

1. 调用 `POST /api/app/workflow/runs`
2. Body：

- `name`
- `projectId`
- `startType`（当前用 `0`）
- `onErrorAction`（`0` 或 `1`）

1. 返回关键字段：

- `runId`
- `hangfireJobId`
- `workflowCount`
- `deploymentId`
- `deploymentRevision`

1. 成功后刷新列表并高亮新任务。

### 4.3 查询任务详情

1. 调用 `GET /api/app/workflow/runs/{runId}`
2. 重点读取：

- `status`
- `executedCount/successCount/failedCount`
- `items[]`（含 `workflowId/executionId/status/errorMessage`）

### 4.4 取消/修改/删除

- 取消：`POST /runs/{runId}/cancel`
- 修改：`PUT /runs/{runId}`，Body 包含 `name`、`onErrorAction`
- 删除：`DELETE /runs/{runId}`
- 统一处理：成功后刷新列表；失败根据状态码展示错误原因。

## 5. Debug 前端流程

### 5.1 查询调试会话

1. 调用 `GET /api/app/workflow/executions`
2. Query：

- `projectId`（可选）
- `runId`（可选）
- `includeVariables`（默认 false）

1. 返回 `List<WorkflowExecutionStatusDto>`。

说明：调试会话存储在内存，服务重启后列表清空，前端应视为空状态而不是报错。

### 5.2 启动调试

1. 调用 `POST /api/app/workflow/executions`
2. 入参规则：

- 必传 `projectId`
- `workflowId` 与 `runId` 至少传一个
- 常用模式：`mode=1`（DebugStep）

1. 最小可用 body（前端默认建议）：

```json
{
  "projectId": "guid",
  "runId": "guid",
  "mode": 1,
  "variableReadTimeoutMs": 1000
}
```

1. 为什么 Swagger 里会看到很多字段：

- Swagger 展示的是完整 DTO 契约，不是每次都必须全传。
- 实际前端常规调试只需要最小参数即可跑通。

1. 完整字段说明（按是否必须区分）：

- 必填：
  - `projectId`
  - `runId` 或 `workflowId`（二选一至少一个）
- 常用可选：
  - `mode`
    - 0 = RunOnce（一次性跑完，不用于单步）
    - 1 = DebugStep（可配合 steps 单步，前端调试推荐）
    - 2 = Loop（循环执行）
  - `variableReadTimeoutMs`
    - 不传时默认 5000
    - 建议传 >= 1000，避免 0 导致读取超时策略过于激进
- 仅特定场景才传：
  - `loopCount`：仅在 `mode=2` 时生效，且必须 > 0
  - `runtimeInstanceId`：需要复用在线变量池实例时传；不传由后端自动复用/生成
    - 在线变量池不是“全局只有一个值表”，而是按 `projectId + runtimeInstanceId` 隔离的实例空间
    - 复用同一个 `runtimeInstanceId` 的目的：让同一任务链路（含前置预热工作流与当前调试工作流）读取到同一份上下文变量
    - 不复用会导致命中新的实例空间，前面步骤写入的变量对后续调试不可见
  - `inputVariableBindings` / `outputVariableBindings`：显式指定跨工作流变量绑定时传
  - `inputVariableKeys` / `outputVariableNames`：不传时后端会按签名默认推导

1. 额外行为约束：

- 同时传 `runId` 和 `workflowId` 时，后端会校验 `workflowId` 必须属于该任务。
- 若仅传 `runId`，后端会按任务进度自动定位当前调试目标工作流。

1. 返回关键字段：

- `executionId`
- `status`（快照）

### 5.3 单步与状态刷新

- 单步：`POST /executions/{executionId}/steps`，Body：`{ "steps": 1, "includeVariables": false }`
- 状态：`GET /executions/{executionId}?includeVariables=false`
- 建议策略：
- 单步后立即拉取一次状态
- 运行中每 1~2 秒轮询
- 页面离开或切换任务时停止轮询

### 5.4 停止调试

- 调用 `DELETE /executions/{executionId}`
- 成功后移除当前调试面板状态并刷新会话列表。

## 6. 前端状态机建议

### 6.1 任务状态映射

- `Pending`
- `Running`
- `Succeeded`
- `Failed`
- `Canceled`

### 6.2 操作按钮可用性

- `Running`：允许取消，不允许删除
- `Pending`：允许取消、修改、删除
- `Succeeded/Failed/Canceled`：允许删除，是否允许修改按业务决定

## 7. 返回处理规范

### 7.1 统一成功处理

- 2xx 视为成功
- 204 按“无返回体成功”处理

### 7.2 统一失败处理

- 401：跳转登录或触发登录过期流程
- 403：无权限提示
- 404：资源不存在（可能被并发删除）
- 409/422：业务冲突或参数不合法，展示后端消息
- 5xx：统一“服务异常，请稍后重试”

## 8. 前端实现清单（可直接按此开发）

1. 任务列表页面：分页查询 + 刷新
2. 创建任务弹窗：字段校验（name/projectId/startType/onErrorAction）
3. 任务详情抽屉：展示 items 与计数
4. 取消/修改/删除操作：二次确认 + 操作后刷新
5. 调试面板：会话列表、启动调试、单步、状态轮询、停止调试
6. 错误处理：统一拦截器 + 业务提示
7. 可观测性：记录 `runId`、`executionId` 到日志上下文

- 脚本文件：`Tools/workflow_runtime_regression.py`
