# 3D 姿态标定与比较检测工作流第三方对接变更

> 生效日期：2026-08-26  
> 接口前缀：`/api/app/workflow`  
> 适用范围：姿态对齐标定、正式单次执行（RunOnce）及 3D 顶面点云比较结果读取

> 注意：仓库中的 `swagger.json` 是旧生成快照，仍包含 `scalarValue` 等历史字段，
> 尚未覆盖本次 `outputs/configuredOutputs` 变化。当前 3D 对接以本文和
> `src/api/workflow.ts` 为准，控制板 Swagger 可访问后需重新生成整份快照。

## 1. 当前部署信息

| 项目 | 当前值 |
| --- | --- |
| 控制板地址 | `http://10.24.1.143:5000` |
| 项目 ID | `3a234514-e887-bc78-8028-448a43d3d6b0` |
| 姿态标定工作流 ID | `3a234fec-b9bb-27ee-bd67-f01421a7d71f` |
| 正式检测工作流 ID | `3a23451f-fc5a-7deb-0935-a30ad7ccf14f` |
| 产品模型 ID | `3a233032-e206-d63c-cc70-ea0c37a0744d` |
| 产品模型名称 | `装配体1_20260820151507` |

地址和 ID 应作为部署配置保存，第三方程序不要写死。点云路径、固定工装姿态、数模轮廓容差和判定阈值已经配置在工作流内，不作为每次执行请求的输入字段。

### 1.1 两个工作流的分工

| 工作流 | 调用时机 | 作用 |
| --- | --- | --- |
| `3D姿态对齐标定` | 首次安装、相机/治具/模型变化或人工复标时 | 在固定工装角度先验附近识别合格顶面扫描相对完整数模的姿态 |
| `3D比较检测` | 每个产品检测周期 | 应用已固化姿态，按数模轮廓排除工装背景，再做一次精修和偏差判定 |

姿态标定不应在每个产品周期执行。标定结果通过审核后，将其中六个旋转/平移值写入正式检测图的“固定姿态变换”节点；正式检测不会自动修改自己的工作流配置。

## 2. 本次契约变化

| 旧接法或假设 | 当前接法 |
| --- | --- |
| `POST /api/app/workflow/execute` | `POST /api/app/workflow/executions` |
| 从顶层 `variables` 或 `resultImageUrls` 读取最终结果 | 以状态接口的 `outputs` 为正式结果来源 |
| RunOnce 完成后请求 `/executions/{id}/result` | RunOnce 不请求 `/result`；轮询状态接口并读取 `outputs` |
| 用 `status` 数字或是否有 `currentNodeId` 推断终态 | 使用 `isTerminal` 和 `debugState` |
| 把 NG 当成执行异常 | NG 是有效检测结果；只有 `faulted` 才是执行故障 |
| 文件字段可直接作为公开 URL | 当前返回相对地址，需拼接控制板 Base URL 并携带认证 |
| 字符串输出一定是普通字符串 | 新版本返回普通字符串；客户端仍需兼容旧服务或旧会话中多一层 JSON 引号的值 |

经当前控制板验证，RunOnce 执行的 `GET /executions/{executionId}/result` 会返回 HTTP 500 和“执行会话不存在”。该接口只保留给持久化调试会话使用，不能用于正式 RunOnce 对接。

## 3. 正式执行

### 3.1 触发

```http
POST /api/app/workflow/executions
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "projectId": "3a234514-e887-bc78-8028-448a43d3d6b0",
  "workflowId": "3a23451f-fc5a-7deb-0935-a30ad7ccf14f",
  "mode": 0,
  "loopCount": 1,
  "inputVariableKeys": [],
  "outputVariableNames": [
    "inspection_result",
    "footprint_filter_result",
    "aligned_cloud_download_url",
    "distance_image_download_url",
    "anomaly_image_download_url",
    "selected_model_id"
  ]
}
```

`mode` 当前使用 `0`（RunOnce）。请求成功后保存 `executionId`。即使触发响应已经带回 `status`，第三方仍应按第 3.2 节处理终态，避免因执行耗时或网关行为差异漏取结果。

### 3.2 查询状态和结果

```http
GET /api/app/workflow/executions/{executionId}?includeVariables=true
Authorization: Bearer <token>
```

建议每 500～1000 ms 查询一次，超时设置为 30 s。当前实测完整流程约 10 s，但不能把该耗时当成协议保证。

主要状态结构：


### 3.3 姿态对齐标定执行

姿态标定使用相同的触发和状态接口，只替换工作流 ID 和输出名称：

```json
{
  "projectId": "3a234514-e887-bc78-8028-448a43d3d6b0",
  "workflowId": "3a234fec-b9bb-27ee-bd67-f01421a7d71f",
  "mode": 0,
  "loopCount": 1,
  "inputVariableKeys": [],
  "outputVariableNames": [
    "pose_calibration_json",
    "pose_aligned_cloud_download_url",
    "selected_model_id"

```

| `name` | `valueType` | 含义 |
| --- | --- | --- |
| `pose_calibration_json` | `string` | 六自由度姿态、矩阵和可信度指标组成的 JSON 文本 |
| `pose_aligned_cloud_download_url` | `string` | 姿态对齐后点云的下载相对地址 |
| `selected_model_id` | `string` | 本次标定使用的产品模型 ID |

`pose_calibration_json` 需要先按第 4.2 节去掉状态快照的 JSON 字符串包装，再对内部 JSON 文本反序列化一次：


## 4. 3D 比较输出格式

正式结果位于状态响应的 `outputs` 数组。当前工作流输出：

| `name` | `valueType` | 含义 |
| --- | --- | --- |
| `inspection_result` | `object` | 判定、原因和点云比较指标 |
| `footprint_filter_result` | `string` | 产品轮廓保留/排除点数及轮廓容差组成的 JSON 文本 |
| `aligned_cloud_download_url` | `string` | 对齐后点云 `.ply` 下载相对地址 |
| `distance_image_download_url` | `string` | 距离伪彩色图 `.png` 预览相对地址 |
| `anomaly_image_download_url` | `string` | 带红色异常填充、轮廓及编号的 `.png` 标注图 |
| `selected_model_id` | `string` | 本次使用的产品模型 ID |

`configuredOutputs` 用于确认服务端声明了哪些输出，`outputs` 才包含本次实际值。终态时仍缺少必需输出，应按接口数据不完整处理并记录完整状态响应。

### 4.1 `inspection_result`

```ts
interface InspectionResult {
  isValid: boolean
  isOk: boolean
  resultCode: 'OK' | 'NG' | 'UNKNOWN' | 'ERROR'
  message: string
  reasons: string[]
  details?: CloudCompareDetails | null
}
```

顶层字段使用 lower camel case；`details` 内字段由当前算子类型直接序列化，使用 PascalCase。第三方反序列化时必须保留这一大小写差异。

`CloudCompareDetails` 的主要字段如下：

```ts

  SourcePointCount: number
  TargetPointCount: number

    DefectCount: number
    DefectRatio: number
    Threshold: number

    UnmatchedPointCount: number
  }
  PositionDifference: {
    TranslationX: number
    TranslationY: number
    TranslationZ: number
    TranslationMagnitude: number
    RotationAngleDeg: number
    RotationMatrix: number[]
  }
  RegistrationMethod: string
  UsedCoarseRegistration: boolean
  IsOk: boolean
  MaxDefectRatio: number
  MaxMeanDistance: number
  MissingRatio: number
  MaxMissingRatio: number
  MissingSurfaceCheckEnabled: boolean
  EffectiveVoxelSizeMm: number
  EffectiveMaxCorrespondenceDistanceMm: number
  SourceRegistrationPointCount: number

```

距离和位移单位为 mm，角度单位为度；`DefectRatio`、`MissingRatio` 和各类 Ratio 的范围为 0～1，界面显示百分比时再乘 100。

当前阈值由工作流维护：距离阈值 3.0 mm、最大超差比例 0.25、最大平均偏差 1.2 mm、最大配准 RMSE 3.0 mm。第三方只展示结果，不应在执行请求中重复传阈值。

`footprint_filter_result` 的内部 JSON 格式：

```ts
interface ReferenceFootprintFilterResult {
  sourcePointCount: number
  referencePointCount: number
  keptPointCount: number
  ignoredPointCount: number
  keptRatio: number
  lateralToleranceMm: number
}
```

该字段只说明哪些扫描点位于 CAD 的 XY 投影足迹内，不参与 OK/NG 阈值放宽。孔洞中可见的工装和产品轮廓外背景会被排除；产品区域内保留下来的点仍按原 3 mm 和平均偏差阈值检测。

### 4.2 字符串输出兼容

新版本状态接口直接返回普通 `string`。旧服务或升级前已持久化的会话中，字符串可能是
JSON 编码后的标量文本，例如：

```json
{
  "name": "distance_image_download_url",
  "valueType": "string",
  "value": "\"/api/app/operator-file/preview?blobName=...png\"",
  "stagedKey": null
}
```

客户端只对 `valueType === "string"` 或 `valueType === "blob"` 的字符串值尝试
`JSON.parse` 一次，并且只在解析结果仍为字符串时采用解析结果。对象和数组不得再次反序列化。

新版本中，持久化调试会话 `/result` 的每个输出与状态接口 `outputs` 中的同名输出
保持相同的 `name`、`displayName`、`valueType` 和 `value`。调试接口不再把文件下载
地址二次转换为 Blob Key。例如两种模式中的姿态对齐点云都应为：

```json
{
  "name": "pose_aligned_cloud_download_url",
  "displayName": "姿态对齐点云",
  "valueType": "string",
  "value": "/api/app/operator-file/download?blobName=a1b2c3d4e5f67890abcdef1234567891%2F20260826192659_650_pose-aligned-cloud.ply"
}
```

旧版本调试接口可能返回 `valueType: "blob"` 的原始 Blob Key，甚至错误保留末尾双引号，
JSON 中显示为 `.ply\"`。项目客户端仍保留该历史格式的兼容处理。

项目客户端已经提供：

- `decodeWorkflowOutputValue`
- `findWorkflowOutput`
- `parse3DComparisonOutputs`
- `parsePoseAlignmentOutputs`
- `resolveWorkflowFileUrl`
- `waitForWorkflowExecution`

实现位置：`Sources/AuroraStruct3D/AuroraStruct3D.Frontend/src/api/workflow.ts`。

### 4.3 文件地址

文件输出不是公开绝对地址，示例：

```text
/api/app/operator-file/download?blobName=...ply
/api/app/operator-file/preview?blobName=...png
```

新版本的调试和 RunOnce 都返回相同的相对文件地址。项目客户端的
`resolveWorkflowFileUrl` 仍兼容旧版本返回的原始 Blob Key。

调用方应使用控制板 Base URL 解析相对地址，并在预览或下载请求中携带与 API 相同的 Cookie 或 Bearer Token。不要缓存某次执行返回的临时 Blob 地址作为下一次执行结果。

`distance_image_download_url` 是未标注的距离伪彩色图。`anomaly_image_download_url`
在同一投影上将距离超过工作流阈值（当前 3 mm）或没有有效模型对应点的区域绘制为
红色半透明填充和红色轮廓，并标记 `NG-1`、`NG-2` 等编号；图像顶部显示异常区域数、
异常点数和阈值。该图片用于人工查看，目前仍不是机器可读的异常坐标/轮廓数据。

## 5. OK、NG 与执行故障

按以下顺序判定：

1. `debugState === "faulted"`：工作流执行故障，读取 `errorCode`、`errorMessage` 和 `faultNodeId`。
2. `debugState === "stopped"`：执行被停止，不产生有效检测结论。
3. `debugState === "completed"` 且 `inspection_result.isValid === true`、`isOk === true`：有效 OK。
4. `debugState === "completed"` 且 `inspection_result.isValid === true`、`isOk === false`：有效 NG，具体原因读取 `reasons`。
5. 已完成但 `isValid === false`，或缺少 `inspection_result`：检测数据无效，不应归类为产品 NG。

NG 是产品检测结果，不应触发“接口调用失败”重试。只有网络失败、超时、`faulted` 或结果数据不完整才进入技术错误处理。

## 6. TypeScript 调用示例

```ts
import {
  executeWorkflow,
  parse3DComparisonOutputs,
  resolveWorkflowFileUrl,
  waitForWorkflowExecution,
} from '@/api/workflow'

const baseUrl = 'http://10.24.1.143:5000'
const started = await executeWorkflow({
  projectId: '3a234514-e887-bc78-8028-448a43d3d6b0',
  workflowId: '3a23451f-fc5a-7deb-0935-a30ad7ccf14f',
  mode: 0,
  loopCount: 1,
  outputVariableNames: [
    'inspection_result',
    'aligned_cloud_download_url',
    'distance_image_download_url',
    'anomaly_image_download_url',
    'selected_model_id',
  ],
})

if (started.error || !started.executionId) {
  throw new Error(started.message ?? started.errorCode ?? '工作流启动失败')
}

const status = started.status.isTerminal
  ? started.status
  : await waitForWorkflowExecution(started.executionId, {
      intervalMs: 750,
      timeoutMs: 30_000,
    })

if (status.debugState === 'faulted') {
  throw new Error(status.errorMessage ?? status.errorCode ?? '工作流执行失败')
}
if (status.debugState !== 'completed') {
  throw new Error(`工作流未正常完成：${status.debugState}`)
}

const output = parse3DComparisonOutputs(status)
if (!output.inspectionResult) throw new Error('缺少 inspection_result')

const pointCloudUrl = output.alignedPointCloudUrl
  ? resolveWorkflowFileUrl(baseUrl, output.alignedPointCloudUrl)
  : undefined
const distanceImageUrl = output.distanceImageUrl
  ? resolveWorkflowFileUrl(baseUrl, output.distanceImageUrl)
  : undefined
const anomalyImageUrl = output.anomalyImageUrl
  ? resolveWorkflowFileUrl(baseUrl, output.anomalyImageUrl)
  : undefined

const decision = output.inspectionResult.isValid
  ? output.inspectionResult.isOk ? 'OK' : 'NG'
  : 'INVALID'
```

## 7. 三方升级检查表

- 姿态标定和正式检测分别配置各自的工作流 ID，不再临时改写同一个工作流。
- 姿态标定只在安装/治具/相机/模型变化时运行，并在人工确认后固化六个参数。
- 请求路径已经切换到复数 `/executions`。
- 正式检测请求明确指定五个 `outputVariableNames`。
- 使用 `executionId` 查询状态并等待 `isTerminal`。
- RunOnce 不调用 `/executions/{id}/result`。
- 从 `outputs` 按 `name` 取值，不依赖数组顺序。
- 字符串输出安全解码一次，对象输出直接使用。
- 区分有效 NG 与 `faulted` 执行故障。
- 相对文件地址拼接控制板 Base URL，并携带认证。
- 客户端超时不少于 30 s，轮询间隔不低于 500 ms。
- 展示异常时使用 `anomaly_image_download_url`，不要用未标注的距离伪彩图替代。
- 异常标注图用于人工查看，不把它误当成结构化异常坐标数据。
