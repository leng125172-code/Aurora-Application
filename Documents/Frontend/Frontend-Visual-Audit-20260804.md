# AuroraStruct3D 前端视觉审计与修复报告

日期：2026-08-04  
测试环境：`local-test` 前端 + 远程开发板 `10.40.154.143:5000`

## 覆盖范围

- 24 个可稳定直达的登录后路由，涵盖 Dashboard、视觉项目、Swagger、CAP、Hangfire、Profiler、系统信息、工作流 IDE、设备状态、相机、光机、串口、电机、PLC、产品模型、AI 模型和标定项目。
- 视口：1920×1080、1366×768、768×1024、390×844。
- 变体：简体中文/英文、浅色/深色，共 384 个路由组合。
- 状态：默认、加载、空数据、筛选器、长表格和实时数据页面。
- 安全边界：未执行设备控制、扫描、启停、保存、上传或删除。

## 已发现并修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P1 | 顶栏在手机宽度下同时展示设备模式和伺服采样控件，容易挤压语言、主题和用户操作 | 小屏隐藏非核心设备控制，仅保留状态和全局操作；统一高度与间距 |
| P1 | Dashboard 指标卡固定为 250px，手机端右侧留下大面积空白 | 改为响应式网格，手机单列满宽，平板双列，桌面按宽度扩展 |
| P1 | 故障历史筛选区使用固定内联网格，窄屏存在溢出风险 | 改为手机单列、平板标签/控件双列、宽屏双组布局 |
| P1 | 英文界面仍显示“来源、次数、系统、相机”等中文硬编码 | 增加中英文 i18n 键并替换硬编码 |
| P2 | 登录校验错误在切换语言后保留旧语言 | 语言变化时清理旧校验状态，避免中英文混排 |
| P2 | System Info 的 CPU 核数和运行时间直接显示服务端中文 | 使用前端本地化格式，根据服务端时间计算中英文运行时长 |
| P2 | 全局表格在手机端强制最小宽度 44rem，横向浏览负担过大 | 按手机宽度下调表格最小宽度并保留受控横向滚动 |
| P2 | 卡片默认使用动态光束，管理页面视觉噪声较高 | 工业控制台卡片默认关闭光束，仅显式品牌卡保留动画 |
| P2 | 浅色主按钮金色对比度偏低，深色背景偏纯黑 | 加深浅色主色并改为冷中性工业背景；深色使用蓝黑层级 |
| P2 | 页面容器、弹窗长文本、代码块和数据表缺少统一宽度约束 | 增加共享页面、工具栏、表面层和溢出约束 |
| P3 | 键盘焦点样式不统一，动态效果未尊重减少动画偏好 | 增加全局 `:focus-visible` 和 `prefers-reduced-motion` 支持 |

## 视觉回归

- 新增 Playwright 配置、登录态初始化、384 个布局检查用例和 112 张代表性截图基线。
- 每个组合验证应用壳、内容区、页面级横向溢出和浏览器控制台错误。
- 代表性截图覆盖 Dashboard、视觉项目、系统信息、故障历史、相机管理、AI 模型和工作流 IDE。
- 结果：`384 passed`，耗时约 9 分钟。

运行方式：

```powershell
$env:AURORA_E2E_USERNAME='admin'
$env:AURORA_E2E_PASSWORD='<password>'
npm run test:visual
```

仅在人工确认视觉变化正确后执行 `npm run test:visual:update` 更新基线。
