# 在线扫描点云第三方对接说明

版本：1.0  
适用模块：AuroraStruct3D Step6 在线扫描  
更新时间：2026-08-22

## 1. 对接目标

第三方系统通过 REST API 启动、停止和查询在线扫描，通过 SignalR 接收每轮生成的增量彩色点云；扫描停止且服务端完成合并后，可通过 REST API 下载完整 PLY 文件。

推荐流程：

1. 建立 SignalR 连接并注册事件处理器。
2. 加入指定标定项目的在线扫描分组。
3. 调用 REST API 启动扫描。
4. 持续接收 `ReceiveIncrementalPointCloudAsync` 增量点云。
5. 调用 REST API 停止扫描。
6. 查询点云状态，取得 `plyDownloadUrl` 后下载完整点云。

> 增量推送不提供历史重放。需要完整结果时，应以停止扫描后下载的合并 PLY 为准。

## 2. 基础约定

| 项目 | 约定 |
| --- | --- |
| 服务地址 | 由部署方提供，例如 `https://192.168.1.10:443` |
| REST 数据格式 | `application/json`，字段采用 camelCase |
| SignalR Hub | `/signalr-hubs/camera` |
| SignalR 协议 | 推荐 MessagePack；服务端同时进行 SignalR 协商 |
| 项目标识 | `calibProjectId`，标准 UUID/GUID 字符串 |
| 时间 | ISO 8601 UTC 时间 |
| 点云分片格式 | ASCII PLY 1.0，XYZRGB，每次事件为一个独立完整的 PLY 分片 |
| 完整点云格式 | ASCII PLY 1.0，XYZRGB |

鉴权方式由部署配置决定。启用身份认证时，REST 请求携带 `Authorization: Bearer <access_token>`；SignalR 客户端通过 `accessTokenFactory` 提供同一令牌。若采用同源 Cookie 会话，则由客户端自动携带 Cookie。

## 3. REST API

### 3.1 启动在线扫描

`POST /api/app/calib-scan/start`

请求体：

```json
{
  "calibProjectId": "2d5af243-7e2f-4fa5-95df-0af4c4cf84a1",
  "suppressProjectorControl": false
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `calibProjectId` | string(UUID) | 是 | 已完成相机、投影仪及标定参数配置的项目 ID |
| `suppressProjectorControl` | boolean | 否 | 默认 `false`。`false` 为结构光扫描；`true` 不发送投影仪模式/触发指令，使用普通双目重建 |

成功返回 `CalibScanStatusDto`。重复启动或设备被其他会话占用时通常返回 HTTP 409；调用方不得并发启动同一项目。

### 3.2 停止在线扫描

`POST /api/app/calib-scan/stop`

```json
{
  "calibProjectId": "2d5af243-7e2f-4fa5-95df-0af4c4cf84a1"
}
```

停止接口会触发累积点云的收尾与合并。返回扫描状态不代表完整 PLY 已立即可下载，应继续查询点云状态，直到其 `state` 为 `2`（Completed）。

### 3.3 查询在线扫描状态

`GET /api/app/calib-scan/status/{calibProjectId}`

响应示例：

```json
{
  "calibProjectId": "2d5af243-7e2f-4fa5-95df-0af4c4cf84a1",
  "state": 2,
  "isRunning": true,
  "startedAt": "2026-08-22T06:20:10.123Z",
  "lastUpdatedAt": "2026-08-22T06:20:15.456Z",
  "errorMessage": null,
  "latestMetrics": {
    "fps": 0.0,
    "depthValidRate": 0.0,
    "confidence": 0.0,
    "depthMapDataUri": null,
    "frameIndex": 18,
    "timestamp": "2026-08-22T06:20:15.456Z",
    "roundIndex": 2,
    "frameIndexInRound": 5,
    "patternCount": 6,
    "isCrosshairDetected": false
  }
}
```

扫描状态枚举：`0=Idle`、`1=Starting`、`2=Running`、`3=Stopping`、`4=Failed`。

### 3.4 查询点云状态

`GET /api/app/calib-point-cloud/status/{calibProjectId}`

关键响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `state` | number | `0=Idle`、`1=Running`、`2=Completed`、`3=Failed` |
| `progressMessage` | string/null | 当前重建或合并进度说明 |
| `errorMessage` | string/null | 失败原因 |
| `plyDownloadUrl` | string/null | 完整 PLY 下载相对地址，完成后提供 |
| `plyFileSizeBytes` | number/null | 完整 PLY 文件字节数 |

### 3.5 下载完整点云

优先直接请求点云状态返回的 `plyDownloadUrl`。当前地址形式为：

`GET /api/app/calib-point-cloud/download/{calibProjectId}`

成功响应体是 PLY 文件二进制内容。即使文件内容为 ASCII，也应按字节流保存，不能按 JSON 解析。

```bash
curl -L \
  -H "Authorization: Bearer $TOKEN" \
  -o result.ply \
  "https://HOST/api/app/calib-point-cloud/download/2d5af243-7e2f-4fa5-95df-0af4c4cf84a1"
```

## 4. SignalR 实时点云

### 4.1 建立连接与加入分组

连接 Hub 后调用：

`JoinCalibScanGroupAsync(calibProjectId)`

断开或不再接收时调用：

`LeaveCalibScanGroupAsync(calibProjectId)`

每次断线重连后都必须重新调用 `JoinCalibScanGroupAsync`。建议自动重连，并在 `onreconnected` 中重新入组。

### 4.2 增量点云事件

事件名：`ReceiveIncrementalPointCloudAsync`

参数按以下顺序传递：

| 序号 | 参数 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `calibProjectId` | string | 项目 ID |
| 2 | `pointCloudBytes` | byte[] / Uint8Array | 本轮 ASCII PLY 完整分片 |
| 3 | `pointCount` | int | 本分片新增点数 |
| 4 | `totalPointCount` | int | 本次扫描已累计的总点数 |

`pointCloudBytes` 当前未做 gzip/zip 压缩。虽然接口内部历史注释曾使用“压缩后的字节数组”表述，但线上数据实际是 `format ascii 1.0` 的 PLY，请以 PLY 头为准。

### 4.3 其他有用事件

| 事件 | 参数 | 用途 |
| --- | --- | --- |
| `ReceiveCalibScanStateAsync` | `CalibScanStatusDto` | 扫描状态变化 |
| `ReceiveCalibScanMetricsAsync` | `projectId, metrics` | 当前轮次、帧序号等实时指标 |
| `ReceivePointCloudStatusAsync` | `PointCloudStatusDto` | 点云重建、合并、完成或失败状态 |
| `ReceiveDepthQualityMapAsync` | `projectId, pngBytes, validPointCount, totalPointCount, minDepthMm, maxDepthMm` | PNG 格式二维深度质量图；不是三维点云 |

## 5. PLY 数据格式

每个增量事件中的字节数组均可独立解析，典型内容如下：

```text
ply
format ascii 1.0
element vertex 2
property float x
property float y
property float z
property uchar red
property uchar green
property uchar blue
end_header
12.345000 -5.210000 418.930000 128 200 255
12.410000 -5.180000 419.020000 130 201 254
```

每个顶点一行，列顺序固定为：

```text
x y z red green blue
```

- `x/y/z` 为浮点坐标；当前重建链路以毫米为工程单位。
- `red/green/blue` 为 `0~255` 无符号颜色值。
- 点云分片没有面信息，不包含 `element face`。
- 第三方可直接追加“解析后的顶点”，不可把多个完整 PLY 文件的原始字节直接拼接，因为每个分片都有独立 PLY 头。
- 如需生成自己的合并 PLY，需汇总所有顶点、重新计算 `element vertex`，只写一个文件头。

## 6. JavaScript/TypeScript 示例

依赖：

```bash
npm install @microsoft/signalr @microsoft/signalr-protocol-msgpack
```

```ts
import * as signalR from '@microsoft/signalr'
import { MessagePackHubProtocol } from '@microsoft/signalr-protocol-msgpack'

const baseUrl = 'https://HOST'
const projectId = '2d5af243-7e2f-4fa5-95df-0af4c4cf84a1'
const accessToken = 'ACCESS_TOKEN'

const connection = new signalR.HubConnectionBuilder()
  .withUrl(`${baseUrl}/signalr-hubs/camera`, {
    accessTokenFactory: () => accessToken,
  })
  .withHubProtocol(new MessagePackHubProtocol())
  .withAutomaticReconnect([0, 2000, 5000, 10000])
  .build()

connection.on(
  'ReceiveIncrementalPointCloudAsync',
  (receivedProjectId: string, bytes: Uint8Array, pointCount: number, totalPointCount: number) => {
    if (receivedProjectId !== projectId) return
    const plyText = new TextDecoder('ascii').decode(Uint8Array.from(bytes))
    console.log(`新增 ${pointCount} 点，累计 ${totalPointCount} 点`)
    consumePlyChunk(plyText)
  },
)

connection.on('ReceivePointCloudStatusAsync', status => {
  if (status.calibProjectId !== projectId) return
  console.log(status.progressMessage, status.errorMessage)
})

connection.onreconnected(async () => {
  await connection.invoke('JoinCalibScanGroupAsync', projectId)
})

await connection.start()
await connection.invoke('JoinCalibScanGroupAsync', projectId)

await fetch(`${baseUrl}/api/app/calib-scan/start`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${accessToken}`,
  },
  body: JSON.stringify({
    calibProjectId: projectId,
    suppressProjectorControl: false,
  }),
})
```

## 7. 推荐时序与可靠性要求

```text
第三方                    Aurora REST                 Camera SignalR
  |                            |                            |
  |------ 建立连接/加入分组 ------------------------------->|
  |------ POST /calib-scan/start ----->|                    |
  |<----- 扫描状态 --------------------|                    |
  |<---------------- 状态/指标/增量 PLY（重复多轮）---------|
  |------ POST /calib-scan/stop ------>|                    |
  |<---------------- 点云合并状态 --------------------------|
  |------ GET /point-cloud/status ---->|                    |
  |<----- plyDownloadUrl --------------|                    |
  |------ GET plyDownloadUrl ---------->|                    |
  |<----- 完整 PLY ---------------------|                    |
```

实现要求：

- 必须先订阅、入组，再启动扫描，避免丢失首个分片。
- SignalR 断线期间产生的增量分片不会补发；重连后重新入组，并在扫描结束后下载完整 PLY 校正结果。
- 使用 `calibProjectId` 过滤所有事件，不能假设一个连接只会收到一个项目的数据。
- `pointCount` 用于校验当前分片，`totalPointCount` 用于检测缺片；若累计值出现跳变，应标记实时数据不完整。
- PLY 分片可能较大，事件处理器内避免阻塞 SignalR 接收线程；建议交给 Worker/后台线程解析。
- 不要无限保留所有解析副本。实时显示可降采样或保留固定数量点；存档使用最终下载文件。
- 仅允许一个在线扫描会话占用相关设备。HTTP 409 后应等待或由操作员释放占用，不应高频重试。

## 8. 常见错误

| 现象 | 可能原因 | 处理建议 |
| --- | --- | --- |
| REST 返回 401/403 | 令牌缺失、过期或权限不足 | 更新令牌并确认部署权限 |
| REST 返回 409 | 项目或相机/投影仪已被其他会话占用 | 停止其他会话后重试 |
| 已连接但无点云事件 | 未加入项目分组、项目 ID 错误、首轮尚未重建完成 | 调用入组方法并查询扫描状态 |
| 重连后不再收到事件 | SignalR 分组成员关系未恢复 | 在 `onreconnected` 中重新入组 |
| PLY 解析失败 | 把 MessagePack 字节当 Base64/JSON，或按二进制 PLY 解析 | 将参数作为原始字节，按 ASCII PLY 解析 |
| 实时累计点数不连续 | 网络断线或客户端处理不过来 | 结束后下载完整 PLY；实时结果仅作预览 |
| 停止后无法立即下载 | 服务端仍在合并或持久化 | 轮询点云状态，等待 Completed |

## 9. 联调验收标准

第三方完成以下检查即可视为接入成功：

1. 能查询指定项目的在线扫描状态。
2. 能建立 SignalR 连接、加入分组并在重连后恢复订阅。
3. 启动扫描后至少收到一个 `ReceiveIncrementalPointCloudAsync` 事件。
4. 解析后的顶点数与事件 `pointCount` 一致。
5. XYZ 坐标及 RGB 颜色可正确显示。
6. 停止扫描后点云状态进入 Completed。
7. 可通过 `plyDownloadUrl` 下载并打开完整 PLY。
