# 视觉平台闭环生态实施跟踪

更新日期：2026-07-30  
产品主线：离线边缘端 3D 精密检测，2D 能力作为通用视觉底座。

## 设备底层高风险修复（本次）

已完成：

- 相机 HTTP/标定帧等待器改为可移除集合；取消订阅后立即释放，避免长运行预览造成等待器引用累积。
- 相机停止采集失败后明确进入可恢复故障态，下一次启动会重新初始化采集资源。
- 光机服务增加单设备异步操作通道；连接、断开、读写命令和整段条纹下载不会交错。
- USB 光机扫描改为读取用户寄存器 `pr 0`。只有已登记且唯一的 1~255 身份值才绑定 HID 索引；未编号、读取失败和重复身份均隔离，不会自动建档或连接。连接时再次校验身份。
- 同型号相机预览采用安全默认值：新预览会先停止已运行的同型号预览；不同型号预览不受该策略限制。
- 启动初始化任务改为复用已校验的投影仪连接入口，避免直接按 HID 索引连到错误设备。
- 连接池在应用退出时改用异步优雅断开；正在执行的下载或控制命令会先结束，底层传输对象才会释放。
- 相机型号为空或读取失败时统一归入未知型号互斥组，避免因元数据缺失意外放开并发预览。
- 通用相机契约已移入共享层，`ICameraDriver` 只包含稳定身份、生命周期、采集、快照和触发，不再暴露 Tucam/GenICam 类型；Tucam 专有节点接口保留在驱动适配器内部。
- 原 `AuroraStruct3D.Tucam` 项目及目录已更名为 `AuroraStruct3D.Cameras`；通用注册表位于 `AuroraStruct3D.Cameras`，厂商实现明确隔离在 `AuroraStruct3D.Cameras.Tucam` 命名空间，后续华睿/大华驱动按同级适配器接入。
- 驱动注册表已贯通设备扫描、打开/关闭、快照、触发和预览；所有运行期操作先按数据库设备 ID 解析 `DriverId + HardwareId`，不再把全局 `DeviceIndex` 作为控制身份。
- 扫描结果按驱动返回发现、绑定、冲突和失败状态。空身份、同驱动重复身份及驱动扫描失败均隔离；离线历史设备保留但禁止硬件操作。
- 预览会话保存驱动 ID 与稳定硬件 ID；同运行期索引的不同驱动不会串设备。同型号互斥组改为 `DriverId + Model`。
- 正式 EF 迁移 `AddGenericCameraDriverBinding` 已生成 Designer 和 Snapshot，移除运行期索引/序列号全局唯一限制，回填历史 Tucam 身份和安全能力默认值。
- 前端管理页桌面/移动视图展示驱动、稳定身份、连接摘要和能力；控制页按预览、快照、软触发、温度、RTP 和参数节点能力控制请求与界面。

待完成（依赖华睿/大华设备和 SDK）：

1. 设备与 SDK 到位后实现华睿/大华 GigE `ICameraDriver`，补充其参数节点/标定适配器并进行双机实测。
2. 将同型号并发能力从当前安全默认值迁移为可持久化的“驱动类型 + 型号”能力档案，并根据实机结果开放并发预览和并发触发。
3. 对华睿双机执行索引重排、断线重连、同型号切换、不同型号并发、软触发和外触发时序验收。

### 3D 配准演示性能修复

- 已定位“特征粗配准（处理初始角度差）”超过 120 秒的问题：`sampleCount` 原先只限制特征匹配，法向估计仍对完整点云执行 O(N²) 暴力 KNN 和逐点全量排序。
- 粗配准现先生成最多 500–1000 点的特征工作云，在工作云上估计法向、描述子与 RANSAC；求得的刚体变换仍应用到完整源点云，输出点数不减少。
- `sampleCount`、`maxIterations` 等参数增加上限与有效性校验，RANSAC 使用固定随机种子以保证演示和回归结果可复现。
- `stats_json` 新增 `sourceWorkingPointCount`、`targetWorkingPointCount`，便于确认实际计算规模。
- 新增 5000 点无预置法向点云回归：完整输出保持 5000 点，工作云各 500 点；专项测试 2/2 通过，测试进程内执行约 0.25 秒。
- 工作流同步节点的 120 秒超时目前仍是“节点返回后判定”，不能强制中断任意第三方同步算子；本次已消除该节点的主要超时源，通用可取消算子契约仍属于后续架构项。

### 第三方 Web 工作流接口路由修复

- rk3588 日志中的第三方 Web 连接失败不是 CORS、HTTPS 或 SignalR 故障，而是 `GET /api/app/workflow` 同时匹配多个工作流 Action，触发 `AmbiguousMatchException` 并返回 HTTP 500。
- `WorkflowAppService` 的列表、创建、详情、更新、删除、校验和仿真接口已补齐唯一的 HTTP Method 与路由模板。
- 仅供后台 Job 调用的 `ExecuteFrozenWorkflowAsync` 同时标记为 `RemoteService(false)` 与 MVC `NonAction`，不再进入 HTTP 端点候选集合。
- 路由契约测试 17/17 通过，Host 与前端构建通过。部署新版本并重启 API 服务后，第三方 Web 仍使用 `GET /api/app/workflow?projectId={guid}`，无需修改调用地址。

### 启动设备任务并发修复

- rk3588 启动日志中的 `ProjectorDevice ... concurrency exception` 来自投影仪连接应用服务已更新 `ConcurrencyStamp` 后，启动 Job 又保存了扫描前加载的旧实体。

## 交付原则

- 核心检测、设备控制和结果判定必须可在断网工控机运行。
- 每项新增能力必须输出可追溯的参数、置信度或失败原因，并提供自动化回归测试。
- 以可交付的 3D 精密检测场景优先，不追求一次性复刻 HALCON/VisionMaster 的全部长尾算子。
