# 前端对接：工作流、设备状态与 OPC UA 完整变更

更新日期：2026-08-03  
工作流基础路由：`/api/app/workflow`

## 1. 本次变更摘要

- 部署改为不可变快照；任务配置发生变化后再次发布会创建新 Revision，不覆盖旧版本。
- 部署快照新增任务类型、周期、正式结果变量、错误策略和快照协议版本。
- 新增部署历史分页接口。
- 正式生产任务统一受设备状态约束：仅 `Running` 且运行模式为 `Online` 或 `Auto` 时允许触发。
- 单设备任意时刻只允许一个正式项目运行；其他触发返回业务错误或在后台跳过。
- 周期、PLC 点位触发、OPC UA 握手三种自动触发方式互斥。
- OPC UA 浏览树接口在后端自动读取全部分页，前端不再逐层、逐页请求。
- PLC 调试点位删除和停止订阅路由修正。
- 新增完整设备状态控制接口，包括软件急停。

## 3. 项目任务配置

### 查询

`GET /api/app/workflow/projects/{projectId}/tasks`

### 整体保存

`PUT /api/app/workflow/projects/tasks`

新增项目任务调用 `POST /api/app/workflow/project-tasks`，请求只有 `projectId` 和 `isEnabled`。禁止使用 `POST /api/app/workflow/runs` 新增任务；`runs` 表示启动正式生产运行，会校验设备必须为 Running + Online/Auto。

前端接口映射必须为：新增项目任务 → `/project-tasks`；保存并生效项目配置 → `/projects/{projectId}/apply`；真正开始生产 → `/runs`。三者不能混用。

```ts
interface WorkflowProjectTaskBatch {
  projectId: string
  taskType: WorkflowProjectTaskType
  cycleIntervalSeconds?: number | null // Cyclic 时必填，1..86400
  resultWorkflowId?: string | null
  resultVariableName?: string | null   // 必须是所选工作流的 Boolean 变量
  onErrorAction: WorkflowProjectRunOnErrorAction
  items: Array<{
    id: string
    projectId: string
    workflowId: string
    workflowName: string
    isEnabled: boolean
    orderNo: number
  }>
}
```

前端规则：

- `taskType === Cyclic` 时显示并必填 `cycleIntervalSeconds`。
- 启用 OPC UA 握手前必须配置 `resultWorkflowId + resultVariableName`。
- 正式结果变量属于工作流任务配置，不属于 PLC 调试点位表。
- `onErrorAction=0` 表示任一工作流失败即停止；`1` 表示记录失败并继续后续工作流。
- 保存为周期任务时，如果项目已启用 PLC 点位触发或 OPC UA 握手，后端拒绝保存。

## 4. 发布、激活、回滚与历史

| 操作 | 方法与路径 |
|---|---|
| 查询最新部署 | `GET /api/app/workflow/projects/{projectId}/deployments` |
| 查询部署历史 | `GET /api/app/workflow/projects/{projectId}/deployments/history?skipCount=0&maxResultCount=20` |
| 发布新快照 | `POST /api/app/workflow/projects/{projectId}/deployments` |
| 激活 | `POST /api/app/workflow/deployments/{deploymentId}/activate` |
| 重新激活 | `POST /api/app/workflow/deployments/{deploymentId}/reactivate` |
| 回滚 | `POST /api/app/workflow/deployments/{deploymentId}/rollback` |
| 删除未激活部署 | `DELETE /api/app/workflow/deployments/{deploymentId}` |

历史接口返回 ABP 分页结构：

```ts
interface PagedResult<T> {
  totalCount: number
  items: T[]
}

interface WorkflowProjectDeployment {
  id: string
  projectId: string
  revision: number
  status: WorkflowProjectDeploymentStatus
  isCurrentActive: boolean
  canActivate: boolean
  canReactivate: boolean
  canRollback: boolean
  snapshotHash: string
  itemCount: number
  activatedAt?: string | null
  activatedBy?: string | null
  creationTime: string
  snapshotSchemaVersion: number
  taskType: WorkflowProjectTaskType
  cycleIntervalSeconds?: number | null
  resultWorkflowId?: string | null
  resultVariableName?: string | null
  onErrorAction: WorkflowProjectRunOnErrorAction

```

前端不要修改历史部署对象。发布相同快照时后端可返回已有最新版本；内容或任务配置变化时创建新 Revision。激活周期部署会自动注册周期调度；激活非周期部署会移除该项目旧周期调度。

普通页面流程为“保存工作流 → 配置任务 → 保存任务配置”。保存任务配置会自动生成并激活后台部署版本；前端不展示发布、激活或应用概念。详细交互见《前端交互-任务配置保存即生效-20260803.md》。

## 5. 正式运行限制

正式运行入口仍为：

`POST /api/app/workflow/runs`

前端手动运行只发送立即类型，周期由任务配置和部署激活管理：

```json
{
  "name": "手动正式运行",
  "projectId": "PROJECT_GUID",
  "startType": 0
}
```

运行前置条件：

1. 项目存在激活部署。
2. 设备状态为 `Running`。
3. 设备模式为 `Online` 或 `Auto`。
4. 整台设备当前没有其他 `Queued` 或 `Running` 的正式运行。

调试执行接口不受正式生产握手配置约束。前端必须把“工作流调试”和“正式运行”做成不同操作，不要在进入调试页面时强制配置 PLC/握手。

## 6. OPC UA 完整树接口

`POST /api/app/plc-device/{plcDeviceId}/browse-tree`

请求：

```ts
interface PlcBrowseTreeInput {
  rootAddress?: string | null
  maxDepth?: number // 1..16，默认 8
  maxNodes?: number // 1..10000，默认 3000
}
```

推荐请求：

```json
{
  "rootAddress": null,
  "maxDepth": 8,
  "maxNodes": 10000
}
```

响应：

```ts
interface PlcBrowseTreeResult {
  items: PlcBrowseTreeNode[]
  nodeCount: number
  truncated: boolean
}

interface PlcBrowseTreeNode {
  address: string
  browseName: string
  displayName: string
  nodeClass: string
  dataType?: number | null
  access: PlcTagAccess
  hasChildren: boolean
  children: PlcBrowseTreeNode[]
}
```

后端会自动消费 OPC UA continuation token 并递归构建完整树。前端只请求一次，不要在展开节点时再次调用浏览接口。`truncated=true` 表示触发 `maxDepth` 或 `maxNodes` 限制，应提示用户提高限制或选择更具体的 `rootAddress`。

选择握手节点时建议：布尔信号仅允许 Boolean 类型；请求 ID、状态码、错误码选择整数类型；输出点必须包含 `Write` 权限，输入点至少包含 `Read` 权限。

## 7. OPC UA 握手配置

| 操作 | 方法与路径 |
|---|---|
| 查询配置 | `GET /api/app/workflow/projects/{projectId}/plc-handshake` |

| 查询状态 | `GET /api/app/workflow/projects/{projectId}/plc-handshake/status` |
| 复位状态 | `POST /api/app/workflow/projects/{projectId}/plc-handshake/reset` |

保存结构中的点位全部是 OPC UA 节点地址，不再是 PLC 调试点位表 ID：

```ts
  projectId: string

```

启用时后端校验：所有地址非空且互不重复；已配置正式 Boolean 结果变量；项目不是周期任务；项目未启用 PLC 点位触发；同一 PLC 未被其他项目启用生产握手。

## 8. PLC 点位触发及调试点位修复

PLC 点位触发：

- `GET /api/app/workflow/projects/{projectId}/plc-triggers`
- `POST /api/app/workflow/plc-triggers`
- `DELETE /api/app/workflow/plc-triggers/{triggerId}`

启用点位触发时不能同时使用周期任务或 OPC UA 握手。

PLC 调试页面：

- 删除点位：`DELETE /api/app/plc-device/{deviceId}/tag/{tagId}`
- 停止订阅：`POST /api/app/plc-device/{deviceId}/unsubscribe`

删除调试点位不再使用旧的复数 `tags` 路由。调试点位表与 OPC UA 生产握手地址相互独立，删除调试点位不会删除握手节点配置。

## 9. 设备状态接口

查询当前状态：`GET /api/app/device-state/current-state`

新增控制接口：

| 操作 | POST 路径 | 请求 |
|---|---|---|
| 启动 | `/api/app/device-state/start` | `{ reason?: string }` |
| 暂停 | `/api/app/device-state/pause` | `{ reason?: string }` |
| 恢复 | `/api/app/device-state/resume` | `{ reason?: string }` |
| 停止 | `/api/app/device-state/stop` | `{ reason?: string }` |
| 确认故障 | `/api/app/device-state/acknowledge-fault` | `{ reason?: string }` |
| 复位 | `/api/app/device-state/reset` | `{ reason?: string }` |
| 软件急停 | `/api/app/device-state/emergency-stop` | `{ reason: string }` |

所有命令成功后直接返回最新 `DeviceStateDto`：

```ts
interface DeviceStateDto {
  status: DeviceStatus
  runMode: DeviceRunMode
  currentFaultId?: string | null
  currentFaultLevel?: number | null
  currentFaultCode?: string | null
  isInTransition: boolean
  canAcceptProductionCommand: boolean
  canSwitchMode: boolean
  canStart: boolean
  canPause: boolean
  canResume: boolean
  canStop: boolean
  canAcknowledgeFault: boolean
  canReset: boolean
  canEmergencyStop: boolean
}
```

按钮禁用状态必须优先使用后端返回的 `can*` 字段，不要在前端重复推导状态机。软件急停必须二次确认并要求输入至少 2 个字符的原因。启动仅允许 Online/Auto；Manual 和 Maintenance 模式不能启动正式生产。

## 10. 错误处理

业务约束错误由 ABP `UserFriendlyException` 返回。前端应展示响应中的业务消息，典型消息包括：

- `启用 OPC UA 握手前必须配置正式任务的布尔结果变量。`
- `周期调度不能与 PLC 点位触发或 OPC UA 握手同时启用。`
- `同一项目只能启用一种自动触发方式。`
- `设备仅在 Running 且 Online/Auto 模式下允许执行正式任务。`
- `设备已有正式任务正在运行。`

不要把这些业务冲突当作登录失效或网络错误处理。

## 11. 推荐联调清单

1. 加载设备状态并按 `can*` 字段渲染控制按钮。
2. 在 Online/Auto 模式启动设备，确认状态进入 Running。
3. 配置任务顺序、正式 Boolean 结果变量和错误策略。
4. OPC UA 握手页面一次请求完整树，确认 `truncated=false`。
5. 保存并启用握手，验证与周期/点位触发的互斥提示。
6. 发布并激活，确认 Revision 和冻结任务字段正确。
7. 修改任务配置后重新发布，确认产生新 Revision，旧部署仍可在历史中查看和回滚。
8. 验证不同项目并发触发时只接受一个正式运行。
9. 验证 PLC 调试点位删除及停止订阅不再返回 404。
10. 验证 Manual、Maintenance、Paused、Fault、EmergencyStop 状态不能创建正式运行。
