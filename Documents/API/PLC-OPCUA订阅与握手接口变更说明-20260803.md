# PLC OPC UA 订阅与握手接口变更说明

> 日期：2026-08-03  
> 面向：前端开发、联调与测试  
> 变更性质：停止订阅路由修复；工作流握手配置与 PLC 调试点位解耦

## 1. 变更摘要

本次包含两项不相关的功能修正：

1. PLC 调试页的 OPC UA 停止订阅接口增加明确路由，修复请求返回 404。
2. 工作流 PLC 握手配置不再引用 PLC 调试页维护的实时点位 ID，改为直接保存独立的 OPC UA NodeId。

PLC 调试页的实时点位仅用于临时监看、订阅、读取和写值；工作流握手 NodeId 属于生产配置。两者不再共享点位数据。

## 2. OPC UA 停止订阅

### 2.1 接口

```http
POST /api/app/plc-device/{id}/unsubscribe?subscriptionId={subscriptionId}
Authorization: Bearer {accessToken}
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | Path | UUID | 是 | PLC 设备 ID |
| `subscriptionId` | Query | string | 是 | 开始订阅接口返回的订阅 ID |

请求体为空。

### 2.2 成功响应

```http
HTTP/1.1 204 No Content
```

设备已经断线时，后端不会为了取消订阅重新连接 PLC，但仍会清理本地订阅跟踪记录。

### 2.3 前端调用

```ts
export async function unsubscribePlcTags(
    deviceId: string,
    subscriptionId: string,
): Promise<void> {
    await httpClient.post(
        `/api/app/plc-device/${deviceId}/unsubscribe`,
        undefined,
        { params: { subscriptionId } },
    )
}
```

建议前端在发送请求前保存当前 `subscriptionId`，并立即清空页面订阅状态，避免用户重复点击：

```ts
const activeSubscriptionId = subscriptionId.value
subscriptionId.value = undefined

if (activeSubscriptionId) {
    await unsubscribePlcTags(deviceId, activeSubscriptionId)
}
```

## 3. 删除 PLC 调试点位

```http
DELETE /api/app/plc-device/{id}/tag/{tagId}
Authorization: Bearer {accessToken}
```

| 参数 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | Path | UUID | PLC 设备 ID |
| `tagId` | Path | UUID | 调试点位 ID |

成功响应为 `204 No Content`。该接口只删除 PLC 调试页点位，不影响工作流握手 NodeId。

## 4. 工作流 PLC 握手配置

### 4.1 获取 OPC UA 节点树

握手配置必须使用本接口选择生产 NodeId，不使用 PLC 调试实时点位接口。

```http
POST /api/app/plc-device/{id}/browse-tree
Content-Type: application/json
Authorization: Bearer {accessToken}
```

请求示例：

```json
{
  "rootAddress": null,
  "maxDepth": 8,
  "maxNodes": 3000
}
```

| 字段 | 类型 | 必填 | 限制 | 说明 |
| --- | --- | --- | --- | --- |
| `rootAddress` | string/null | 否 | — | 根 NodeId；为空时从 OPC UA Objects 目录开始 |
| `maxDepth` | number | 否 | 1–16 | 最大递归深度，默认 8 |
| `maxNodes` | number | 否 | 1–10000 | 最大返回节点数，默认 3000 |

响应示例：

```json
{
  "items": [
    {
      "address": "ns=2;s=Handshake",
      "browseName": "Handshake",
      "displayName": "Handshake",
      "nodeClass": "Object",
      "dataType": null,
      "access": 0,
      "hasChildren": true,
      "children": [
        {
          "address": "ns=2;s=Handshake.CaptureRequest",
          "browseName": "CaptureRequest",
          "displayName": "CaptureRequest",
          "nodeClass": "Variable",
          "dataType": null,
          "access": 3,
          "hasChildren": false,
          "children": []
        }
      ]
    }
  ],
  "nodeCount": 2,
  "truncated": false
}
```

前端只允许选择 `nodeClass === "Variable"` 的节点。`address` 是保存握手配置时提交的 NodeId。`truncated=true` 表示达到深度、节点数量或单层分页限制，页面应提示当前树不完整。

前端只调用一次 `browse-tree`。OPC UA 目录递归和服务端 `ContinuationPoint` 分页续传均由后端完成，前端不得按目录层级重复请求 `browse`。

### 4.2 破坏性字段变更

以下旧字段已从前后端接口契约中移除：

```text
captureRequestTagId
requestIdTagId
resultAckTagId
resultAckIdTagId
heartbeatTagId
deviceStatusTagId
taskStatusTagId
canCaptureTagId
captureAckTagId
ackRequestIdTagId
resultValidTagId
resultRequestIdTagId
resultCodeTagId
errorCodeTagId
```

替换为独立的 OPC UA NodeId 字段：

```text
captureRequestAddress
requestIdAddress
resultAckAddress
resultAckIdAddress
heartbeatAddress
deviceStatusAddress
taskStatusAddress
canCaptureAddress
captureAckAddress
ackRequestIdAddress
resultValidAddress
resultRequestIdAddress
resultCodeAddress
errorCodeAddress
```

前端不得再通过 `/api/app/plc-device/{id}/tags` 获取握手候选项，也不得把 PLC 调试页点位 ID 提交给握手接口。

### 4.4 保存握手配置

```http
PUT /api/app/workflow/projects/{projectId}/plc-handshake
Content-Type: application/json
Authorization: Bearer {accessToken}
```

请求示例：

```json
{
  "projectId": "38e78b6c-b605-45af-a204-66c52f003f80",
  "plcDeviceId": "62068ce4-cac3-4536-b82a-55fe4a59e426",
  "captureRequestAddress": "ns=2;s=Handshake.CaptureRequest",
  "requestIdAddress": "ns=2;s=Handshake.RequestId",
  "resultAckAddress": "ns=2;s=Handshake.ResultAck",
  "resultAckIdAddress": "ns=2;s=Handshake.ResultAckId",
  "heartbeatAddress": "ns=2;s=Handshake.Heartbeat",
  "deviceStatusAddress": "ns=2;s=Handshake.DeviceStatus",
  "taskStatusAddress": "ns=2;s=Handshake.TaskStatus",
  "canCaptureAddress": "ns=2;s=Handshake.CanCapture",
  "captureAckAddress": "ns=2;s=Handshake.CaptureAck",
  "ackRequestIdAddress": "ns=2;s=Handshake.AckRequestId",
  "resultValidAddress": "ns=2;s=Handshake.ResultValid",
  "resultRequestIdAddress": "ns=2;s=Handshake.ResultRequestId",
  "resultCodeAddress": "ns=2;s=Handshake.ResultCode",
  "errorCodeAddress": "ns=2;s=Handshake.ErrorCode",
  "isEnabled": true
}
```

成功时返回完整的握手配置对象，结构与查询接口一致。

### 4.5 字段约束

| 字段 | OPC UA 类型 | 所有者 | 说明 |
| --- | --- | --- | --- |
| `captureRequestAddress` | BOOL | PLC | PLC 发起拍照请求 |
| `requestIdAddress` | DINT | PLC | PLC 递增请求号 |
| `resultAckAddress` | BOOL | PLC | PLC 确认已收到结果 |
| `resultAckIdAddress` | DINT | PLC | PLC 回写确认的请求号 |
| `heartbeatAddress` | DINT | 平台 | 平台周期心跳 |
| `deviceStatusAddress` | DINT | 平台 | 平台设备状态 |
| `taskStatusAddress` | DINT | 平台 | 当前任务阶段 |
| `canCaptureAddress` | BOOL | 平台 | 是否允许接收拍照请求 |
| `captureAckAddress` | BOOL | 平台 | 平台确认已受理请求 |
| `ackRequestIdAddress` | DINT | 平台 | 平台确认的请求号 |
| `resultValidAddress` | BOOL | 平台 | 当前结果是否有效 |
| `resultRequestIdAddress` | DINT | 平台 | 当前结果对应的请求号 |
| `resultCodeAddress` | DINT | 平台 | OK、NG 或 Error 结果码 |
| `errorCodeAddress` | DINT | 平台 | 错误原因码 |

保存校验规则：

- `projectId`、`plcDeviceId` 必须是有效 UUID。
- URL 中的 `projectId` 必须与请求体一致；请求体也可传空 UUID，由 URL 决定项目。
- 14 个 NodeId 均不能为空。
- 14 个 NodeId 不允许重复，比较时区分大小写。
- 启用握手前必须配置正式任务的布尔结果变量。
- 同一 PLC 同时只能被一个项目的生产握手启用。

NodeId 由前端以普通字符串提交。常见格式包括：

```text
ns=2;s=Handshake.CaptureRequest
ns=3;i=1001
```

### 4.6 查询运行状态

```http
GET /api/app/workflow/projects/{projectId}/plc-handshake/status
```

响应结构没有变化：

```ts
interface WorkflowPlcHandshakeStatus {
    projectId: string
    isConfigured: boolean
    isEnabled: boolean
    phase: 0 | 1 | 2 | 3 | 4
    currentRequestId: number
    lastCompletedRequestId: number
    currentRunId?: string
    resultCode: number
    errorCode: number
    lastRequestAt?: string
    lastResultAt?: string
    lastError?: string
}
```

### 4.7 复位运行状态

```http
POST /api/app/workflow/projects/{projectId}/plc-handshake/reset
```

请求体为空，成功时返回最新的 `WorkflowPlcHandshakeStatus`。

## 5. 推荐的前端初始化流程

```ts
const status = await getWorkflowPlcHandshakeStatus(projectId)

if (status.isConfigured) {
    form.value = await getWorkflowPlcHandshake(projectId)
} else {
    form.value = createEmptyHandshakeForm(projectId)
}
```

握手配置页面应调用 `browse-tree` 呈现 OPC UA 层级目录，并用用户选中变量节点的 `address` 回填表单。不要使用 PLC 调试实时点位下拉框。

## 6. 数据库迁移影响

新增迁移：

```text
20260803032550_DecoupleWorkflowPlcHandshakeAddresses
```

迁移会为握手配置增加 14 个独立地址字段。已有配置保存的是调试点位 ID，无法无歧义转换为生产 NodeId，因此迁移会将已有握手配置设为停用。

部署后操作顺序：

1. 执行数据库迁移。
2. 打开项目的任务与 PLC 握手配置。
3. 填写并核对 14 个生产 OPC UA NodeId。
4. 保存但暂不启用，先由 PLC 工程师核对地址和 BOOL/DINT 类型。
5. 联调通过后启用握手。

## 7. 前端验收清单

- 开始订阅后可以收到实时点位更新。
- 点击停止订阅不再返回 404，接口返回 204。
- 删除调试点位不再返回 404，接口返回 204。
- 停止后按钮恢复为“开始订阅”。
- 握手配置页不加载 PLC 调试点位列表。
- 选择 PLC 后可以加载 OPC UA 树状目录，并只能选择变量节点。
- 删除或修改调试页实时点位不会改变握手配置。
- 握手配置可以保存并重新加载 14 个 NodeId。
- 重复或空 NodeId 会显示后端业务错误。
- 数据库升级后，旧握手配置显示为停用，要求重新确认 NodeId。
