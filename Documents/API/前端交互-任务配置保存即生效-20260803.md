# 前端交互：任务配置保存即生效

更新日期：2026-08-03

## 0. 当前报错结论（前端必须修改）

前端点击“新增任务”时调用了错误接口：

```http
POST /api/app/workflow/runs
```

`/runs` 不是新增任务接口，它表示“立即启动一次正式生产运行”，因此后端会检查：

- 设备状态必须为 `Running`
- 设备模式必须为 `Online` 或 `Auto`
- 必须存在已经生效的任务版本
- 当前不能有其他正式运行

所以日志中的提示是预期行为，不能通过移除设备状态校验解决。前端必须改掉调用地址。

### 接口用途对照

| 前端操作 | 正确接口 | 是否要求设备运行 |
|---|---|---|
| 新增项目任务 | `POST /api/app/workflow/project-tasks` | 否 |
| 启用/停用项目任务 | `PUT /api/app/workflow/project-tasks/{taskId}/enabled` | 否 |
| 查询项目完整任务配置 | `GET /api/app/workflow/projects/{projectId}/tasks` | 否 |
| 保存完整任务配置并立即生效 | `POST /api/app/workflow/projects/{projectId}/apply` | 否 |
| 启动一次正式生产 | `POST /api/app/workflow/runs` | 是 |
| 查询正式运行记录 | `GET /api/app/workflow/runs?projectId={projectId}` | 否 |

必须在前端删除类似代码：

```ts
// 错误：新增任务时启动了正式运行
await httpClient.post('/api/app/workflow/runs', {
  projectId,
  name: taskName,
  startType: 0,
})
```

替换为：

```ts
// 正确：把已有工作流加入项目任务配置
await httpClient.post('/api/app/workflow/project-tasks', {
  projectId,
  isEnabled: true,
})
```

## 用户流程

前端只呈现以下流程：

```text
创建项目 → 创建并保存工作流 → 配置任务 → 保存任务配置（直接生效）
```

对应接口时序：

```text
1. 创建/保存工作流
   POST/PUT 工作流接口

2. 打开任务配置
   GET /api/app/workflow/projects/{projectId}/tasks

3. 任务管理中点击“新增任务”
   POST /api/app/workflow/project-tasks
   body: { projectId, isEnabled }

4. 调整顺序、触发方式、结果变量
   只修改前端 taskConfig 状态

5. 点击“保存任务配置”
   POST /api/app/workflow/projects/{projectId}/apply
   body: { expectedActiveDeploymentId, taskConfig }

6. 用户真正点击“开始生产”时
   POST /api/app/workflow/runs
```

步骤 1～5 都不要求设备正在运行。只有步骤 6 会检查设备状态和运行模式。

普通用户不需要理解部署、发布、激活或“应用到设备”。部署快照和版本激活全部由后端在保存任务配置时自动完成。

## 页面交互

工作流页面提供：

- `保存工作流`：仅保存当前工作流。
- `任务配置`：打开项目任务配置抽屉。
- `版本历史`：高级功能，用于查看后台自动生成的版本和回滚。
- `PLC 触发`：独立配置，不属于任务保存操作。

任务配置抽屉只有一个主按钮：

```text
[保存任务配置]
```

点击后自动执行：保存尚未保存的当前工作流 → 保存任务配置 → 生成不可变快照 → 激活快照 → 同步周期调度。

成功提示：

```text
任务配置已保存并生效 R4。
```

相同配置重复保存：

```text
任务配置已生效 R4。
```

## 保存任务配置接口

```http
POST /api/app/workflow/projects/{projectId}/apply
```

虽然后端路径保留 `apply`，但前端文案必须叫“保存任务配置”，不能显示“应用”“发布”或“激活”。

请求：

```json
{
  "expectedActiveDeploymentId": "CURRENT_DEPLOYMENT_GUID_OR_NULL",
  "taskConfig": {
    "projectId": "PROJECT_GUID",
    "taskType": 0,
    "cycleIntervalSeconds": null,
    "resultWorkflowId": "WORKFLOW_GUID",
    "resultVariableName": "inspectionResult",
    "onErrorAction": 0,
    "items": [
      {
        "id": "TASK_ID_OR_EMPTY_GUID",
        "projectId": "PROJECT_GUID",
        "workflowId": "WORKFLOW_GUID",
        "workflowName": "检测流程",
        "isEnabled": true,
        "orderNo": 0
      }
    ]
  }
}
```

响应：

```ts
interface SaveEffectiveTaskResult {
  projectId: string
  deployment: ProjectDeployment
  createdNewRevision: boolean
  activationChanged: boolean
  unchanged: boolean
  appliedAt: string
}
```

`expectedActiveDeploymentId` 来自：

```http
GET /api/app/workflow/projects/{projectId}/application-status
```

首次配置没有激活版本时传 `null`。

## 新增项目任务

任务列表：

```http
GET /api/app/workflow/project-tasks
```

返回 `Array<{ id, projectId, isEnabled, creationTime }>`。新增弹窗只需选择尚未创建任务的项目和是否启用。

新增任务配置不能调用 `/workflow/runs`。`runs` 表示立即启动正式生产，因此会要求设备处于 Running + Online/Auto。

新增或启用单个工作流任务使用：

```http
POST /api/app/workflow/project-tasks
```

```json
{
  "projectId": "PROJECT_GUID",
  "isEnabled": true
}
```

该接口创建“项目级任务”，不启动正式运行。工作流列表、顺序、周期、结果变量和错误策略都属于项目配置，不得放入新增任务请求。

响应是完整任务配置，前端应直接覆盖本地状态：

```ts
const task = await createProjectTask({
  projectId,
  isEnabled: true,
})
```

启停接口：

```http
PUT /api/app/workflow/project-tasks/{taskId}/enabled
```

```json
{ "isEnabled": false }
```

注意：一个项目最多一个项目任务；重复新增会返回业务错误。

## 部署查询兼容

```http
GET /api/app/workflow/projects/{projectId}/deployments
```

首次配置、尚无部署时返回 `null`，不再抛出“当前项目尚未创建部署快照”。前端必须接受 `ProjectDeployment | null`。

## 状态和错误处理

- 本地工作流未保存：任务保存前自动保存；失败则停止后续操作。
- 任务配置非法：展示后端业务消息，原生效版本不变。
- 版本并发冲突：刷新 `application-status` 后提示用户重新保存。
- 保存超时：查询 `application-status` 确认最终生效版本，不要直接重试。
- 设备未运行：保存任务配置不要求设备运行；只有真正调用 `/workflow/runs` 启动生产时才校验设备状态。

## 前端伪代码

```ts
async function saveTaskConfig() {
  if (sourceDirty) await saveCurrentWorkflow()

  const status = await getProjectApplicationStatus(projectId)
  const result = await applyProjectToDevice(
    projectId,
    taskConfig,
    status.activeDeployment?.id ?? null,
  )

  toast.success(result.unchanged
    ? `任务配置已生效 R${result.deployment.revision}。`
    : `任务配置已保存并生效 R${result.deployment.revision}。`)
}
```
