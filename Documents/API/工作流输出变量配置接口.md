# 工作流输出变量配置接口

## 概述

本功能用于配置工作流运行结束后，哪些变量需要提取并直接返回给前端（称为**提级输出**），避免前端从 `status.variables` 数百个变量中手动查找。

- 输出由工作流结束节点的 `properties.inputBindings` 声明
- 输出支持点路径和数组下标，可选择整个变量或下探到任意叶子字段
- 创建、更新工作流时，后端从结束节点自动推导并同步到工作流实体字段
- 调试完成后通过独立结果接口直接返回结束节点选中的四字段结果数组
- ABP 框架自动生成 REST 端点，路由基础路径：`/api/app/workflow`

> **迁移提示**：输出变量的唯一编辑入口已经改为工作流结束节点。
> `PUT /api/app/workflow/{id}/output-config` 不再是独立配置接口；前端不应继续
> 使用它修改输出。详细交互见
> [3D检测补充交互设计](../01-项目管理/3D检测补充交互设计.md)。

## 接口列表

### 0. 查询变量可下探路径

**接口路由**：
`GET /api/app/workflow/{id}/output-paths?variableName=retstatus`

接口根据变量产出端口的类型 Schema 返回前端级联选择器所需的扁平树节点：

```json
{
  "workflowId": "a1b2c3d4-...",
  "variableName": "retstatus",
  "valueType": "object",
  "items": [
    {
      "path": "retstatus",
      "name": "retstatus",
      "displayName": "检测结果",
      "valueType": "object",
      "isLeaf": false,
      "isArray": false,
      "depth": 0
    },
    {
      "path": "retstatus.status",
      "name": "status",
      "displayName": "检测状态",
      "valueType": "string",
      "isLeaf": true,
      "isArray": false,
      "depth": 1
    },
    {
      "path": "retstatus.regions",
      "name": "regions",
      "displayName": "区域列表",
      "valueType": "array",
      "isLeaf": false,
      "isArray": true,
      "depth": 1
    }
  ]
}
```

数组元素使用 `[0]` 作为可编辑路径示例，例如
`retstatus.regions[0].name`。前端可根据 `depth` 构建树，也可直接按
`path` 保存到结束节点的 `inputBindings`。

### 1. 获取输出变量配置

**接口路由**：`GET /api/app/workflow/{id}/output-config`

**请求参数**：

| 参数 | 类型 | 位置 | 说明 |
|------|------|------|------|
| `id` | `Guid` | URL path | 工作流 ID |

**响应示例**：

```json
{
  "workflowId": "a1b2c3d4-...",
  "outputVariables": ["result_json", "regions_json", "height_result"]
}
```

结束节点可按需配置不同粒度的输出：

```json
{
  "inputBindings": {
    "output1": "retstatus",
    "output2": "retstatus.status",
    "output3": "retstatus.regions[0].name"
  },
  "inputBindingSources": {
    "output1": "variable",
    "output2": "variable",
    "output3": "variable"
  },
  "inputBindingDisplayNames": {
    "output1": "完整结果",
    "output2": "检测状态",
    "output3": "首个区域名称"
  }
}
```

对应返回项的 `name` 分别为 `retstatus`、`retstatus.status` 和
`retstatus.regions[0].name`。叶子字段的 `value` 是字符串、数字或布尔值，
可直接交给模板渲染，无需再次解析 JSON。
Display 名称未设置或为空时，返回项的 `displayName` 使用变量名称。

**返回字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `workflowId` | `Guid` | 工作流 ID |
| `outputVariables` | `string[]` | 需要提级输出的变量名列表 |

### 2. 保存输出变量配置

**状态：已弃用，不用于前端编辑。**

**接口路由**：`PUT /api/app/workflow/{id}/output-config`

**请求参数**：

| 参数 | 类型 | 位置 | 说明 |
|------|------|------|------|
| `id` | `Guid` | URL path | 工作流 ID |
| `input.WorkflowId` | `Guid` | Body | 工作流 ID |
| `input.OutputVariables` | `string[]` | Body | 需要提级输出的变量名列表 |

**请求示例**：

```json
{
  "workflowId": "a1b2c3d4-...",
  "outputVariables": ["result_json", "regions_json"]
}
```

服务端会将请求列表与当前工作流结束节点自动推导出的列表比较。二者不一致时返回：

```text
输出变量由结束节点自动生成，请在工作流结束节点中调整输出绑定后保存。
```

正确方式是在 `graphData` 的 `end-node.properties.inputBindings` 中调整绑定，
然后调用 `POST /api/app/workflow` 或 `PUT /api/app/workflow/{id}` 保存整个工作流。

**响应示例**：

```json
{
  "workflowId": "a1b2c3d4-...",
  "outputVariables": ["result_json", "regions_json"]
}
```

### 3. 工作流执行触发接口（新增字段）

**接口路由**：`POST /api/app/workflow/execute`（原有接口，新增字段）

**响应结构**：

```json
{
  "error": false,
  "errorCode": null,
  "resultImageUrls": [
    "https://.../result_top.png",
    "https://.../result_30degree.png"
  ],
  "message": null,
  "executionId": "...",
  "variables": [
    {
      "name": "result_json",
      "valueType": "string",
      "value": {
        "regions": [
          {"name": "A", "x": -16.96, "y": 5.58, "z": -0.0041}
        ]
      },
      "stagedKey": null
    },
    {
      "name": "regions_json",
      "valueType": "string",
      "value": [
        {"name": "A", "x": -16.96, "y": 5.58, "z": -0.0041}
      ],
      "stagedKey": null
    }
  ],
  "status": {
    "executionId": "...",
    "status": "Completed",
    "variables": [...]
  }
}
```

**新增响应字段说明**：

| 字段 | 类型 | 位置 | 说明 |
|------|------|------|------|
| `variables` | `WorkflowVariableResultDto[]` | 顶级（与 `status` 同级） | 提取出来的目标变量列表，格式同 `status.variables` |
| `resultImageUrls` | `string[]` | 顶级 | 结果图片 URL 列表（原来只保留第一张图，现在全部返回） |

**`WorkflowVariableResultDto` 结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | `string` | 变量名 |
| `valueType` | `string` | 值类型：`string`/`blob`/`int`/`long`/`float`/`double`/`decimal`/`bool`/`object`/`array`/`datetime`/`guid`/`Mat`/`PointCloudData` |
| `value` | `any?` | 原生 JSON 值；对象、数组、数字和布尔值不再包装成字符串，`Mat`/点云为 `null` |
| `stagedKey` | `string?` | 若已写回 Redis 暂存，则为暂存 key（前端可经 `variable-stage` 接口取回）；否则 `null` |

### 4. 调试完成结果接口

**接口路由**：`GET /api/app/workflow/executions/{executionId}/result`

前端必须先查询状态，只有 `debugState === "completed"` 时才调用。响应直接为数组：

```json
[
  {
    "name": "retstatus.status",
    "displayName": "检测状态",
    "valueType": "bool",
    "value": true
  },
  {
    "name": "result_blob_key",
    "displayName": "结果点云",
    "valueType": "blob",
    "value": "workflow-results/2026/07/result.ply"
  }
]
```

数组只包含结束节点选中的变量，每项固定为 `name`、`displayName`、`valueType`、
`value` 四个字段。文件、图片和点云应选择存 Blob 算子输出的 Blob Key 变量，
因此 `value` 直接是 Blob Key；前端自行通过 Key 查询或下载。此接口不返回
`status`、全量变量、`resultImageUrls` 或 `stagedKey`。

正式结果使用稳定类型令牌：`int`、`long`、`float`、`double`、`decimal`、
`bool`、`string`、`blob`、`object`、`array`、`datetime`、`guid`，未知类型回退
`string`。不会暴露 `System.Int32` 等 CLR 名称；数值和布尔值保持原生 JSON 类型。
布尔值 `true` 在界面显示为绿色 `OK`，`false` 显示为红色 `NG`。

文件类结果的 `valueType` 是 `blob`，普通文本仍是 `string`。前端仅对 `blob`
以 Blob Key 最后一个路径段的扩展名（忽略大小写）分类：

| 分类 | 扩展名 | 前端行为 |
|---|---|---|
| 图片 | `.png/.jpg/.jpeg/.bmp/.webp/.tif/.tiff` | 图片预览 |
| 点云/3D | `.ply/.pcd/.xyz/.pts/.asc/.obj` | 3D 查看器 |
| 3D 模型 | `.stl/.glb/.gltf` | 3D 查看器 |
| CAD | `.step/.stp/.iges/.igs` | 下载 |
| JSON | `.json` | 结构化查看 |
| 文本 | `.txt/.csv/.log` | 文本查看 |
| 未知 | 其他扩展名 | 下载 |

不使用变量名或 Display 名称猜测文件类型。Blob Key 必须原样返回。结束节点直接绑定
`Mat` 或 `PointCloudData` 时，结果页提示“请先使用存 Blob 算子”，不内嵌原始数据。

## 数据存储

### 数据库表结构

表名：`AbpProWorkflowDefinitions`

新增字段：

| 字段名 | 类型 | 可空 | 说明 |
|--------|------|------|------|
| `OutputVariables` | `text` | 是 | 输出变量名列表的 JSON 字符串（如 `["result_json", "regions_json"]`） |

### 实体定义

见 `WorkflowDefinition` 实体：

```csharp
/// <summary>输出变量配置 JSON（变量名列表），用于运行时从所有变量中提取目标变量返回给前端。</summary>
public string? OutputVariables { get; private set; }

/// <summary>更新输出变量配置。</summary>
public void UpdateOutputVariables(string? outputVariablesJson)
{
    OutputVariables = outputVariablesJson;
}
```

## 使用说明

### 前端工作流

1. 新建和编辑时，在结束节点配置 `inputBindings`、`inputBindingSources` 和可选的 `inputBindingDisplayNames`
2. 新建调用 `POST /api/app/workflow`，一次提交包含结束节点的完整 `graphData`
3. 更新调用 `PUT /api/app/workflow/{id}`，一次提交完整 `graphData`
4. 打开工作流时直接从 `graphData` 的结束节点回显；`GET output-config` 仅用于兼容校验
5. 调试状态为 `completed` 后，调用 `/executions/{executionId}/result` 获取正式输出

### 后端运行流程

1. 执行触发接口收到请求
2. 编译并执行工作流
3. 执行完成后，根据存储在 `WorkflowDefinition.OutputVariables` 中的配置
4. 从冻结变量快照中筛选出目标变量
5. 返回给前端，放在 `variables` 顶级字段
