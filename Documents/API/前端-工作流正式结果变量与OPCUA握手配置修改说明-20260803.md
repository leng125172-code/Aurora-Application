# 前端：工作流正式结果变量与 OPC UA 握手配置修改说明

更新日期：2026-08-03

## 1. 问题结论

后端提示：

```text
启用 OPC UA 握手前必须配置正式任务的布尔结果变量。
```

这里的“正式任务布尔结果变量”属于**项目的工作流任务配置**，不是：

- PLC 调试页面保存的实时点位；
- OPC UA 握手配置中的节点地址；
- PLC 触发条件使用的点位；
- 前端临时变量或调试变量。

它表示正式任务执行结束后用于判定检测结果的工作流输出：

- `true`：任务判定为 OK；
- `false`：任务判定为 NG；
- 未产出或不是 Boolean：本次任务为错误，不能作为正常 OK/NG 结果上报。

后端在启用握手时要求项目任务配置同时存在：

```text
resultWorkflowId   最终判定结果来自哪个已启用工作流
resultVariableName 该工作流产出的 Boolean 输出变量名
```

## 2. 三类配置的边界

| 配置 | 数据来源 | 用途 |
|---|---|---|
| 正式任务结果绑定 | 项目工作流任务配置 | 从工作流运行结果中取得 OK/NG |
| OPC UA 握手地址 | OPC UA 完整节点树 | 与 PLC 交换请求、状态和结果 |
| PLC 调试点位 | PLC 调试页点位表 | 人工实时读写和联调 |

三者不能互相替代。尤其不能从 PLC 调试点位表中选择“正式任务结果变量”。

## 3. 页面配置顺序

“任务执行与 PLC 握手”抽屉必须按以下顺序引导：

1. 配置并保存正式任务工作流。
2. 选择“最终判定工作流”。
3. 选择该工作流正式输出中的 Boolean 变量。
4. 保存任务配置。
5. 发布并激活新的项目部署。
6. 从 OPC UA 完整节点树选择握手地址。
7. 最后才允许勾选并保存“启用 PLC 握手”。

只修改前端表单但没有调用“保存任务配置”，后端仍然读不到结果绑定。

## 4. 项目任务配置接口

### 4.1 获取配置

```http
GET /api/app/workflow/projects/{projectId}/tasks
```

关键响应字段：

```ts
interface ProjectTaskBatch {
  projectId: string
  taskType: number
  cycleIntervalSeconds?: number
  resultWorkflowId?: string
  resultVariableName?: string
  items: Array<{
    id: string
    projectId: string
    workflowId: string
    workflowName: string
    isEnabled: boolean
    orderNo: number
  }>
}
```

### 4.2 保存配置

```http
PUT /api/app/workflow/projects/tasks
Content-Type: application/json
```

请求示例：

```json
{
  "projectId": "3a22ce72-c2d4-7b10-7862-814a3c14b91f",
  "taskType": 0,
  "cycleIntervalSeconds": null,
  "resultWorkflowId": "11111111-2222-3333-4444-555555555555",
  "resultVariableName": "inspectionPassed",
  "items": [
    {
      "id": "00000000-0000-0000-0000-000000000000",
      "projectId": "3a22ce72-c2d4-7b10-7862-814a3c14b91f",
      "workflowId": "11111111-2222-3333-4444-555555555555",
      "workflowName": "正式检测流程",
      "isEnabled": true,
      "orderNo": 0
    }
  ]
}
```

后端会校验：

- `resultWorkflowId` 必须属于当前项目；
- 对应工作流必须在 `items` 中启用；
- `resultVariableName` 必须是该工作流声明的正式输出；
- 变量的声明类型必须是 `System.Boolean`。

前端应使用保存接口返回值覆盖本地 `taskConfig`，以服务端返回结果作为“已保存”状态。

## 5. 正式输出变量来源

选择 `resultWorkflowId` 后，前端获取工作流详情：

```ts
const workflow = await getRuntimeWorkflow(resultWorkflowId)
const names = JSON.parse(workflow.outputVariables || '[]')
```

下拉框只显示工作流声明为正式输出的变量。当前接口的 `outputVariables` 只包含名称，最终 Boolean 类型仍由后端保存任务配置时校验。

若保存任务配置返回以下错误，前端应保留抽屉和用户输入，并把错误展示在“布尔输出变量”字段附近：

```text
正式任务结果变量必须是布尔类型。
结果变量不在所选工作流的正式输出中。
结果绑定必须选择已启用的工作流和布尔输出变量。
```

## 6. OPC UA 握手接口

```http
PUT /api/app/workflow/projects/{projectId}/plc-handshake
Content-Type: application/json
```

`SaveWorkflowPlcHandshakeConfigInput` 中不传 `resultWorkflowId` 或 `resultVariableName`。握手接口会读取前一步已保存的项目任务配置。

```ts
interface SaveWorkflowPlcHandshakeConfig {
  projectId: string
  plcDeviceId: string
  captureRequestAddress: string
  requestIdAddress: string
  resultAckAddress: string
  resultAckIdAddress: string
  heartbeatAddress: string
  deviceStatusAddress: string
  taskStatusAddress: string
  canCaptureAddress: string
  captureAckAddress: string
  ackRequestIdAddress: string
  resultValidAddress: string
  resultRequestIdAddress: string
  resultCodeAddress: string
  errorCodeAddress: string
  isEnabled: boolean
}
```

握手地址必须来自：

```http
POST /api/app/plc-device/{plcDeviceId}/browse-tree
```

不能使用 `/tags` 或 PLC 调试页点位表作为候选项。

## 7. 前端交互修改

### 7.1 增加任务配置保存状态

建议增加：

```ts
const taskConfigSaved = ref(false)

const hasSavedResultBinding = computed(() =>
  taskConfigSaved.value
  && !!taskConfig.value?.resultWorkflowId
  && !!taskConfig.value?.resultVariableName
  && taskConfig.value.items.some(item =>
    item.workflowId === taskConfig.value?.resultWorkflowId && item.isEnabled,
  )
)
```

行为要求：

- 打开抽屉并成功取得任务配置后，设置 `taskConfigSaved = true`；
- 工作流启用状态、顺序、结果工作流或结果变量发生变化时，设置为 `false`；
- `updateProjectTasks` 成功返回后，重新设置为 `true`；
- 保存失败时保持 `false`。

### 7.2 限制握手启用

当 `handshakeForm.isEnabled === true` 时，保存按钮必须检查：

```ts
if (!hasSavedResultBinding.value) {
  toast.error('请先选择并保存正式任务的 Boolean 结果变量。')
  return
}
```

建议在“启用 PLC 握手”旁显示状态：

```text
正式结果：正式检测流程 / inspectionPassed（已保存）
```

未满足条件时：

```text
尚未保存正式任务 Boolean 结果变量，请先完成第 1 步。
```

可以保存 `isEnabled: false` 的握手草稿；只有启用握手时才强制要求正式结果绑定。

### 7.3 切换结果工作流

切换 `resultWorkflowId` 时必须：

1. 清空旧的 `resultVariableName`；
2. 加载新工作流的正式输出；
3. 标记任务配置为未保存；
4. 不自动调用握手保存接口。

### 7.4 避免两个保存动作造成误解

页面应保留两个独立按钮并明确文案：

- `保存任务与结果绑定`
- `保存 OPC UA 握手配置`

不要把第一个按钮仅命名为“保存”，否则用户容易直接进入第 3 步启用握手。

## 8. 推荐的保存逻辑

```ts
async function saveHandshake() {
  if (!projectId.value) return

  if (handshakeForm.value.isEnabled && !hasSavedResultBinding.value) {
    toast.error('请先选择并保存正式任务的 Boolean 结果变量。')
    return
  }

  if (!handshakeForm.value.plcDeviceId) {
    toast.error('请选择 PLC 设备。')
    return
  }

  handshakeForm.value.projectId = projectId.value
  await saveWorkflowPlcHandshake(projectId.value, handshakeForm.value)
  handshakeStatus.value = await getWorkflowPlcHandshakeStatus(projectId.value)
}
```

## 9. 验收用例

1. 未选择结果工作流，启用握手：前端阻止提交。
2. 选择未启用的结果工作流：保存任务配置失败并定位到第 1 步。
3. 选择非 Boolean 输出：后端拒绝，前端保留选择并展示明确错误。
4. 选择 Boolean 正式输出并成功保存任务配置：允许启用握手。
5. 修改结果变量但未重新保存任务配置：禁止启用或保存已启用握手。
6. `isEnabled=false`：允许先保存 OPC UA 地址草稿。
7. OPC UA 地址选择只读取 `browse-tree`，不读取 PLC 调试点位表。
8. 完成任务配置后发布并激活，再由 PLC 发起请求，可正确得到 OK/NG 结果。

## 10. 当前报错的处理步骤

1. 打开“任务执行与 PLC 握手”。
2. 在第 1 步启用用于正式检测的工作流。
3. 选择“最终判定工作流”。
4. 选择该工作流声明并实际产出的 Boolean 输出变量。
5. 点击“保存任务配置”，确认保存成功。
6. 发布新版本并激活。
7. 再到第 3 步启用并保存 OPC UA 握手。
