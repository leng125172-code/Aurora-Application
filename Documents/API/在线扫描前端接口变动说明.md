# 在线扫描前端接口变动说明

## 1. 适用范围

本文档用于标定流程 Step 6“在线扫描”的前端对接。

- REST 基础路径：`/api/app/calib-scan`
- 实时状态 Hub：`/signalr-hubs/camera`
- 相机图像流：`/api/streaming/calibration/{projectId}/cameras/{cameraRole}/preview`
- 接口需要登录态和当前系统权限。

本次接口的核心变化是：

1. 相机原图不再通过 SignalR 传输，改为独立 HTTP Multipart BMP 流。
2. SignalR 只推送扫描状态、扫描指标和增量点云。
3. 有投影仪模式固定使用 `B 2` 单帧模式：`T` 显示第一帧，后续通过 `N` 逐帧切换。
4. `T` 和 `N` 后端均增加 50ms 投影稳定等待，前端不需要自行延时。
5. 每轮条纹总帧数为 Step 3 `PatternCount × 2`，顺序固定为横、竖交替。

## 2. REST 接口

### 2.1 启动在线扫描

```http
POST /api/app/calib-scan/start
Content-Type: application/json
```

请求：

```json
{
  "calibProjectId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

响应：

```json
{
  "calibProjectId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "state": 2,
  "isRunning": true,
  "startedAt": "2026-07-27T08:00:00Z",
  "lastUpdatedAt": "2026-07-27T08:00:00Z",
  "errorMessage": null,
  "latestMetrics": null
}
```

启动时后端自动执行：

1. 校验项目的相机和投影仪绑定。
2. 读取 Step 3 已保存的投影仪参数。
3. 将相机切换为软件触发模式。
4. 投影仪开灯并切换为 `B 2` 单帧触发模式。
5. 启动后台扫描循环。

前端不得重复发送 `B 2`、`T` 或 `N`。

### 2.2 停止在线扫描

```http
POST /api/app/calib-scan/stop
Content-Type: application/json
```

请求：

```json
{
  "calibProjectId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

响应结构与启动接口相同。停止完成后：

- `state` 为 `Idle`；
- `isRunning` 为 `false`；
- 后端停止相机采集并关闭投影仪 LED；
- 后端完成当前增量点云收尾。

重复停止是安全的；不存在运行会话时返回空闲状态。

### 2.3 查询扫描状态

```http
GET /api/app/calib-scan/status/{calibProjectId}
```

该接口是页面刷新、SignalR 重连和状态恢复的权威来源。前端初始化和 Hub 重连后都应重新调用。

## 3. 数据结构

### 3.1 扫描状态

```ts
export enum CalibScanRunState {
    Idle = 0,
    Starting = 1,
    Running = 2,
    Stopping = 3,
    Failed = 4,
}

export interface CalibScanStatusDto {
    calibProjectId: string
    state: CalibScanRunState
    isRunning: boolean
    startedAt: string | null
    lastUpdatedAt: string
    errorMessage: string | null
    latestMetrics: CalibScanMetricsDto | null
}
```

### 3.2 实时指标

```ts
export interface CalibScanMetricsDto {
    fps: number
    depthValidRate: number
    confidence: number
    depthMapDataUri: string | null
    frameIndex: number
    timestamp: string
    roundIndex: number
    frameIndexInRound: number
    patternCount: number
    isCrosshairDetected: boolean
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `roundIndex` | 当前扫描轮次，从 1 开始 |
| `frameIndexInRound` | 当前条纹帧序号，从 0 开始 |
| `patternCount` | 本轮条纹总帧数，等于 Step 3 `PatternCount × 2` |
| `frameIndex` | 跨轮次累计条纹帧序号 |
| `isCrosshairDetected` | 兼容字段；当前正常条纹帧为 `false` |
| `depthValidRate` | 兼容旧接口，当前固定为 0 |
| `confidence` | 兼容旧接口，当前固定为 0 |
| `depthMapDataUri` | 兼容旧接口，当前固定为 `null` |

## 4. 相机预览流

### 4.1 路由

主相机：

```http
GET /api/streaming/calibration/{projectId}/cameras/0/preview
```

从相机：

```http
GET /api/streaming/calibration/{projectId}/cameras/1/preview
```

`cameraRole`：

- `0`：主相机
- `1`：从相机

响应头：

```text
Content-Type: multipart/x-mixed-replace; boundary=auroraframe7f3d9a2b
Cache-Control: no-cache, no-store, must-revalidate
X-Frame-Content-Type: image/bmp
```

每个 Part 的格式：

```text
--auroraframe7f3d9a2b
Content-Type: image/bmp
Content-Length: {length}

{BMP bytes}
```

注意：虽然后端内部扫描 DTO 仍保留 `JpegBytes` 命名，当前浏览器预览接口实际传输的是 BMP 帧，应以响应头 `X-Frame-Content-Type` 为准。

### 4.2 前端读取要求

- 使用 `fetch + ReadableStream` 读取 Multipart 数据。
- 按响应头中的 boundary 分帧。
- 使用 `Content-Length` 截取完整帧。
- 创建 `Blob([bytes], { type: frameMime })` 并显示。
- 替换图片时调用 `URL.revokeObjectURL` 释放旧地址。
- 页面卸载、切换项目或停止预览时取消 `AbortController`。
- URL 建议增加时间戳，并使用 `cache: "no-store"`。

```ts
const response = await fetch(
    `/api/streaming/calibration/${projectId}/cameras/0/preview?t=${Date.now()}`,
    {
        signal: abortController.signal,
        cache: 'no-store',
    }
)
```

无从相机的项目可以不建立角色 `1` 的流连接。

## 5. SignalR

### 5.1 建立连接

```ts
const connection = new signalR.HubConnectionBuilder()
    .withUrl('/signalr-hubs/camera')
    .withHubProtocol(new MessagePackHubProtocol())
    .withAutomaticReconnect([0, 2000, 5000, 10000])
    .build()

await connection.start()
await connection.invoke('JoinCalibScanGroupAsync', projectId)
```

离开页面或切换项目时：

```ts
await connection.invoke('LeaveCalibScanGroupAsync', projectId)
await connection.stop()
```

重连成功后必须重新调用 `JoinCalibScanGroupAsync`，并通过状态接口重新同步：

```ts
connection.onreconnected(async () => {
    await connection.invoke('JoinCalibScanGroupAsync', projectId)
    await getCalibScanStatus(projectId)
})
```

### 5.2 扫描状态事件

事件名：

```text
ReceiveCalibScanStateAsync
```

参数：

```ts
(status: CalibScanStatusDto) => void
```

前端应先检查 `status.calibProjectId === currentProjectId`。

### 5.3 实时指标事件

事件名：

```text
ReceiveCalibScanMetricsAsync
```

参数：

```ts
(projectId: string, metrics: CalibScanMetricsDto) => void
```

### 5.4 增量点云事件

事件名：

```text
ReceiveIncrementalPointCloudAsync
```

参数：

```ts
(
    projectId: string,
    pointCloudBytes: Uint8Array,
    pointCount: number,
    totalPointCount: number
) => void
```

`pointCloudBytes` 是压缩后的点云二进制数据。该事件与相机图像流无关。

### 5.5 已停止使用的帧事件

前端不得继续等待以下方式的扫描原图：

```text
SignalR CalibScanFrameDto / ReceiveCalibScanFrame
```

扫描原图已经转移到 HTTP Multipart BMP 流，SignalR 不再传输大尺寸相机帧。

## 6. 有投影仪模式的帧顺序

假设 Step 3 的 `PatternCount = 4`，则每轮条纹总数为 8：

| `frameIndexInRound` | 投影命令 | 图案 |
| ---: | --- | --- |
| 0 | `T` | 横向第 1 帧 |
| 1 | `N` | 竖向第 1 帧 |
| 2 | `N` | 横向第 2 帧 |
| 3 | `N` | 竖向第 2 帧 |
| 4 | `N` | 横向第 3 帧 |
| 5 | `N` | 竖向第 3 帧 |
| 6 | `N` | 横向第 4 帧 |
| 7 | `N` | 竖向第 4 帧 |

每条投影命令后，后端等待 50ms 再触发相机：

```text
B 2
T → 等待 50ms → 拍摄第 0 帧
N → 等待 50ms → 拍摄第 1 帧
...
```

条纹序列完成后：

1. 投影仪切换白屏；
2. 等待 80ms；
3. 仅主相机采集一张纹理帧；
4. 纹理帧不计入 `patternCount`，不参与相位计算；
5. 随后进入点云重建和下一轮。

## 7. 启动前置条件与常见错误

### 7.1 通用条件

- 项目必须绑定主相机。
- 主相机必须已经打开。

### 7.2 双相机模式

- 必须绑定从相机。
- 从相机必须已经打开。

### 7.3 含投影仪模式

- 必须绑定投影仪。
- 投影仪必须已经连接。
- 必须完成 Step 3 投影仪参数配置。
- Step 3 `PatternCount` 必须大于 0。
- 修改或重新生成条纹后，必须先成功下载到投影仪 Flash。

常见错误消息：

```text
请先绑定主相机后再启动在线扫描
双目扫描模式下必须绑定从相机
含结构光扫描模式下必须绑定投影仪
投影仪尚未连接，请先在设备管理页连接投影仪
请先在 Step3 完成投影仪参数配置
Step3 投影仪参数中图案数量无效，请先完成配置
相机未打开，请先在设备管理页打开相机
```

## 8. 推荐前端调用顺序

```text
进入页面
  ├─ 建立 CameraHub
  ├─ 加入项目扫描分组
  ├─ GET status
  ├─ 建立主相机 HTTP 图像流
  └─ 双相机项目建立从相机 HTTP 图像流

点击开始
  └─ POST start

运行中
  ├─ SignalR 接收状态和指标
  ├─ HTTP Multipart 接收相机图像
  └─ SignalR 接收增量点云

点击停止
  ├─ POST stop
  └─ GET status 确认最终状态

离开页面
  ├─ 取消 HTTP 图像流
  ├─ 退出项目扫描分组
  ├─ 停止 Hub
  └─ 释放 Blob URL 和点云缓冲
```

## 9. 兼容性说明

- REST 启动、停止和状态路由未删除。
- `depthValidRate`、`confidence`、`depthMapDataUri` 为兼容字段，前端不要再依赖其业务值。
- `CalibScanFrameDto` 暂时保留在后端契约中，但不再作为前端实时帧通道。
- HTTP 状态接口是状态恢复依据，SignalR 事件可能因页面断线而丢失。
- 投影仪下载协议修复后，需要重新下载条纹；旧 Flash 内容不会自动转换。
