# 前端 AI 实现任务：多任务与 PLC OPC UA 握手配置

> 本文档用于直接交给代码生成 AI。请严格按本文实现，不要自行增加部署、激活、运行或项目级握手流程。

## 一、实现目标

在现有前端中实现“项目任务管理”功能：

1. 一个项目可以创建多条任务。
2. 每条任务只关联一个项目，并拥有独立的 PLC OPC UA 握手配置。
3. 每条任务必须填写任务名称，用于在同项目的多条任务之间进行区分。
4. 同一项目最多启用一条任务。
5. 切换任务通过修改 `isEnabled` 完成。
6. 页面通过任务列表查询、展示、创建、编辑和切换任务。
7. 新增任务不能调用 `/api/app/workflow/runs`。

## 二、不可变业务规则

- PLC 握手配置属于任务，前端字段路径为 `task.plcHandshake`。
- `name` 是任务名称，创建和修改时必填，去除首尾空格后长度为 1～128 个字符。
- 同项目允许存在多条任务，但最多一条 `isEnabled=true`。
- 启用某条任务时，后端会自动停用同项目其他任务。
- 开关操作成功后必须重新查询整个列表，不能只修改当前行的本地状态。
- `plcHandshake` 可以不配置；未配置时为 `null` 或字段缺省。
- 不传 `plcHandshake` 修改任务时，表示保留原握手配置。
- `plcHandshake.isEnabled` 表示是否启用该任务的 OPC UA 握手协议。
- `task.isEnabled` 表示该任务是否为项目当前生效任务，两者含义不同。
- `/api/app/workflow/runs` 只用于真正启动正式生产运行，不用于创建、保存或启用任务。
- 本页面不要展示“部署快照”“激活版本”“应用到设备”等概念。

## 四、API 封装

基础路径：

```ts
const BASE = '/api/app/workflow'
```

### 4.1 查询任务列表

```http
GET /api/app/workflow/project-tasks?projectId={projectId}
```

- `projectId` 是可选查询参数。
- 当前项目页面必须传 `projectId`。
- 返回 `ProjectTaskRegistration[]`，不是分页对象。

```ts
export async function getProjectTaskRegistrations(
  projectId?: string,
): Promise<ProjectTaskRegistration[]> {
  return (
    await httpClient.get<ProjectTaskRegistration[]>(`${BASE}/project-tasks`, {
      params: projectId ? { projectId } : undefined,
    })
  ).data
}
```

### 4.2 创建任务

```http
POST /api/app/workflow/project-tasks
Content-Type: application/json
```

请求类型：`CreateProjectTaskInput`。

```ts
export async function createProjectTask(
  input: CreateProjectTaskInput,
): Promise<ProjectTaskRegistration> {
  return (
    await httpClient.post<ProjectTaskRegistration>(`${BASE}/project-tasks`, input)
  ).data
}
```

### 4.3 修改任务及握手配置

```http
PUT /api/app/workflow/project-tasks/{taskId}
Content-Type: application/json
```

请求类型：`UpdateProjectTaskInput`。

```ts
export async function updateProjectTask(
  taskId: string,
  input: UpdateProjectTaskInput,
): Promise<ProjectTaskRegistration> {
  return (
    await httpClient.put<ProjectTaskRegistration>(
      `${BASE}/project-tasks/${taskId}`,
      input,
    )
  ).data
}
```

### 4.4 快速切换启用状态

```http
PUT /api/app/workflow/project-tasks/{taskId}/enabled
Content-Type: application/json
```

请求体：

```json
{
  "isEnabled": true
}
```

```ts
export async function setProjectTaskEnabled(
  taskId: string,
  isEnabled: boolean,
): Promise<ProjectTaskRegistration> {
  return (
    await httpClient.put<ProjectTaskRegistration>(
      `${BASE}/project-tasks/${taskId}/enabled`,
      { isEnabled },
    )
  ).data
}
```

## 五、完整请求示例

创建或修改时的 `plcHandshake` 使用以下结构：

```json
{
  "projectId": "project-id",
  "name": "产线一检测任务",
  "isEnabled": true,
  "plcHandshake": {
    "projectId": "project-id",
    "plcDeviceId": "plc-device-id",
    "captureRequestAddress": "ns=2;s=CaptureRequest",
    "requestIdAddress": "ns=2;s=RequestId",
    "resultAckAddress": "ns=2;s=ResultAck",
    "resultAckIdAddress": "ns=2;s=ResultAckId",
    "heartbeatAddress": "ns=2;s=Heartbeat",
    "deviceStatusAddress": "ns=2;s=DeviceStatus",
    "taskStatusAddress": "ns=2;s=TaskStatus",
    "canCaptureAddress": "ns=2;s=CanCapture",
    "captureAckAddress": "ns=2;s=CaptureAck",
    "ackRequestIdAddress": "ns=2;s=AckRequestId",
    "resultValidAddress": "ns=2;s=ResultValid",
    "resultRequestIdAddress": "ns=2;s=ResultRequestId",
    "resultCodeAddress": "ns=2;s=ResultCode",
    "errorCodeAddress": "ns=2;s=ErrorCode",
    "isEnabled": true
  }

```

创建任务时使用全部结构。修改任务时删除最外层 `projectId`，但必须保留 `name`，其余结构相同。

## 六、页面结构

在项目任务页面实现以下区域。

### 6.1 顶部操作区

- 当前项目名称或项目选择器。
- “新增任务”按钮。
- “刷新”按钮。

### 6.2 任务列表

每一行至少展示：

- 项目名称。
- 任务名称，作为列表主标题。
- 任务 ID，可缩略显示并支持复制。
- 当前启用状态。
- PLC 设备名称；未配置时显示“未配置”。
- OPC UA 握手状态；根据 `plcHandshake?.isEnabled` 显示“已启用/未启用”。
- 创建时间。
- 操作：编辑、启用或停用。

同项目只有一条任务可以显示为当前启用。

### 6.3 新增/编辑抽屉或弹窗

表单分成两个区块：

1. 基本信息
   - 项目，创建时必填；编辑时只读。
   - 任务名称，创建和编辑时均必填，最大 128 个字符。
   - 是否启用任务。
2. PLC OPC UA 握手
   - 是否配置握手。
   - 是否启用握手。
   - PLC 设备。
   - 14 个 OPC UA 点位地址。

关闭“是否配置握手”时，提交请求中不要携带 `plcHandshake`。

## 七、交互流程

### 7.1 页面加载

```text
读取路由 projectId
  → GET /project-tasks?projectId=...
  → 保存为任务数组
  → 渲染列表
```

必须提供 `loading`、空状态和重试入口。

### 7.2 新增任务

```text
点击新增
  → 初始化表单
  → 用户填写任务名称并选择项目、启用状态和可选握手配置
  → 表单校验
  → POST /project-tasks
  → 成功提示
  → 关闭弹窗
  → 重新查询整个任务列表
```

### 7.3 编辑任务

```text
点击编辑
  → 使用该列表项及 plcHandshake 回填表单
  → PUT /project-tasks/{taskId}
  → 成功提示
  → 关闭弹窗
  → 重新查询整个任务列表
```

### 7.4 切换当前任务

```text
用户打开某行 isEnabled
  → 二次确认“启用后将自动停用该项目的其他任务”
  → PUT /project-tasks/{taskId}/enabled
  → 重新查询整个任务列表
```

无论成功还是失败，都不要提前永久修改本地列表。请求期间禁用该行开关，防止重复提交。

## 八、表单校验

任务基本信息：

- `projectId` 必填且不是空 GUID。
- `name` 必填；去除首尾空格后长度必须为 1～128 个字符。

当提交 `plcHandshake` 时：

- `plcDeviceId` 必填。
- 14 个地址全部必填并去除首尾空格。
- 14 个地址不得重复。
- `plcHandshake.projectId` 必须等于任务所属 `projectId`。
- 不要向后端提交 `id` 和 `taskConfigId`。

14 个点位字段：

## 九、错误处理

- 优先展示后端返回的 `error.message`。
- 400/500 均不能关闭编辑弹窗，保留用户输入。
- 切换启用失败时重新加载列表，恢复后端真实状态。
- 若后端提示“启用 OPC UA 握手前必须配置正式任务的布尔结果变量”，提示用户先到项目工作流配置正式结果变量。
- 若后端提示“循环任务不能同时启用 OPC UA 握手触发”，不要自动关闭握手，应让用户自行修改配置。
- 不要把业务错误统一替换为“网络错误”。

## 十、禁止实现

- 不要调用 `POST /api/app/workflow/runs` 创建任务。
- 不要在前端自行停用其他任务；只调用目标任务的启用接口，然后刷新列表。
- 不要逐级调用 OPC UA 浏览接口构造树；点位选择应使用后端提供的完整树接口。
- 不要把握手配置保存到独立的项目级表单状态后再单独提交。
- 不要要求用户手动创建部署快照或激活版本。
- 不要把 `task.isEnabled` 和 `plcHandshake.isEnabled` 合并成一个开关。
- 不要假设列表只有一条数据。

## 十一、建议组件拆分

可按现有项目规范调整命名，但职责不要混合：

```text
ProjectTaskPage
├── ProjectTaskToolbar
├── ProjectTaskTable
├── ProjectTaskEditor
│   ├── TaskBasicForm
│   └── PlcHandshakeForm
└── useProjectTasks
```

`useProjectTasks` 负责：

- 列表加载。
- 新增和修改。
- 启用状态切换。
- loading/submitting/switching 状态。
- 请求完成后统一刷新列表。

## 十二、验收标准

AI 完成代码后必须逐项检查：

- [ ] 一个项目可以连续新增两条以上任务。
- [ ] 创建和编辑任务时必须填写任务名称。
- [ ] 任务列表以任务名称作为主要识别信息，不依赖任务 ID 区分。
- [ ] 查询结果以数组形式展示全部任务。
- [ ] 每条任务正确展示自己的 `plcHandshake`。
- [ ] 新增时可以同时提交 PLC 握手配置。
- [ ] 编辑时可以回填并修改 PLC 握手配置。
- [ ] 不传 `plcHandshake` 时不会清空原配置。
- [ ] 启用第二条任务后刷新列表，第一条自动变为停用。
- [ ] 任务启用开关和握手启用开关相互独立。
- [ ] 页面未调用 `/workflow/runs` 创建任务。
- [ ] 页面没有部署快照或激活操作。
- [ ] API 类型检查通过。
- [ ] 前端构建或 `vue-tsc --noEmit` 通过。
