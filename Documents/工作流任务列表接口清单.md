# 工作流任务列表接口清单

> 更新时间：2026-07-08
> 模块：Workflow Runtime
> 路由前缀：/api/app/workflow

## 0. 2026-07 重构变更（CodeSYS 四层对齐）

- 术语澄清：本文「任务」现对应「运行 Run」（执行实例）；路由由 `/tasks` 改为 `/runs`。
- 「任务配置」（原绑定 Binding，启用/顺序/触发类型）是另一层概念，详见《工作流运行时新增接口列表》。
- 强制部署：创建运行前项目必须存在「已激活的部署快照」，已移除 legacy 回退；无激活部署将返回友好错误。
- 冻结执行：运行执行的是部署快照冻结的 GraphData 与变量定义，发布后修改工作流不影响已激活部署的运行结果。
- 新增周期运行：`startType` 支持 `1 = Cyclic`（需 `cycleIntervalSeconds`），通过 Hangfire RecurringJob 周期重跑激活部署。
- 运行入队结果 `deploymentId/deploymentRevision` 恒有值（不再为 null）。

## 1. 说明与范围

本文仅覆盖“任务列表页面”直接相关的接口：

- 启动任务（手动启动）
- 创建任务（入队）
- 查询任务列表
- 查询任务详情
- 修改任务
- 取消任务
- 删除任务
- 任务 Debug（执行会话）

## 3. 详细接口

### 3.0 启动任务（手动启动）

- Method: POST
- Path: /api/app/workflow/runs
- 对应方法：EnqueueProjectRunAsync
- 说明：当前后端没有“先创建、后启动”的二段式接口；调用该接口即表示启动任务（会立即入队到 Hangfire）。

启动请求示例：

```json
{
  "name": "手动启动任务",
  "projectId": "guid",
  "startType": 0,
  "onErrorAction": 0
}
```

启动成功后返回：

- runId
- hangfireJobId
- workflowCount
- deploymentId/deploymentRevision（恒有值，运行来源于激活部署快照）

### 3.1 创建并入队任务

- Method: POST
- Path: /api/app/workflow/runs
- 对应方法：EnqueueProjectRunAsync
- 说明：
  - 1 个运行 = 1 个项目 = 多个工作流
  - 支持 immediate（立即）与 cyclic（周期）启动类型
  - 必须存在已激活 deployment，否则拒绝创建（已移除 legacy 回退）

请求体（WorkflowProjectRunEnqueueInput）:

```json
{
  "name": "任务名称",
  "projectId": "guid",
  "startType": 0,
  "onErrorAction": 0
}
```

字段说明：

- name: 任务名称
- projectId: 项目 ID（必填，不能为空）
- startType:
  - 0 = Immediate（立即执行一次）
  - 1 = Cyclic（周期执行，需 cycleIntervalSeconds > 0）
- cycleIntervalSeconds: 周期间隔（秒），仅 Cyclic 有效
- onErrorAction:
  - 0 = StopRun（遇错停止）
  - 1 = ContinueRun（跳过失败继续）

响应体（WorkflowProjectRunEnqueueResultDto）:

```json
{
  "runId": "guid",
  "projectId": "guid",
  "workflowCount": 3,
  "hangfireJobId": "21873",
  "deploymentId": "guid 或 null",
  "deploymentRevision": 7
}
```

说明：

- deploymentId/deploymentRevision 恒有值（运行来源于激活部署快照）

### 3.2 查询任务列表

- Method: GET
- Path: /api/app/workflow/runs
- 对应方法：GetProjectRunsAsync
- Query:
  - ProjectId（可选，不传表示全部项目）
  - SkipCount（>= 0）
  - MaxResultCount（1 到 200）

响应体：List<WorkflowProjectRunStatusDto>

列表项关键字段：

- runId, name, projectId
- status, startType, cycleIntervalSeconds, onErrorAction
- workflowCount, executedCount, successCount, failedCount
- isCancelRequested
- deploymentId, deploymentRevision
- creationTime, startedAt, finishedAt
- errorMessage

### 3.3 查询任务详情

- Method: GET
- Path: /api/app/workflow/runs/{runId}
- 对应方法：GetProjectRunStatusAsync
- 说明：返回单个任务完整状态，含任务内各工作流执行结果

响应体：WorkflowProjectRunStatusDto

详情关键字段补充：

- items（List<WorkflowProjectRunItemDto>）
  - workflowId
  - status
  - executionId
  - errorMessage
  - startedAt
  - finishedAt

### 3.4 取消任务

- Method: POST
- Path: /api/app/workflow/runs/{runId}/cancel
- 对应方法：CancelProjectRunAsync
- 说明：设置取消请求标志；接口返回 200 表示请求已受理

### 3.5 修改任务

- Method: PUT
- Path: /api/app/workflow/runs/{runId}
- 对应方法：UpdateProjectRunAsync
- 说明：仅允许修改任务名称与任务级错误策略

请求体（WorkflowProjectRunUpdateInput）:

```json
{
  "name": "更新后的任务名称",
  "onErrorAction": 1
}
```

校验与限制：

- runId 不能为空
- name 不能为空
- onErrorAction 必须是有效枚举值
- 运行中的任务不允许修改

响应体：WorkflowProjectRunStatusDto（修改后的最新状态）

### 3.6 删除任务

- Method: DELETE
- Path: /api/app/workflow/runs/{runId}
- 对应方法：DeleteProjectRunAsync
- 说明：运行中的任务不允许删除，请先取消或等待结束

### 3.7 任务 Debug（执行会话）

- 说明：
  - 任务接口本身没有独立的 /tasks/{runId}/debug 路由。
  - Debug 通过执行会话接口完成，路由前缀仍是 /api/app/workflow。
  - `/api/app/workflow/executions` 同一路径支持两种方法：GET（查询）与 POST（触发）。
  - 对于任务中的单工作流，可通过任务详情 items[*].executionId 关联到执行会话状态。

#### 3.7.1 [GET] 查询调试任务列表

- Method: GET
- Path: /api/app/workflow/executions
- 对应方法：GetDebugSessionsAsync
- Query:
  - projectId（可选，不传返回全部项目调试会话）
  - runId（可选，按任务过滤）
  - includeVariables（可选，默认 false）
- 说明：
  - 不传 runId：返回常规调试会话列表。
  - 传 runId：返回该任务“当前执行会话”单条记录，前端无需自行聚合。

响应体：List<WorkflowExecutionStatusDto>

关键字段：

- runId, projectId
- workflowOrderNo（当前执行到任务工作流列表第几个）
- currentNodeOrderNo（当前执行到当前工作流第几个节点）
- workflowId, currentNodeId
- executionId, status

重启行为：

- 调试任务列表存储在进程内存中，不落库。
- 程序重启后会话存储重新初始化，调试列表会被自动清空。

#### 3.7.2 [POST] 触发调试执行

- Method: POST
- Path: /api/app/workflow/executions
- 对应方法：ExecuteAsync
- 入参规则：
  - `projectId` 必填。
  - `workflowId` 与 `runId` 至少传一个。
  - 若只传 `runId`：
    - 任务内只有 1 个工作流时，后端自动解析该工作流。
    - 任务内有多个工作流时，后端会自动按任务进度定位当前调试目标工作流（优先级：Running > Pending > Failed）。
    - 调试目标前置工作流会自动按任务顺序预热执行（RunOnce），用于恢复跨工作流变量上下文。

请求示例（DebugStep 模式）：

```json
{
  "projectId": "guid",
  "runId": "guid",
  "mode": 1,
  "useOnlineVariablePool": true,
  "runtimeInstanceId": "guid"
}
```

响应关键字段：

- executionId
- status（当前执行状态快照）

#### 3.7.3 调试单步执行

- Method: POST
- Path: /api/app/workflow/executions/{executionId}/steps
- 对应方法：StepAsync

#### 3.7.4 查询调试状态

- Method: GET
- Path: /api/app/workflow/executions/{executionId}
- 对应方法：GetStatusAsync
- Query: includeVariables（可选，默认 true）

#### 3.7.5 停止调试会话

- Method: DELETE
- Path: /api/app/workflow/executions/{executionId}
- 对应方法：StopDebugAsync

## 4. 枚举建议（前端展示）

### 4.1 WorkflowProjectRunOnErrorAction

- 0: StopRun
- 1: ContinueRun

### 4.2 WorkflowProjectRunStatus

- 建议前端按后端实际枚举值做状态映射，避免硬编码文本
- 列表页至少区分：Pending/Running/Succeeded/Failed/Canceled

### 4.3 WorkflowProjectRunStartType

- 0: Immediate（立即执行一次）
- 1: Cyclic（周期执行，需 cycleIntervalSeconds > 0）

## 5. 列表页联调建议

1. 首次加载按 creationTime 倒序展示，分页参数使用 skipCount/maxResultCount。
2. 当列表项 isCancelRequested=true 时，前端应禁用再次取消按钮。
3. 当任务 status=Running 时，前端应禁用修改/删除按钮。
4. 运行恒来源于激活部署快照，deploymentId/deploymentRevision 必有值，可展示部署版本号。
5. 当任务详情中存在 items[*].executionId 时，可进入执行会话 Debug 面板查询状态/变量并进行单步调试。
