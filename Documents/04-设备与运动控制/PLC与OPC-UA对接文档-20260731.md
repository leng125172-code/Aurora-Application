# PLC 与 OPC UA 对接文档

> 适用版本：AuroraStruct3D PLC 通讯首版  
> 更新日期：2026-07-31  
> 面向对象：PLC/电气工程师、前端开发、第三方系统开发及部署运维人员

## 1. 功能范围

系统通过统一 PLC 设备和业务点位模型接入工业控制器。本版本完整支持 OPC UA，并为后续协议驱动保留统一扩展接口。

| 协议 | 驱动 ID | 当前状态 |
| --- | --- | --- |
| OPC UA | `opc-ua` | 已安装，支持连接、浏览、批量读写和订阅 |
| 西门子 S7 | `siemens-s7` | 规划中，驱动未安装 |
| 欧姆龙 FINS TCP | `omron-fins-tcp` | 规划中，驱动未安装 |
| 欧姆龙 FINS UDP | `omron-fins-udp` | 规划中，驱动未安装 |
| 基恩士 MC/SLMP | `keyence-mc` | 规划中，驱动未安装 |

未安装的驱动会出现在驱动目录中，但不能建立连接或执行点位操作。

OPC UA 驱动能力值为：

| 能力 | 位值 |
| --- | ---: |
| Browse | 1 |
| Read | 2 |
| Write | 4 |
| Subscribe | 8 |
| BatchRead | 16 |
| BatchWrite | 32 |
| SecureChannel | 64 |

客户端应依据接口返回的 `capabilities` 和 `driverInstalled` 控制功能，不应仅根据协议名称判断。

## 2. 网络与 PLC 侧准备

### 2.1 OPC UA 服务端

PLC 侧需完成以下配置：

1. 启用 OPC UA Server。
2. 开放 OPC UA 监听端口，默认 TCP 端口为 `4840`。
3. 将需要访问的变量发布到 OPC UA 地址空间。
4. 为变量配置正确的读写权限。
5. 根据现场安全要求启用匿名、用户名密码或证书认证。
6. 确认应用服务器能访问 PLC IP 和端口。`ping` 成功只代表 ICMP 可达，仍需确认 TCP 端口可连接。

Endpoint URL 示例：

```text
opc.tcp://192.168.1.10:4840
```

Linux 端口检查示例：

```bash
nc -vz 192.168.1.10 4840
```

### 2.2 已验证的基恩士 PLC

本项目已对以下现场设备完成真实连接与读写测试：

| 项目 | 结果 |
| --- | --- |
| Endpoint | `opc.tcp://192.168.1.10:4840` |
| 认证/安全 | 匿名、SecurityPolicy `None`、MessageSecurityMode `None` |
| 服务端证书指纹 | `DC645A4E2BA57BA18AD8B48AC8B7FB074B9971CF` |
| 已发现目录 | `PLC/GlobalVars` |
| 已读取节点 | `ns=4;s=MESData`，类型 `Byte[5481]`，质量 `Good` |
| 已读写节点 | `ns=4;s=TEST_OPCUA`，类型 `Int32` |
| 写入验证 | 原值 `0` → 写入 `1` → 读回 `1` → 恢复 `0` |
| 恢复验证 | 恢复成功，最终质量 `Good` |

以上 NodeId 和 NamespaceIndex 由当前 PLC 工程决定。PLC 程序重新下载或服务器命名空间调整后，应重新浏览并确认 NodeId。

## 3. 关键概念

### 3.1 设备与点位

- `PlcDevice` 表示一个 PLC 通讯端点和安全配置。
- `PlcTag` 表示一个业务点位。
- OPC UA 点位地址使用标准 NodeId，例如 `ns=4;s=TEST_OPCUA`。
- 业务代码 `code` 全局唯一，例如 `MES.TEST_VALUE`。
- 应用层及未来工作流应使用设备 ID 和业务代码访问点位，不应直接依赖 OPC UA NodeId。

### 3.2 工程量转换

读取时：

```text
工程值 = 原始值 × scale + offset
```

写入时，API 接收工程值并反算：

```text
原始值 = (工程值 - offset) / scale
```

`minimum`、`maximum` 约束针对传入的工程值。布尔、字符串、日期和字节串不执行数值缩放。

### 3.3 连接生命周期

- 首次连接测试、浏览、读取、写入或订阅时按需建立连接。
- 同一设备复用一个并发安全连接。
- KeepAlive 默认 5 秒。
- 初始重连间隔默认 1 秒，最大 30 秒。
- 空闲连接默认 10 分钟后回收。
- 服务停止时释放订阅和 OPC UA Session。

## 4. 调用约定

REST API 基础路径：

```text
/api/app/plc-device
```

SignalR Hub：

```text
/signalr-hubs/plc
```

所有接口均要求登录认证。受保护操作还应携带稳定的客户端会话标识：

```http
Authorization: Bearer <access-token>
X-Client-Session-Id: <client-generated-uuid>
Content-Type: application/json
```

`X-Client-Session-Id` 应由客户端首次运行时生成并在同一客户端会话中复用，用于 PLC 独占操作会话判定。

### 6.7.1 读取值与复杂 OPC UA 数据展示

`rawValue` 和 `engineeringValue` 保持 OPC UA 驱动读取到的原始值形态：它们可能是标量、
数组或结构体。接口不会把复杂对象压缩成字符串；调用方必须根据值类型决定展示方式。

对于 OPC UA `ExtensionObject`，JSON 中常出现 `typeId`、`encoding`、
`binaryEncodingId`、`xmlEncodingId`、`jsonEncodingId` 及 `innerNodeId`。这些是 OPC UA
类型和编码元数据，不是 PLC 过程值。客户端应按以下步骤处理：

1. 若对象含有 `body` 对象，以 `body` 作为业务内容。
2. 默认视图过滤上述编码元数据，并将剩余字段渲染为“字段名 - 值”。
3. 标量直接显示；数组显示数量并可展开逐项查看；复杂结构显示业务摘要和字段详情。
4. 原始 JSON 只能放在“调试”折叠区，不能直接作为操作人员默认看到的值。

基恩士 KV OPC UA Server 的标准服务器状态节点为 `ns=0;i=2256`（`ServerStatus`）。
该节点返回 `ServerStatusDataType`，不是普通数值。当前已验证的设备返回：

| 字段 | 示例值 | 操作员界面显示 |
| --- | --- | --- |
| `state` | `0` | 运行中 |
| `buildInfo.productName` | `KV OPC UA Server` | 产品名称 |
| `buildInfo.manufacturerName` | `KEYENCE CORPORATION` | 厂商 |
| `buildInfo.softwareVersion` | `1.400` | 软件版本 |

因此，建议显示摘要“`KV OPC UA Server · 运行中`”，而不是显示完整编码 JSON。标准
`ServerStatus` 适合做连接健康与设备信息展示；生产业务逻辑应读取 PLC 工程发布的变量
节点，例如当前工程中的 `ns=4;s=TEST_OPCUA`，并通过业务点位代码访问。

## 7. SignalR 实时订阅

### 7.1 建立 Hub 连接

```ts
import * as signalR from '@microsoft/signalr'

const connection = new signalR.HubConnectionBuilder()
  .withUrl('/signalr-hubs/plc', {
    accessTokenFactory: () => accessToken,
  })
  .withAutomaticReconnect()
  .build()

connection.on('ValueChanged', value => {
  console.log('PLC value:', value)
})

connection.on('ConnectionStateChanged', (deviceId, status, error) => {
  console.log('PLC state:', deviceId, status, error)
})

await connection.start()
```

### 7.2 创建订阅

SignalR 连接成功后，使用 `connection.connectionId` 调用：

```http
POST /api/app/plc-device/{id}/subscribe
```

```json
{
  "connectionId": "<signalr-connection-id>",
  "tagIds": [
    "11111111-1111-1111-1111-111111111111"
  ]
}
```

响应：

```json
{
  "subscriptionId": "<server-subscription-id>"
}
```

取消订阅：

```http
POST /api/app/plc-device/{id}/unsubscribe?subscriptionId=<server-subscription-id>
```

客户端正常退出时应主动取消订阅。SignalR 意外断开时，Hub 会回收该连接关联的订阅。

## 8. 写入与配置安全

以下操作仅允许在系统处于手动模式或检修模式时执行：

- 创建、修改或删除 PLC。
- 修改凭据和连接配置。
- 创建、修改或删除点位。
- 写入点位。
- 确认变化后的服务端证书。

写操作需要持有该 PLC 的独占设备会话。同一个 `X-Client-Session-Id` 会续期；不同客户端同时操作时，后到请求会因设备已被占用而失败。读取、浏览和监控允许共享。

写入还会执行以下检查：

- PLC 和点位必须启用。
- 点位必须属于目标 PLC。
- 点位必须具有写权限。
- 输入必须能转换为点位数据类型。
- 数值不能为 `NaN` 或无穷大。
- 工程值必须位于 `minimum` 和 `maximum` 范围内。
- 批量写入结果必须逐项确认。

生产环境不建议使用测试点位之外的变量进行试写。测试时应先读取原值，在 `finally` 或等效故障保护流程中恢复，并再次读回确认。

## 9. OPC UA 证书策略

- 首次连接到未知服务端证书时，若启用 `autoTrustServerCertificate`，系统接受证书并保存指纹元数据。
- 后续连接必须与已保存指纹一致。
- 服务端证书变化时，系统断开连接并拒绝静默替换。
- 确认 PLC 固件、证书和网络环境可信后，调用 `confirm-server-certificate` 更新指纹。

```http
POST /api/app/plc-device/{id}/confirm-server-certificate
```

```json
{
  "thumbprint": "<new-certificate-thumbprint>"
}
```

证书确认属于安全敏感操作，应记录设备变更依据和操作人。

## 11. 部署检查

1. 执行 DbMigrator，确认 PLC 设备、点位、操作日志和证书表创建成功。
2. 确认 API 服务发布包包含 `AuroraStruct3D.Plc.dll` 和 OPC Foundation 依赖。
3. 确认 API 主机到 PLC 的 TCP 4840 端口可达。
4. 启动 API，确认没有 `PlcHubProxy`、驱动注册或 OPC UA 依赖加载异常。
5. 在 PLC 管理页创建设备并执行连接测试。
6. 浏览地址空间，创建测试点位。
7. 先读后写，并恢复原值。
8. 建立 SignalR 订阅，确认值变化和连接状态事件。

## 12. 常见问题

### 12.1 Ping 通但连接失败

检查 4840 端口、防火墙、OPC UA Server 是否启用、Endpoint URL 是否正确，以及安全策略是否被服务端支持。

### 12.2 提示“PLC 驱动未安装”

当前只有 `opc-ua` 已实现。S7、FINS 和 MC/SLMP 只是协议占位，不能用于真实连接。

### 12.3 浏览不到变量

确认变量已发布到 OPC UA 地址空间，并检查当前账号的浏览权限。NamespaceIndex 可能因 PLC 工程变化而变化。

### 12.4 读取成功但质量不是 Good

HTTP 成功不代表过程值有效。应根据 `quality`、时间戳和 `error` 判断数据是否可用于业务。

### 12.5 写入被拒绝

依次检查系统运行模式、`X-Client-Session-Id`、独占会话占用情况、点位访问权限、数据类型和工程值上下限。

### 12.6 提示服务端证书已变化

不要直接绕过。先核对 PLC 地址、设备身份和新证书指纹，确认是合法证书更新后再执行人工确认。
