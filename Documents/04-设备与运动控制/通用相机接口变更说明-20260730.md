# 通用相机接口变更说明

更新日期：2026-07-30  
适用范围：后端 `ICameraDeviceAppService`、前端 `src/api/cameras.ts`  
基础路由：`/api/app/camera-device`

## 1. 变更摘要

本次没有修改相机接口的基础路由，但修改了设备 DTO、扫描接口返回值和设备信息温度字段，并在硬件操作前增加统一的在线状态与能力校验。

主要兼容性影响：

1. `POST /api/app/camera-device/scan-cameras` 的返回值由单个数字改为结构化对象，属于破坏性返回类型变更。
2. `CameraDeviceDto` 新增驱动、稳定硬件身份、连接摘要、能力位图和在线状态。
3. `CameraDeviceInfoDto.fpgaTemperature`、`sensorTemperature` 改为可空；不支持温度的相机返回 `null`，不再导致整个设备信息接口失败。
4. 预览、快照、软件触发、RTP、温度和参数节点操作会按设备能力校验。不支持的操作返回可展示的业务错误。
5. 上层硬件操作仍使用数据库设备 `id`；`deviceIndex` 仅作为兼容字段，不得作为跨驱动稳定身份。

## 2. 设备 DTO 新增字段

以下接口返回的 `CameraDeviceDto` 均包含新增字段：

- `GET /api/app/camera-device`
- `GET /api/app/camera-device/{id}`
- `POST /api/app/camera-device`
- `PUT /api/app/camera-device/{id}`

新增字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `driverId` | `string` | 驱动唯一标识，当前 Tucam 为 `tucam` |
| `hardwareId` | `string \| null` | 驱动提供的稳定硬件身份；Tucam 使用设备序列号 |
| `connectionSummary` | `string \| null` | 当前连接摘要，例如 `USB index 0` |
| `capabilities` | `number` | `CameraCapability` 位图 |
| `isOnline` | `boolean` | 本次扫描是否发现该设备 |

示例：

```json
{
  "id": "3a22c47b-d8df-c79c-3a71-49964e5faac5",
  "name": "Tucam Libra 3405UC",
  "model": "Libra 3405UC",
  "driverId": "tucam",
  "hardwareId": "RCSJ18925003",
  "connectionSummary": "USB index 0",
  "capabilities": 87,
  "isOnline": true,
  "deviceIndex": 0,
  "status": 1,
  "isEnabled": true
}
```

注意：日志、界面和导出文件应对 `hardwareId` 脱敏，不应直接公开完整序列号。

## 3. 相机能力位图

`capabilities` 为 Flags 位图，可通过按位与判断能力：

| 能力 | 数值 | 前端含义 |
| --- | ---: | --- |
| `Preview` | 1 | 实时预览 |
| `Snapshot` | 2 | 单帧快照 |
| `SoftwareTrigger` | 4 | 软件触发 |
| `ExternalTrigger` | 8 | 外部触发 |
| `ParameterNodes` | 16 | 参数节点/NodeMap |
| `Temperature` | 32 | 温度读取与显示 |
| `RtpStream` | 64 | RTP/MJPEG UDP 推流 |
| `ConcurrentPreview` | 128 | 同能力组并发预览 |
| `ConcurrentTrigger` | 256 | 同能力组并发触发 |

TypeScript 判断示例：

```ts
const supportsSnapshot =
    (camera.capabilities & CameraCapability.Snapshot) !== 0
```

能力缺失时，前端不应发起对应请求；后端仍会二次校验，避免绕过前端控制。

## 4. 扫描接口变更

### 请求

```http
POST /api/app/camera-device/scan-cameras
Authorization: Bearer <token>
```

请求体为空。

### 原返回值

```json
2
```

### 新返回值

```json
{
  "totalDiscovered": 2,
  "created": 0,
  "updated": 2,
  "offline": 0,
  "conflicts": 0,
  "drivers": [
    {
      "driverId": "tucam",
      "displayName": "Tucam",
      "discovered": 2,
      "bound": 2,
      "conflicts": 0,
      "error": null
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `totalDiscovered` | 所有驱动本次发现的有效设备数量 |
| `created` | 新建绑定记录数量 |
| `updated` | 刷新连接摘要、能力或在线状态的记录数量 |
| `offline` | 保留在数据库但本次未发现的历史设备数量 |
| `conflicts` | 空硬件 ID、同驱动重复身份等冲突数量 |
| `drivers` | 每个驱动的扫描、绑定、冲突和错误结果 |

单个驱动扫描失败不会阻断其他驱动；失败信息写入对应 `drivers[].error`。

## 5. 设备信息接口变更

### 请求

```http
GET /api/app/camera-device/{id}/device-info
Authorization: Bearer <token>
```

### 返回

```json
{
  "model": "Libra 3405UC",
  "serialNumber": "RCSJ18925003",
  "firmwareVersion": "",
  "fpgaVersion": "",
  "fpgaTemperature": null,
  "sensorTemperature": null,
  "currentWidth": 0,
  "currentHeight": 0
}
```

温度字段为 `null` 表示设备未声明 `Temperature` 能力。前端必须按可空字段处理，不能把 `null` 显示为 `0 °C`。

Tucam `Libra 3405UC` 在未开始采集时可能返回 `currentWidth=0`、`currentHeight=0`；实际采集帧已验证为 2448×2048。当前尺寸字段不能作为该型号是否在线或能否采集的判断依据。

## 6. 当前相机控制接口

| 方法 | 路由 | 所需能力 |
| --- | --- | --- |
| `POST` | `/api/app/camera-device/{id}/open-camera` | 在线且驱动可用 |
| `POST` | `/api/app/camera-device/{id}/close-camera` | 驱动可用 |
| `POST` | `/api/app/camera-device/{id}/take-snapshot` | `Snapshot` |
| `POST` | `/api/app/camera-device/{id}/start-preview` | `Preview`；启用 RTP 时还需 `RtpStream` |
| `POST` | `/api/app/camera-device/{id}/stop-preview` | `Preview` |
| `POST` | `/api/app/camera-device/{id}/do-software-trigger` | `SoftwareTrigger` |
| `GET` | `/api/app/camera-device/{id}/rtp-endpoint` | `RtpStream` |
| `GET` | `/api/app/camera-device/{id}/node-map` | `ParameterNodes` |
| `POST` | `/api/app/camera-device/{id}/refresh-node-map` | `ParameterNodes` |
| `GET/POST` | GenICam 参数读写与命令路由 | `ParameterNodes` |

设备离线、驱动未注册或能力不支持时，接口返回 ABP 标准业务错误：

```json
{
  "error": {
    "message": "相机 [设备名称] 的驱动不支持 Temperature 能力",
    "details": null,
    "data": {},
    "validationErrors": null
  }
}
```

前端应优先展示 `error.message`。

## 7. 前端迁移要求

1. 将 `scanCameras(): Promise<number>` 更新为 `Promise<CameraScanResultDto>`。
2. 列表绑定使用数据库 `id`，设备展示使用 `driverId + hardwareId`，不得用 `deviceIndex` 作为业务主键。
3. 根据 `capabilities` 动态显示预览、快照、软触发、RTP、温度及参数节点面板。
4. `ParameterNodes` 缺失时，不请求 NodeMap、节点快照或刷新接口。
5. `fpgaTemperature`、`sensorTemperature` 按 `number | null` 处理。
6. `isOnline=false` 时禁用所有硬件操作，但保留历史设备记录和编辑入口。

## 8. 已验证结果

- 本地 Host 后台扫描：发现 2 台、冲突 0、打开 2 台。
- 登录态设备列表正确返回数据库设备 ID、`driverId`、稳定 `hardwareId` 和能力位图。
- 两台相机分别通过 HTTP 快照接口成功返回 JPEG Data URI。
- 无温度能力时设备信息接口正常返回，温度字段为 `null`。
- USB 交换后单实例全量硬件回归通过，失败用例 0。

## 9. 已知限制

- 当前 Swagger JSON 会被既有 `WorkflowAppService.GetListAsync` HTTP 方法歧义阻断；ABP API Definition 和实际相机 HTTP 接口可正常使用。
- 物理交换 USB 后，Tucam SDK 枚举顺序仍保持不变，尚未实际覆盖运行期索引对调。
- SignalR 预览与标定采图仍属于测试设备升级前的剩余回归门禁。
