# Aurora Struct3D 第三方相机预览接入与 AI 代码生成规格

## 0. AI 使用说明

本文既是第三方接入文档，也是可以直接交给 AI 编程助手执行的技术规格。

使用 AI 生成代码时，推荐按以下方式操作：

1. 将本文完整内容提供给 AI，不要只复制某一个接口章节。
2. 在本文后追加目标技术栈，例如 Vue 3、React、原生 JavaScript、C# WPF 或 Python。
3. 要求 AI 严格按照“AI 实现约束”和“验收标准”生成代码。
4. 如果现有项目已经有 HTTP 客户端、认证模块或 UI 组件，应同时把相关文件提供给 AI。

### 0.1 可直接复制的 AI 提示词

复制下面的提示词，并将本文作为上下文一起提供给 AI：

```text

目标技术栈：
[在这里填写，例如：Vue 3 + TypeScript + Vite]

项目约束：
[在这里填写，例如：使用现有 Axios 实例；组件采用 Composition API；不能新增 UI 框架]

2. 打开相机。

4. 使用 fetch + ReadableStream 读取 multipart/x-mixed-replace 流。
5. 动态解析 boundary、Content-Length 和帧 MIME。
6. 将每个 image/bmp 帧显示在页面上。
7. 正确取消读取、释放 Object URL 并停止预览。

9. 如项目允许安装依赖，则接入 SignalR MessagePack、心跳和断线续约；否则将 SignalR 封装为可选模块。

实现时禁止：
1. 禁止把预览地址直接赋给 img.src。
2. 禁止把帧按 JPEG 解码；网络帧是 BMP。
3. 禁止再次解包 BAYGB12Packed。
4. 禁止硬编码 multipart boundary。
5. 禁止忽略 Content-Length。
6. 禁止累积所有历史帧。
7. 禁止遗漏 AbortController、reader 释放和 URL.revokeObjectURL。

输出内容：
1. 文件清单。
2. 每个新增或修改文件的完整代码。
3. 依赖安装命令（如有）。
4. 配置项说明。
5. 启动和测试步骤。
6. 对照文档验收标准逐项说明。

如果规格与目标项目现有实现冲突，先指出具体冲突，再采用改动最小且符合协议的实现。不要自行改变服务端接口路径、请求方法、字段名或传输格式。
```

### 0.2 AI 需要生成的推荐文件

不同技术栈可以调整文件名，但职责应保持一致：

```text
src/
├─ api/
│  └─ aurora-camera-api.ts       # REST API 封装
├─ streaming/
│  ├─ multipart-bmp-parser.ts    # Multipart 增量解析器
│  ├─ camera-preview-client.ts   # 预览生命周期、重连和资源释放
│  └─ camera-signalr-client.ts   # SignalR，可选
├─ components/
│  └─ CameraPreview.vue          # 或 React/WPF 等对应 UI
└─ types/
   └─ aurora-camera.ts           # DTO 和状态类型
```

AI 应优先把 Multipart 解析器与 UI 分离，以便单元测试和在其他页面复用。

### 0.3 AI 实现约束

以下要求属于强制协议，不是建议：

- 必须使用 HTTP `fetch` 或支持流式读取的等价 API。
- 必须增量处理数据块，因为 boundary、Part Header 和 BMP 帧都可能被任意拆分到多个网络数据块。
- 必须从响应 `Content-Type` 动态解析 boundary。
- 必须从每个 Part Header 解析 `Content-Length`。
- 必须优先读取 `X-Frame-Content-Type`，缺失时回退为 `image/bmp`。
- 必须把每一帧视为完整 BMP 文件。
- 必须仅保留最新显示帧，不能建立无界帧队列。
- 替换图片后必须释放上一帧的 Object URL。
- 停止、异常、组件卸载时必须取消读取并释放资源。
- REST 接口错误必须向调用方或 UI 暴露，不能全部静默吞掉。
- 自动重连必须有退避和次数/状态控制，不能无间隔死循环。
- 不得根据 `BAYGB12Packed` 推断网络帧布局，也不得在客户端解 Bayer。

### 0.4 最小交付要求

AI 生成结果至少应包含：

| 交付项 | 要求 |
|---|---|
| API 客户端 | 封装列表、打开、启动和停止接口 |
| Multipart 解析器 | 支持跨 Chunk 的 boundary、Header 和 Payload |
| 预览客户端 | 使用 AbortController 管理单个相机流 |
| UI 示例 | 能选择或配置相机 ID，并显示最新 BMP 帧 |
| 错误状态 | 至少区分启动失败、流连接失败和流读取中断 |
| 清理逻辑 | 停止、卸载及异常时释放 reader、流和 Object URL |
| 配置 | Base URL、认证信息不得散落硬编码 |
| 测试 | 至少覆盖 Multipart 被拆分为多个 Chunk 的情况 |

### 0.5 AI 验收标准

生成代码必须能够通过以下场景：

1. 一个 boundary 被拆成两个网络 Chunk，仍能正确识别。
2. `Content-Length` Header 被拆成多个 Chunk，仍能正确解析。
3. 一帧 BMP Payload 被拆成多个 Chunk，等待完整后才显示。
4. 一个 Chunk 同时包含多帧，能够连续解析全部完整帧。
5. 收到不完整帧时不创建 Blob。
6. 收到完整帧后使用 `image/bmp` 创建 Blob。
7. 新帧替换旧帧时调用 `URL.revokeObjectURL`。
8. 用户停止预览后，底层 fetch 被 AbortController 取消。
9. UI/组件卸载后不存在继续运行的读取循环。
10. 服务端返回非 2xx 时，客户端显示或抛出可诊断错误。
11. 流断开重连时不会重复启动多个并发读取器。
12. 客户端不包含 `BAYGB12Packed` 解包代码。

## 1. 文档说明

本文说明第三方 Web、桌面或服务端程序如何接入 Aurora Struct3D 相机实时预览。

当前预览方案由三部分组成：

1. REST API：查询、打开相机以及启动/停止预览。
2. HTTP Multipart 流：持续传输预览图像。
3. SignalR（可选但推荐）：接收相机状态和运行指标，并管理预览连接生命周期。

> 重要：预览流的 HTTP 类型为 `multipart/x-mixed-replace`，但每一帧是未经 JPEG 压缩的 BMP 图像（`image/bmp`）。浏览器不能直接使用 `<img src="预览地址">` 播放，必须使用 `fetch` 读取响应流并按 `Content-Length` 拆帧。

### 1.1 协议事实表

AI 和第三方实现应直接采用以下事实，不得自行猜测：

| 项目 | 固定值或规则 |
|---|---|
| 相机 REST 根路径 | `/api/app/camera-device` |
| 启动预览 | `POST /api/app/camera-device/{cameraId}/start-preview` |
| 停止预览 | `POST /api/app/camera-device/{cameraId}/stop-preview` |
| 预览流 | `GET /api/streaming/cameras/{cameraId}/preview` |
| SignalR Hub | `/signalr-hubs/camera` |
| 流响应类型 | `multipart/x-mixed-replace` |
| Part 图像类型 | `image/bmp` |
| 帧长度来源 | Part Header 中的 `Content-Length` |
| boundary 来源 | HTTP 响应 `Content-Type` 参数 |
| 典型分辨率 | `2448 × 2048`，但客户端不得写死 |
| Bayer 处理位置 | 服务端 |
| 客户端是否解 Bayer | 否 |
| 客户端是否直接 `<img src=流地址>` | 否 |

## 2. 基本信息

将以下示例中的变量替换为实际值：

```text
BASE_URL  = http://设备地址:端口
CAMERA_ID = 相机设备 GUID
```

例如：

```text
BASE_URL  = http://192.168.1.100:5000
CAMERA_ID = 35e3df33-9fb1-4c44-b521-ea63e188dfc2
```

所有 JSON 请求均使用：

```http
Content-Type: application/json
```

如果部署环境启用了身份认证，还需要携带：

```http
Authorization: Bearer <access_token>
```

跨域访问时，服务端必须允许第三方页面所在 Origin。若使用 Cookie 认证，客户端还需要设置 `credentials: "include"`，服务端同时需要允许凭据。

## 3. 推荐接入流程

```text
查询相机列表
    ↓
打开目标相机
    ↓
建立 SignalR 连接（推荐）
    ↓
调用 start-preview
    ↓
连接 HTTP Multipart 预览流
    ↓
持续拆分并显示 BMP 帧
    ↓
断开流并调用 stop-preview
```

相机控制接口只允许在系统的“手动模式”或“检修模式”下调用。相机被其他客户端独占或系统处于不允许手动控制的模式时，启动接口会返回业务错误。

## 4. REST API

### 4.1 查询相机列表

```http
GET {BASE_URL}/api/app/camera-device?maxResultCount=100
```

响应示例：

```json
{
  "totalCount": 1,
  "items": [
    {
      "id": "35e3df33-9fb1-4c44-b521-ea63e188dfc2",
      "name": "Camera 0",
      "deviceIndex": 0,
      "status": 1
    }
  ]
}
```

第三方应使用 `items[].id` 作为后续接口的 `CAMERA_ID`。实际 DTO 可能包含更多字段，客户端应忽略不认识的新增字段。

### 4.2 查询单台相机

```http
GET {BASE_URL}/api/app/camera-device/{CAMERA_ID}
```

### 4.3 打开相机

```http
POST {BASE_URL}/api/app/camera-device/{CAMERA_ID}/open-camera
Content-Length: 0
```

正常响应为 HTTP 2xx。重复打开时应以服务端返回结果为准。

### 4.4 启动预览

```http
POST {BASE_URL}/api/app/camera-device/{CAMERA_ID}/start-preview
Content-Type: application/json

{
  "connectionId": "<SignalR connectionId，可为 null>",
  "enableRtp": false
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
|---|---:|---:|---|
| `connectionId` | string/null | 否 | SignalR 连接 ID，用于状态推送、断线清理和预览续约 |
| `enableRtp` | boolean | 否 | 是否同时启用 RTP/MJPEG UDP 输出；普通 HTTP 预览应设为 `false` |

如果第三方不使用 SignalR，可传：

```json
{
  "connectionId": null,
  "enableRtp": false
}
```

启动接口成功仅表示后台采集任务已经启动。首帧生成可能需要少量时间，随后再连接预览流。

### 4.5 读取预览流

```http
GET {BASE_URL}/api/streaming/cameras/{CAMERA_ID}/preview
Cache-Control: no-cache
```

响应头示例：

```http
HTTP/1.1 200 OK
Content-Type: multipart/x-mixed-replace; boundary=auroraframe7f3d9a2b
X-Frame-Content-Type: image/bmp
Cache-Control: no-cache, no-store, must-revalidate
```

每帧格式如下：

```text
\r\n--auroraframe7f3d9a2b\r\n
Content-Type: image/bmp\r\n
Content-Length: <BMP字节数>\r\n
\r\n
<BMP二进制数据>
```

接入程序应从响应头的 `boundary` 参数读取分隔符，不应永久硬编码当前值。帧体长度必须以每个 Part 的 `Content-Length` 为准，不能通过搜索 BMP 结束标记判断。

流端点在尚无首帧时最多等待约 10 秒。预览未启动、相机没有出帧或处于外触发等待状态时，连接可能在无帧后结束。

### 4.6 停止预览

```http
POST {BASE_URL}/api/app/camera-device/{CAMERA_ID}/stop-preview
Content-Length: 0
```

停止时应先取消本地流读取，再调用此接口。即使流连接已异常断开，也建议调用停止接口释放相机采集资源。

### 4.7 关闭相机

```http
POST {BASE_URL}/api/app/camera-device/{CAMERA_ID}/close-camera
Content-Length: 0
```

关闭相机前应先停止预览。

## 5. 浏览器完整示例

HTML：

```html
<img id="camera-preview" alt="相机预览" />
<button id="start">启动预览</button>
<button id="stop">停止预览</button>
```

JavaScript：

```js
const BASE_URL = "http://192.168.1.100:5000";
const CAMERA_ID = "35e3df33-9fb1-4c44-b521-ea63e188dfc2";

const image = document.querySelector("#camera-preview");
let streamController = null;
let currentObjectUrl = null;

function indexOfBytes(source, pattern, start = 0) {
  outer:
  for (let i = start; i <= source.length - pattern.length; i++) {
    for (let j = 0; j < pattern.length; j++) {
      if (source[i + j] !== pattern[j]) continue outer;
    }
    return i;
  }
  return -1;
}

function appendBytes(left, right) {
  const merged = new Uint8Array(left.length + right.length);
  merged.set(left, 0);
  merged.set(right, left.length);
  return merged;
}

function getBoundary(contentType) {
  const match = /boundary\s*=\s*"?([^";]+)"?/i.exec(contentType || "");
  if (!match) throw new Error("预览响应缺少 multipart boundary");
  return match[1];
}

async function post(path, body) {
  const response = await fetch(`${BASE_URL}${path}`, {
    method: "POST",
    headers: body === undefined ? {} : { "Content-Type": "application/json" },
    body: body === undefined ? undefined : JSON.stringify(body),
    // 使用 Cookie 认证时取消下一行注释：
    // credentials: "include",
  });

  if (!response.ok) {
    throw new Error(`${path} 请求失败：HTTP ${response.status} ${await response.text()}`);
  }
}

async function startPreview() {
  if (streamController) return;

  // 相机已由业务系统提前打开时，可移除此调用。
  await post(`/api/app/camera-device/${CAMERA_ID}/open-camera`);

  await post(`/api/app/camera-device/${CAMERA_ID}/start-preview`, {
    connectionId: null,
    enableRtp: false,
  });

  const controller = new AbortController();
  streamController = controller;

  try {
    const response = await fetch(
      `${BASE_URL}/api/streaming/cameras/${CAMERA_ID}/preview?t=${Date.now()}`,
      {
        signal: controller.signal,
        cache: "no-store",
        // 使用 Cookie 认证时取消下一行注释：
        // credentials: "include",
      },
    );

    if (!response.ok || !response.body) {
      throw new Error(`预览流连接失败：HTTP ${response.status}`);
    }

    const boundary = getBoundary(response.headers.get("Content-Type"));
    const frameMime =
      response.headers.get("X-Frame-Content-Type") || "image/bmp";

    const encoder = new TextEncoder();
    const decoder = new TextDecoder("ascii");
    const separator = encoder.encode(`--${boundary}\r\n`);
    const headersEndMarker = encoder.encode("\r\n\r\n");
    const reader = response.body.getReader();
    let buffer = new Uint8Array(0);

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      if (value?.length) buffer = appendBytes(buffer, value);

      while (true) {
        const separatorIndex = indexOfBytes(buffer, separator);
        if (separatorIndex < 0) break;

        const headersStart = separatorIndex + separator.length;
        const headersEnd = indexOfBytes(buffer, headersEndMarker, headersStart);
        if (headersEnd < 0) break;

        const headerText = decoder.decode(
          buffer.subarray(headersStart, headersEnd),
        );
        const lengthMatch = /^Content-Length:\s*(\d+)\s*$/im.exec(headerText);
        if (!lengthMatch) {
          buffer = buffer.subarray(headersStart);
          continue;
        }

        const frameLength = Number(lengthMatch[1]);
        const payloadStart = headersEnd + headersEndMarker.length;
        const payloadEnd = payloadStart + frameLength;
        if (buffer.length < payloadEnd) break;

        // slice 会复制出独立缓冲，避免后续修改接收 buffer 影响 Blob。
        const frame = buffer.slice(payloadStart, payloadEnd);
        const nextUrl = URL.createObjectURL(
          new Blob([frame], { type: frameMime }),
        );

        image.src = nextUrl;
        if (currentObjectUrl) URL.revokeObjectURL(currentObjectUrl);
        currentObjectUrl = nextUrl;

        buffer = buffer.subarray(payloadEnd);
      }
    }
  } catch (error) {
    if (error?.name !== "AbortError") {
      console.error("预览读取失败", error);
      throw error;
    }
  } finally {
    if (streamController === controller) streamController = null;
  }
}

async function stopPreview() {
  streamController?.abort();
  streamController = null;

  if (currentObjectUrl) {
    URL.revokeObjectURL(currentObjectUrl);
    currentObjectUrl = null;
  }
  image.removeAttribute("src");

  await post(`/api/app/camera-device/${CAMERA_ID}/stop-preview`);
}

document.querySelector("#start").addEventListener("click", () => {
  startPreview().catch(console.error);
});

document.querySelector("#stop").addEventListener("click", () => {
  stopPreview().catch(console.error);
});

window.addEventListener("beforeunload", () => {
  streamController?.abort();
});
```

生产项目还应在页面卸载、路由切换和组件销毁时调用 `stopPreview()`，避免留下采集任务。

## 6. SignalR 接入（推荐）

Hub 地址：

```text
{BASE_URL}/signalr-hubs/camera
```

推荐使用：

- `@microsoft/signalr`
- `@microsoft/signalr-protocol-msgpack`

示例：

```js
import * as signalR from "@microsoft/signalr";
import { MessagePackHubProtocol } from
  "@microsoft/signalr-protocol-msgpack";

const connection = new signalR.HubConnectionBuilder()
  .withUrl(`${BASE_URL}/signalr-hubs/camera`)
  .withHubProtocol(new MessagePackHubProtocol())
  .withAutomaticReconnect([0, 2000, 5000, 10000])
  .build();

connection.on("ReceiveCameraStateAsync", (state) => {
  console.log("相机状态", state);
});

connection.on("ReceiveLiveMetricsAsync", (cameraId, metrics) => {
  console.log("实时指标", cameraId, metrics);
});

await connection.start();

await post(`/api/app/camera-device/${CAMERA_ID}/start-preview`, {
  connectionId: connection.connectionId,
  enableRtp: false,
});
```

常用 Hub 方法：

| 方法 | 参数 | 说明 |
|---|---|---|
| `PingAsync` | 无 | 返回服务器 UTC 毫秒时间戳，可每 15 秒调用一次 |
| `ReattachPreviewAsync` | `cameraId` 字符串 | SignalR 重连后重新绑定预览会话 |

SignalR 连接断开时，服务端会处理该连接关联的预览会话。自动重连成功后，应立即调用：

```js
await connection.invoke("ReattachPreviewAsync", CAMERA_ID);
```

服务端为断线重连保留约 30 秒宽限期。超过宽限期仍未续约，关联预览可能被自动停止。

## 7. 图像格式说明

### 7.1 网络输出格式

第三方收到的每一帧均为完整 BMP 文件：

```text
MIME：image/bmp
像素输出：服务端已完成 Bayer 解包、显示拉伸及解马赛克
典型分辨率：2448 × 2048
```

第三方不需要也不应再次执行 `BAYGB12Packed` 解包。

### 7.2 BAYGB12Packed

`BAYGB12Packed` 是相机传感器侧的原始像素编码。两个 12-bit 像素通常占用 3 字节，理论紧凑行长度为：

```text
ceil(width / 2) × 3
```

宽度为 2448 时：

```text
2448 / 2 × 3 = 3672 字节/行
```

但 TUCam SDK 可能在交付给应用前，将原始 Bayer 帧转换成三通道 8-bit 显示帧。此时实际行长度通常为：

```text
2448 × 3 = 7344 字节/行
```

因此第三方应以网络帧的 BMP 文件头为准，不要根据相机 PixelFormat 名称推断网络帧内存布局。把已经转换的三通道帧再次按 Packed Bayer 解包，会出现上下拼接、画面压缩、错行或颜色异常。

## 8. 错误处理与重连

建议按以下策略处理：

| 场景 | 建议 |
|---|---|
| REST 返回 401/403 | 重新获取令牌或检查账号权限 |
| REST 返回 409 或业务错误 | 检查相机是否被其他客户端占用、系统是否处于手动/检修模式 |
| 启动预览后 10 秒仍无首帧 | 检查相机连接、触发模式、曝光时间和硬件触发信号 |
| HTTP 流正常结束 | 延迟 1～2 秒后重新调用启动流程，最多重试有限次数 |
| Multipart Part 缺少 `Content-Length` | 丢弃当前 Part，从下一个 boundary 重新同步 |
| BMP 解码失败 | 丢弃当前帧，不要断开整个预览 |
| 页面关闭或应用退出 | 取消流读取并调用 `stop-preview` |
| SignalR 自动重连成功 | 调用 `ReattachPreviewAsync(cameraId)` |

不要在没有退避的情况下无限快速重连。推荐重试间隔为：

```text
0 秒、2 秒、5 秒、10 秒，之后保持 10 秒
```

## 9. 性能与资源管理

1. 服务端最多约每 16 ms 发送一帧，即上限约 60 FPS，实际帧率由相机和处理性能决定。
2. BMP 未压缩，2448×2048、24-bit 单帧约为 15 MB；高帧率时带宽占用较大。
3. 浏览器每显示一帧后必须释放上一帧的 Object URL：

   ```js
   URL.revokeObjectURL(previousUrl);
   ```

4. 客户端应始终只显示最新帧。处理速度跟不上时应主动丢弃旧帧，避免帧队列持续增长。
5. 不要把整个 HTTP 响应一次性读入内存；必须使用流式读取。
6. 同一客户端不要为同一相机重复建立多个预览流连接。

## 10. 联调检查清单

- [ ] 能通过列表接口取得相机 GUID。
- [ ] 系统处于手动模式或检修模式。
- [ ] 相机能够成功打开。
- [ ] `start-preview` 返回 HTTP 2xx。
- [ ] 流响应为 `multipart/x-mixed-replace`。
- [ ] `X-Frame-Content-Type` 为 `image/bmp`。
- [ ] 每个 Part 都按自己的 `Content-Length` 读取。
- [ ] BMP 显示分辨率符合预期，例如 2448×2048。
- [ ] 第三方没有再次处理 `BAYGB12Packed`。
- [ ] 停止或退出时调用了 `stop-preview`。
- [ ] SignalR 重连后调用了 `ReattachPreviewAsync`。

## 11. 版本兼容建议

第三方实现应遵守以下兼容原则：

1. 动态读取 Multipart `boundary`。
2. 动态读取 `X-Frame-Content-Type`，缺失时可回退为 `image/bmp`。
3. 忽略 JSON 响应中不认识的新增字段。
4. 不依赖固定 BMP 文件大小。
5. 不依赖固定分辨率或固定帧率。
6. REST 路径、SignalR 方法名和事件名区分大小写时，以本文给出的名称为准。
