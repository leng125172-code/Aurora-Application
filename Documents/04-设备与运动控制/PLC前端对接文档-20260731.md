# PLC 前端对接文档

> 适用版本：AuroraStruct3D PLC 通讯首版  
> 更新日期：2026-07-31  
> 技术栈：Vue 3、TypeScript、Axios、Microsoft SignalR

## 1. 对接范围

前端需要提供两类功能：

1. PLC 管理：设备列表、新增/编辑、连接测试、连接状态和删除。
2. PLC 控制：OPC UA 节点浏览、创建点位、批量读取、手动写入和实时订阅。

当前协议状态：

| 协议 | `driverId` | 前端行为 |
| --- | --- | --- |
| OPC UA | `opc-ua` | 正常启用 |
| 西门子 S7 | `siemens-s7` | 显示“未安装”，禁用选择和操作 |
| 欧姆龙 FINS TCP | `omron-fins-tcp` | 显示“未安装”，禁用选择和操作 |
| 欧姆龙 FINS UDP | `omron-fins-udp` | 显示“未安装”，禁用选择和操作 |
| 基恩士 MC/SLMP | `keyence-mc` | 显示“未安装”，禁用选择和操作 |

前端必须使用驱动目录返回的 `isInstalled` 和 `capabilities` 判断功能，不要把协议支持状态写死。

## 2. 已有前端入口

路由：

```text
/plcs
/plcs/:id/control
```

相关文件：

```text
src/api/plcs.ts
src/views/plcs/PlcManagePage.vue
src/views/plcs/PlcControlPage.vue
src/utils/plc-value-display.ts
```

后端入口：

```text
REST API:   /api/app/plc-device
SignalR:    /signalr-hubs/plc
```

所有请求需要登录令牌。公共 Axios 客户端会自动添加：

```http
Authorization: Bearer <access-token>
X-Client-Session-Id: <client-session-id>
```

`X-Client-Session-Id` 用于写入和配置修改的 PLC 独占会话，同一浏览器会话中应保持稳定。

  Read: 2,
  Write: 4,

### 5.3 创建 OPC UA 设备

```ts
const input: SavePlcDeviceDto = {
  name: '基恩士PLC-01',
  protocol: PlcProtocolType.OpcUa,
  driverId: 'opc-ua',
  isEnabled: true,
  endpointUrl: 'opc.tcp://192.168.1.10:4840',
  authenticationType: PlcAuthenticationType.Anonymous,
  securityPolicy: 'None',
  messageSecurityMode: PlcMessageSecurityMode.None,
  autoTrustServerCertificate: true,
  connectTimeoutMs: 5000,
  operationTimeoutMs: 5000,
  sessionTimeoutMs: 60000,
  keepAliveMs: 5000,
  reconnectInitialMs: 1000,
  reconnectMaxMs: 30000,
  idleTimeoutMs: 600000,
}

const device = (
  await httpClient.post<PlcDeviceDto>('/api/app/plc-device', input)
).data
```

表单显示规则：

- `Anonymous`：隐藏用户名、密码和客户端证书。
- `UserName`：显示用户名和密码。
- `Certificate`：显示客户端证书路径和私钥口令。
- `Sign`、`SignAndEncrypt`：必须同时选择服务端支持的 `securityPolicy`。
- Endpoint 必须以 `opc.tcp://` 开头。

### 5.4 连接测试

```ts
interface PlcConnectionTestResult {
  success: boolean
  error?: string
  durationMs: number
}

const result = (
  await httpClient.post<PlcConnectionTestResult>(
    `/api/app/plc-device/${deviceId}/test-connection`,
  )
).data
```

建议 UI：

- 成功：显示“连接成功（436 ms）”。
- 失败：显示后端 `error`，同时保留重试入口。
- 测试按钮执行期间禁用，避免重复并发请求。

### 5.5 浏览 OPC UA 节点

```ts
interface PlcBrowseResult {
  items: PlcBrowseNode[]
  continuationToken?: string
}

const result = (
  await httpClient.post<PlcBrowseResult>(
    `/api/app/plc-device/${deviceId}/browse`,
    {
      parentAddress: 'ns=4;s=PLC',
      continuationToken: undefined,
      maxResults: 200,
    },
  )
).data
```

交互建议：

- `hasChildren=true`：点击进入子节点。
- `nodeClass='Variable'`：允许加入点位表。
- 建点时使用 `address`，不要使用 `displayName` 代替 NodeId。
- 若返回 `continuationToken`，继续请求下一页并追加节点。
- PLC 工程变化后，NamespaceIndex 可能变化，应允许重新浏览和改点。

### 5.7 批量读取

```ts
const { data } = await httpClient.post<{ items: PlcTagValueDto[] }>(
  `/api/app/plc-device/${deviceId}/read`,
  { tagIds },
)

for (const value of items(data)) {
  valueMap[value.tagId] = value
}
```

状态展示建议：

| 条件 | UI |
| --- | --- |
| `quality === 'Good'` 且无 `error` | 正常颜色 |
| `quality` 不是 `Good` | 黄色警告 |
| 存在 `error` | 红色错误并展示原因 |
| `receivedAt` 长时间未更新 | 显示“数据已过期” |
| 值为空 | 显示 `—`，不要显示为 `0` |

### 5.7.1 统一值展示（标量、数组和 OPC UA 结构体）

`rawValue` 与 `engineeringValue` 是协议原值字段，可能是标量、数组，或 OPC UA
`ExtensionObject` 序列化后的对象。第三方前端不得假设它们始终是数字或字符串，也不要把
复杂对象直接以 `JSON.stringify` 作为默认用户界面。

推荐按以下规则展示；本项目控制页使用
`src/utils/plc-value-display.ts` 实现相同规则：

| 原值类型 | 默认展示 | 详情 |
| --- | --- | --- |
| 标量（布尔、数值、字符串、时间） | 直接显示格式化值 | 不需要 |
| 数组 | 显示“`N` 项” | 按索引显示各元素 |
| 结构体 / `ExtensionObject` | 显示业务摘要 | 展开为“字段名 - 值” |

对于 OPC UA 序列化结构体，先使用 `body` 作为实际负载（如果存在），并在默认展示中忽略
`typeId`、`encoding`、`binaryEncodingId`、`xmlEncodingId`、`jsonEncodingId`、
`innerNodeId` 及其内部的 NodeId 元数据。这些字段用于 OPC UA 编码，不是过程业务值。
原始 JSON 可作为标注“仅调试”的二级折叠内容提供，不能作为默认界面。

例如读取标准节点 `ns=0;i=2256`（`ServerStatus`）时，基恩士 KV OPC UA Server 返回的是
结构体。应展示为类似“`KV OPC UA Server · 运行中`”，详情至少包含：

| 字段 | 推荐中文标签 |
| --- | --- |
| `state` | 状态；`0` 显示为“运行中” |
| `buildInfo.productName` | 产品名称 |
| `buildInfo.manufacturerName` | 厂商 |
| `buildInfo.softwareVersion` | 软件版本 |
| `startTime` / `currentTime` | 启动时间 / 当前时间 |

`ValueChanged` 的 `PlcTagValueDto` 与批量读取使用同一展示规则，确保实时订阅与手动读取
的界面一致。

### 5.8 批量写入

请求中的 `value` 是工程值：

```ts
const { data } = await httpClient.post<{ items: PlcWriteResultDto[] }>(
  `/api/app/plc-device/${deviceId}/write`,
  {
    items: [
      { tagId: tag.id, value: 1 },
    ],
  },
)

const results = items(data)
const failed = results.filter(x => !x.success)
```

必须逐项检查结果。HTTP 200 不代表每个点位都写入成功。

输入控件应按数据类型生成：

| 数据类型 | 控件 |
| --- | --- |
| `Boolean` | Switch/Checkbox |
| 整数、浮点 | NumberInput |
| `String` | TextInput |
| `DateTime` | DateTimePicker |
| `ByteString` | 明确格式的文本或文件输入 |

写入成功后建议立即执行一次读取并更新 UI。不要仅在前端乐观更新。

## 6. SignalR 实时订阅

### 6.1 建立连接

```ts
import {
  HubConnectionBuilder,
  HubConnectionState,
} from '@microsoft/signalr'

const hub = new HubConnectionBuilder()
  .withUrl('/signalr-hubs/plc', {
    accessTokenFactory: () => authStore.token || '',
  })
  .withAutomaticReconnect()
  .build()

hub.on('ValueChanged', (value: PlcTagValueDto) => {
  valueMap[value.tagId] = value
})

hub.on(
  'ConnectionStateChanged',
  (deviceId: string, status: PlcConnectionStatus, error?: string) => {
    if (deviceId !== currentDeviceId.value) return
    connectionStatus.value = status
    connectionError.value = error
  },
)

await hub.start()
```

### 6.2 创建订阅

必须先完成 `hub.start()`，并获得 `hub.connectionId`：

```ts
const { data } = await httpClient.post<{ subscriptionId: string }>(
  `/api/app/plc-device/${deviceId}/subscribe`,
  {
    connectionId: hub.connectionId,
    tagIds,
  },
)

subscriptionId.value = data.subscriptionId
```

每个点位的 `samplingIntervalMs` 和 `deadband` 会用于 OPC UA MonitoredItem。

### 6.3 取消订阅

```ts
await httpClient.post(
  `/api/app/plc-device/${deviceId}/unsubscribe`,
  undefined,
  { params: { subscriptionId: subscriptionId.value } },
)
```

页面卸载顺序：

```ts
onUnmounted(async () => {
  if (subscriptionId.value) {
    await unsubscribe()
  }
  if (hub.state !== HubConnectionState.Disconnected) {
    await hub.stop()
  }
})
```

服务端会在 Hub 异常断开时回收订阅，但前端正常退出仍应主动取消。

### 6.4 自动重连后的处理

SignalR 自动重连后 `connectionId` 可能变化，旧订阅不能继续绑定到新连接。前端应重新创建订阅：

```ts
hub.onreconnected(async () => {
  subscriptionId.value = undefined
  await subscribeCurrentTags()
})
```

点位新增、删除或采样配置变化后，也应先取消旧订阅，再用最新点位列表重新订阅。

## 8. 权限和安全交互

写入、设备配置和点位配置要求系统处于手动或检修模式，并需要 PLC 独占设备会话。

前端遇到以下错误时应给出明确提示：

| 错误内容 | 建议提示 |
| --- | --- |
| 仅允许手动或检修模式 | 引导用户切换系统运行模式 |
| 设备被其他客户端占用 | 显示当前占用信息并禁止写入 |
| 点位只读 | 禁用写入控件 |
| 低于/高于上下限 | 标出合法工程值范围 |
| 驱动未安装 | 禁用连接、浏览、读写和订阅 |
| 服务端证书已变更 | 显示新指纹并要求人工核验 |

证书变化时不得自动点击确认。应显示：

- PLC 名称和 Endpoint。
- 旧证书指纹。
- 新证书指纹。
- 风险提示。
- 仅管理员或检修人员可见的确认按钮。

## 9. 错误处理

统一捕获 ABP/Axios 错误：

```ts
function getErrorMessage(error: unknown): string {
  if (axios.isAxiosError(error)) {
    return error.response?.data?.error?.message
      ?? error.response?.data?.message
      ?? error.message
  }
  return error instanceof Error ? error.message : String(error)
}
```

建议：

- 页面初始化失败时保留“重试”按钮。
- 单次读取失败不要清空最后一次有效值，应标记为陈旧。
- 批量写入逐项展示失败原因。
- SignalR 断开时显示实时监控已中断，不要继续显示“在线”。
- 不在浏览器日志中输出密码、私钥口令或敏感字符串点位值。

## 10. 推荐初始化流程

```text
进入管理页
  → 并行获取设备列表和驱动目录
  → 根据 isInstalled/capabilities 渲染操作
  → 创建或选择 OPC UA 设备
  → 执行连接测试
  → 进入控制页
  → 并行获取设备和点位
  → 浏览 OPC UA 节点
  → 创建业务点位
  → 建立 SignalR
  → 使用 connectionId 创建订阅
  → 接收 ValueChanged 更新 valueMap
  → 页面退出时取消订阅并停止 Hub
```
