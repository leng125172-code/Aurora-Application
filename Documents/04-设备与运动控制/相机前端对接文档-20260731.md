# 相机前端对接文档

> 适用版本：AuroraStruct3D 通用相机驱动版本  
> 更新日期：2026-07-31  
> 技术栈：Vue 3、TypeScript、Axios、Fetch Streams、Microsoft SignalR

## 1. 对接范围

本文说明前端如何接入：

- 相机扫描、列表和基本配置。
- 相机打开、关闭和状态展示。
- 单帧快照。
- HTTP Multipart 实时预览。
- 软件触发、自动曝光和图像旋转。
- GenICam NodeMap 动态参数面板。
- SignalR 状态、指标和节点增量推送。
- 操作日志。

当前相机模块已改为通用驱动模型。前端所有业务绑定必须使用数据库设备 `id`，不得使用 `deviceIndex` 作为稳定标识。

## 2. 前端入口与服务地址

已有前端文件：

```text
src/api/cameras.ts
src/stores/cameras.ts
src/views/cameras/CameraManagePage.vue
src/views/cameras/CameraControlPage.vue
```

服务端入口：

```text
REST API:       /api/app/camera-device
预览流:         /api/streaming/cameras/{cameraId}/preview
SignalR Hub:    /signalr-hubs/camera
```

普通 REST 请求由公共 Axios 客户端自动携带：

```http
Authorization: Bearer <access-token>
X-Client-Session-Id: <client-session-id>
```

流式预览使用 `fetch` 时，需要自行补充认证头和会话头。

## 3. 推荐接入流程

```text
进入相机管理页
  → 扫描硬件并同步数据库
  → 获取相机列表
  → 根据 isOnline、isEnabled、capabilities 渲染操作
  → 打开相机
  → 建立 SignalR 连接
  → 获取 camera-snapshot-state 恢复页面
  → 调用 start-preview，并传入 SignalR connectionId
  → fetch 连接 Multipart 预览流
  → 持续解析 BMP 帧并替换 Object URL
  → 接收状态、指标和 GenICam 增量事件
  → 停止预览、取消 fetch、释放 Object URL
  → 按需关闭相机
```

## 4. 枚举和能力位

### 4.1 相机状态

```ts
export enum CameraStatus {
  Unknown = 0,
  Ready = 1,
  Capturing = 2,
  Error = 3,
  Closed = 4,
}
```

### 4.2 相机能力

```ts
export enum CameraCapability {
  Preview = 1 << 0,           // 1
  Snapshot = 1 << 1,          // 2
  SoftwareTrigger = 1 << 2,   // 4
  ExternalTrigger = 1 << 3,   // 8
  ParameterNodes = 1 << 4,    // 16
  Temperature = 1 << 5,       // 32
  RtpStream = 1 << 6,         // 64
  ConcurrentPreview = 1 << 7, // 128
  ConcurrentTrigger = 1 << 8, // 256
}

export function hasCameraCapability(
  camera: CameraDeviceDto,
  capability: CameraCapability,
) {
  return (camera.capabilities & capability) === capability
}
```

按钮启用条件至少包含：

```ts
const canOperate = camera.isEnabled && camera.isOnline

const canPreview = canOperate
  && hasCameraCapability(camera, CameraCapability.Preview)
```

能力缺失时前端应隐藏或禁用操作，后端仍会进行二次校验。

## 5. 核心 TypeScript 类型

### 5.1 相机设备

```ts
export interface CameraDeviceDto {
  id: string
  creationTime: string
  creatorId: string | null
  lastModificationTime: string | null
  lastModifierId: string | null

  name: string
  model: string | null
  driverId: string
  hardwareId: string | null
  connectionSummary: string | null
  capabilities: CameraCapability
  isOnline: boolean

  deviceIndex: number
  status: CameraStatus
  statusText: string
  description: string | null
  isEnabled: boolean
  imageRotationAngle: number
}

export interface GetCameraListDto {
  filter?: string
  skipCount?: number
  maxResultCount?: number
}

export interface UpdateCameraDeviceDto {
  name: string
  description?: string
  isEnabled: boolean
}
```

注意：

- `id`：前端路由、状态缓存和接口调用的唯一业务主键。
- `driverId + hardwareId`：硬件稳定身份，仅用于展示和诊断。
- `deviceIndex`：SDK 当前枚举位置，只是兼容字段。
- `hardwareId` 可能包含序列号，日志和截图中应脱敏。
- `isOnline=false` 时保留设备记录，但禁用硬件操作。

| 方法 | 路由 | 说明 |
| --- | --- | --- |
| `GET` | `/api/app/camera-device` | 相机分页列表 |
| `GET` | `/api/app/camera-device/{id}` | 相机详情 |
| `PUT` | `/api/app/camera-device/{id}` | 更新名称、描述和启用状态 |

### 6.5 设备信息

```ts
export interface CameraDeviceInfoDto {
  model: string
  serialNumber: string
  firmwareVersion: string
  fpgaVersion: string
  fpgaTemperature: number | null
  sensorTemperature: number | null
```

## 8. 实时预览

### 8.1 启动和停止

先建立 SignalR 连接，再将 `connectionId` 传给启动接口：

```ts
await httpClient.post(
  `${BASE}/${cameraId}/start-preview`,
  {
    connectionId: cameraHub.connectionId,
    enableRtp: false,
  },
)
```

停止：

```ts
await httpClient.post(`${BASE}/${cameraId}/stop-preview`)
```

启动成功只代表服务端开始采集。前端还需要连接图像流：

```text
GET /api/streaming/cameras/{cameraId}/preview
```

### 8.2 图像流协议

| 项目 | 值 |
| --- | --- |
| 响应类型 | `multipart/x-mixed-replace` |
| 帧类型 | `image/bmp` |
| Boundary | 从响应 `Content-Type` 动态解析 |
| 帧长度 | 每个 Part 的 `Content-Length` |
| Bayer 解包 | 服务端完成 |
| 客户端解 Bayer | 禁止 |

重要：

- 不能把流 URL 直接赋给 `<img src>`。
- 不能把帧按 JPEG 解码。
- 不能硬编码 boundary。
- 网络 Chunk 不等于一帧；boundary、Header 和 BMP Payload 都可能跨 Chunk。
- 只能保留最新帧，不能无限累积历史帧。

### 8.3 Fetch 连接

```ts
const controller = new AbortController()

const response = await fetch(
  `/api/streaming/cameras/${cameraId}/preview?t=${Date.now()}`,
  {
    method: 'GET',
    headers: {
      Authorization: `Bearer ${accessToken}`,
      'X-Client-Session-Id': clientSessionId,
    },
    cache: 'no-store',
    signal: controller.signal,
  },
)

if (!response.ok || !response.body) {
  throw new Error(`预览流连接失败：HTTP ${response.status}`)
}
```

从响应头解析 boundary：

```ts
function getBoundary(contentType: string | null): string {
  const match = contentType?.match(
    /boundary=(?:"([^"]+)"|([^;,\s]+))/i,
  )
  const value = match?.[1] ?? match?.[2]
  if (!value) throw new Error('预览响应缺少 multipart boundary')
  return value
}
```

解析器必须以字节处理协议，不应先把整个响应转换成字符串。推荐复用现有 `src/stores/cameras.ts` 中的增量解析实现。

### 8.4 显示和释放帧

收到完整 BMP Payload 后：

```ts
function replaceFrame(frameBytes: Uint8Array) {
  const nextUrl = URL.createObjectURL(
    new Blob([frameBytes], { type: 'image/bmp' }),
  )

  const previous = previewUrl.value
  previewUrl.value = nextUrl

  if (previous) {
    URL.revokeObjectURL(previous)
  }
}
```

停止或页面卸载：

```ts
controller.abort()
await reader.cancel().catch(() => undefined)
reader.releaseLock()

if (previewUrl.value) {
  URL.revokeObjectURL(previewUrl.value)
  previewUrl.value = null
}
```

### 8.5 首帧与重连

- 服务端最多等待约 10 秒首帧。
- 启动预览后再连接流，避免首帧等待超时。
- 流断开后使用有限次数指数退避重连。
- 每个相机只能存在一个活动读取器。
- 重连前先终止旧 `AbortController`。

## 9. SignalR 对接

### 9.1 建立连接

```ts
import * as signalR from '@microsoft/signalr'

const hub = new signalR.HubConnectionBuilder()
  .withUrl('/signalr-hubs/camera', {
    accessTokenFactory: () => accessToken,
  })
  .withAutomaticReconnect()
  .build()
```

Hub 当前允许匿名连接，但已登录前端仍应提供令牌，避免部署策略变化后失效。

### 9.2 前端监听事件

| 事件 | 参数 | 用途 |
| --- | --- | --- |
| `ReceiveCameraStateAsync` | `CameraStateDto` | 相机完整状态 |
| `ReceiveLiveMetricsAsync` | `cameraId, CameraLiveMetricsDto` | 温度、帧率和评分 |
| `OnGenICamNodesChangedAsync` | `cameraId, changes[]` | 节点值/权限增量 |
| `OnGenICamNodeMapReloadedAsync` | `cameraId, enumeratedAt` | NodeMap 已重建 |

`ReceiveCameraFrameAsync` 不是当前 Web 预览的主要图像通道；前端应使用 HTTP Multipart 流。

注册示例：

```ts
hub.on('ReceiveCameraStateAsync', (state: CameraStateDto) => {
  cameraStates.set(state.cameraId, state)
})

hub.on(
  'ReceiveLiveMetricsAsync',
  (cameraId: string, metrics: CameraLiveMetricsDto) => {
    cameraMetrics.set(cameraId, metrics)
  },
)

hub.on(
  'OnGenICamNodesChangedAsync',
  (cameraId: string, changes: GenICamNodeChangeDto[]) => {
    patchNodeMap(cameraId, changes)
  },
)

hub.on(
  'OnGenICamNodeMapReloadedAsync',
  async (cameraId: string) => {
    nodeMaps.set(cameraId, await getCameraNodeMap(cameraId))
  },
)
```

### 9.5 心跳与断线续约

前端可周期调用：

```ts
const serverTime = await hub.invoke<number>('PingAsync')
```

SignalR 重连后，在 30 秒宽限期内重新绑定预览会话：

```ts
hub.onreconnected(async () => {
  for (const cameraId of previewingCameraIds) {
    await hub.invoke<boolean>('ReattachPreviewAsync', cameraId)
    const snapshot = await getCameraSnapshotState(cameraId)
    restoreCameraUi(snapshot)
  }
})
```

若未能在宽限期内续约，服务端会清理该 SignalR 连接启动的预览。

| `nodeType` | 推荐控件 |
| --- | --- |

```http

```

### 11.5 节点写入

```http
POST /api/app/camera-device/{id}/set-gen-iCam-param
```

单节点：

```json
{
  "nodeName": "ExposureTime",
  "dataType": "float",
  "value": "5000"
}
```

批量：

```json
{
  "nodes": [
    { "nodeName": "ExposureTime", "value": "5000" },
    { "nodeName": "Gain", "value": "1.5" }
  ]
}
```

数值统一用 InvariantCulture 字符串传输，小数点使用 `.`。

### 11.6 命令节点

```ts
await httpClient.post(
  `${BASE}/${cameraId}/execute-gen-iCam-command`,
  'AcquisitionStart',
  { headers: { 'Content-Type': 'application/json' } },
)
```

请求体是 JSON 字符串，不是 `{ nodeName: ... }`。

### 11.7 增量更新

收到 `OnGenICamNodesChangedAsync` 后，按 `nodeName` 更新本地 NodeMap：

```ts
function patchNodeMap(
  cameraId: string,
  changes: GenICamNodeChangeDto[],
) {
  const map = nodeMaps.get(cameraId)
  if (!map) return

  const byName = new Map(map.allNodes.map(node => [node.nodeName, node]))
  for (const change of changes) {
    const node = byName.get(change.nodeName)
    if (!node) continue
    node.currentValue = change.value
    if (change.access) node.access = change.access
    node.isLocked = change.isLocked
  }
}
```

收到 `OnGenICamNodeMapReloadedAsync` 才重新拉取整张 NodeMap。

## 14. 独占会话和运行模式

硬件控制、参数写入和预览通常要求系统处于手动或检修模式，并由当前客户端持有设备会话。

前端必须：

- 为所有 REST 和预览流请求携带同一个 `X-Client-Session-Id`。
- 不在多个标签页生成相同的并发控制流程。
- 遇到设备占用错误时显示占用人信息。
- 页面只读查看与硬件写操作分开控制。
- 自动操作失败时不循环强制抢占。

## 15. 错误处理

ABP 业务错误示例：

```json
{
  "error": {
    "message": "相机 [设备名称] 的驱动不支持 Temperature 能力",
    "details": null,
    "data": {},
    "validationErrors": null
  }
}
```

前端优先展示：

```ts
function getApiErrorMessage(error: unknown): string {
  if (axios.isAxiosError(error)) {
    return error.response?.data?.error?.message
      ?? error.response?.data?.message
      ?? error.message
  }
  return error instanceof Error ? error.message : String(error)
}
```

预览错误需要区分：

- 启动预览接口失败。
- HTTP 流连接失败。
- 首帧超时。
- 流读取中断。
- Multipart 格式错误。
- SignalR 断开。
- 相机离线或被占用。

## 16. 页面卸载清理

控制页卸载时至少执行：

```ts
onUnmounted(async () => {
  stopHeartbeat()
  abortPreviewStream(cameraId)
  revokePreviewObjectUrl(cameraId)

  if (shouldStopServerPreview) {
    await stopPreview(cameraId).catch(() => undefined)
  }

  if (hub.state !== signalR.HubConnectionState.Disconnected) {
    await hub.stop()
  }
})
```

若产品需要支持路由切换后 30 秒内恢复预览，可不立即调用服务端 `stop-preview`，但必须在 SignalR 重连后调用 `ReattachPreviewAsync`。明确退出预览时应立即停止。

## 18. 前端验收清单

- [ ] 扫描结果按驱动展示成功、冲突和错误。
- [ ] 列表使用数据库 `id`，不使用 `deviceIndex` 作为主键。
- [ ] 离线或禁用相机不能执行硬件操作。
- [ ] 按 `capabilities` 控制预览、快照、触发、参数和温度功能。
- [ ] 温度 `null` 显示为不可用而非 0。
- [ ] 快照能显示 JPEG Data URI。
- [ ] 预览使用 Fetch Streams，不直接使用流 URL 作为图片地址。
- [ ] Multipart boundary 和 `Content-Length` 支持跨 Chunk。
- [ ] 每帧按 BMP 创建 Blob。
- [ ] 新帧替换后释放旧 Object URL。
- [ ] 停止和卸载时取消 reader 与 AbortController。
- [ ] SignalR 能接收状态和实时指标。
- [ ] SignalR 重连后能续约预览并恢复状态快照。
- [ ] GenICam 参数面板依据 NodeMap 动态生成。
- [ ] 节点增量事件只更新变化节点。
- [ ] NodeMap 重载事件会重新拉取整张表。
- [ ] 参数写入使用 InvariantCulture 字符串。
- [ ] 独占会话冲突和运行模式错误有明确提示。
- [ ] 操作日志支持失败筛选和分页。
