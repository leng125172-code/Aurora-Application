# 流程库接口对接说明

版本：1.1  
更新日期：2026-09-09  
适用模块：工作流模板库、工作流编辑器

## 1. 功能说明

流程库用于保存可复用的工作流模板，并从模板创建项目工作流。

核心规则：

- 模板保存的是来源工作流当时的 `graphData` 快照。
- 从模板创建的是新的独立工作流，具有新的工作流 ID。
- 修改或删除模板，不会影响已经创建的工作流。
- 修改实例化后的工作流，不会反向修改模板。
- 模板创建、更新时，前端只提交来源工作流 ID，不需要上传 `graphData`。
- 模板实例化时会执行现有工作流的图校验、变量编译、源码生成、哈希和版本初始化。
- 只有工作流创建成功后，模板的 `usageCount` 才会加一。

## 2. 通用约定

### 2.1 基础地址

所有接口均使用当前 AuroraStruct3D 服务地址：

```text
{baseUrl}/api/app/workflow-template
```

同源前端可直接使用相对地址：

```text
/api/app/workflow-template
```

### 2.2 鉴权

全部接口要求用户已登录，并具有系统操作权限。

```http
Authorization: Bearer {accessToken}
Content-Type: application/json
```

多租户部署时增加租户请求头：

```http
__tenant: {tenantId}
```

### 2.3 数据格式

- 请求和响应编码：UTF-8。
- 请求和响应格式：JSON。
- GUID 使用标准字符串格式。
- 时间使用 ISO 8601 字符串。
- JSON 字段采用 camelCase。

### 2.4 接口清单

| 功能 | 方法 | 路径 |
| --- | --- | --- |
| 查询模板列表 | GET | `/api/app/workflow-template` |
| 查询模板详情 | GET | `/api/app/workflow-template/{id}` |
| 当前工作流保存为模板 | POST | `/api/app/workflow-template` |
| 使用当前工作流覆盖模板 | PUT | `/api/app/workflow-template/{id}` |
| 从模板创建工作流 | POST | `/api/app/workflow-template/{id}/instantiate` |
| 删除模板 | DELETE | `/api/app/workflow-template/{id}` |

## 3. 数据结构

### 3.1 模板列表项 WorkflowTemplateListItem

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string(UUID) | 是 | 模板 ID |
| `name` | string | 是 | 模板名称，最大 128 字符 |
| `graphData` | object | 是 | 模板保存的工作流图快照，固定包含 `nodes` 和 `edges` |

### 3.2 模板详情 WorkflowTemplate

模板详情包含 `id`、`name` 和 `graphData`，另外包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `category` | string | 分类；允许空字符串 |
| `description` | string/null | 模板说明 |
| `sourceWorkflowId` | string(UUID)/null | 最近一次生成模板快照的来源工作流 ID |
| `usageCount` | integer | 成功实例化次数 |
| `creationTime` | string(datetime) | 创建时间 |
| `creatorId` | string(UUID)/null | 创建人 ID |
| `lastModificationTime` | string(datetime)/null | 最后修改时间 |
| `lastModifierId` | string(UUID)/null | 最后修改人 ID |
| `isDeleted` | boolean | 是否软删除 |
| `deletionTime` | string(datetime)/null | 删除时间 |
| `deleterId` | string(UUID)/null | 删除人 ID |

### 3.3 工作流图 graphData

```json
{
  "nodes": [
    {
      "id": "start-1",
      "type": "start-node",
      "x": 120,
      "y": 180,
      "text": {
        "value": "开始"
      },
      "properties": {
        "params": {},
        "paramSources": {},
        "inputBindings": {},
        "inputBindingSources": {},
        "outputBindings": {},
        "outputBindingSources": {}
      }
    }
  ],
  "edges": []
}
```

模板库接口的创建和更新操作不接收 `graphData`。列表、详情以及实例化后的工作流响应会将其作为 JSON 对象返回，而不是转义后的 JSON 字符串。

## 4. 查询模板列表

```http
GET /api/app/workflow-template
```

### 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `filter` | string | 否 | 对模板名称、分类和说明执行包含匹配 |
| `category` | string | 否 | 分类精确匹配 |

两个参数同时传递时按 AND 条件组合。结果按最后修改时间倒序排列；当前接口不分页。

### 请求示例

```bash
curl -X GET "https://server.example.com/api/app/workflow-template" \
  -H "Authorization: Bearer ${TOKEN}"
```

### 成功响应：200 OK

```json
[
  {
    "id": "模板ID",
    "name": "双相机平面检测",
    "graphData": {
      "nodes": [],
      "edges": []
    }
  }
]
```

没有模板时返回空数组 `[]`。

## 6. 当前工作流保存为模板

```http
POST /api/app/workflow-template
```

后端根据 `workflowId` 读取已经保存的工作流，并复制其 `graphData`。因此前端调用前应先保存当前工作流，否则模板中可能是旧版本内容。

### 请求字段

| 字段 | 类型 | 必填 | 约束与说明 |
| --- | --- | --- | --- |
| `workflowId` | string(UUID) | 是 | 来源工作流 ID，不能是空 GUID |
| `name` | string | 是 | 模板名称，去除首尾空白后不能为空，最大 128 字符 |
| `category` | string | 否 | 分类，默认空字符串，最大 64 字符 |
| `description` | string/null | 否 | 使用说明，最大 1024 字符 |

### 请求示例

```json
{
  "workflowId": "778149f7-f632-4075-9d3e-f36489794d04",
  "name": "双相机平面检测",
  "category": "三维检测",
  "description": "使用前修改标定项目、ROI 和高度阈值"
}
```

```bash
curl -X POST "https://server.example.com/api/app/workflow-template" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "workflowId":"778149f7-f632-4075-9d3e-f36489794d04",
    "name":"双相机平面检测",
    "category":"三维检测",
    "description":"使用前修改标定项目、ROI 和高度阈值"
  }'
```

### 成功响应：200 OK

返回完整 `WorkflowTemplate`，包含后端生成的模板 `id` 和模板图 `graphData`。

## 7. 使用当前工作流覆盖模板

```http
PUT /api/app/workflow-template/{id}
```

该接口会同时更新模板名称、分类、说明和流程图快照。新的流程图快照取自请求中的 `workflowId`。

已经从该模板创建出的工作流不会被更新。

### 请求字段

请求结构与“当前工作流保存为模板”一致。

```json
{
  "workflowId": "b6f9eac0-4b62-479e-9dfa-b388b71c97e4",
  "name": "双相机平面检测 V2",
  "category": "三维检测",
  "description": "增加点云离群点清理节点"
}
```

### 成功响应：200 OK

返回更新后的完整 `WorkflowTemplate`。

更新模板不会清零 `usageCount`。

## 8. 从模板创建工作流

```http
POST /api/app/workflow-template/{id}/instantiate
```

### 请求字段

| 字段 | 类型 | 必填 | 约束与说明 |
| --- | --- | --- | --- |
| `projectId` | string(UUID) | 是 | 新工作流所属项目 ID，不能是空 GUID |
| `name` | string | 是 | 新工作流名称，最大 256 字符 |

### 请求示例

```json
{
  "projectId": "46ff4f89-3f4c-42d8-baf3-59b052137081",
  "name": "工件 A 平面检测"
}
```

```bash
curl -X POST "https://server.example.com/api/app/workflow-template/1b46b1a7-1bc6-4ad2-9a9a-9023256829ba/instantiate" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "projectId":"46ff4f89-3f4c-42d8-baf3-59b052137081",
    "name":"工件 A 平面检测"
  }'
```

### 成功响应：200 OK

返回新建的标准工作流对象：

```json
{
  "id": "957bcb00-26df-4d12-b7d9-c8de545cb58d",
  "projectId": "46ff4f89-3f4c-42d8-baf3-59b052137081",
  "name": "工件 A 平面检测",
  "graphData": {
    "nodes": [],
    "edges": []
  },
  "outputVariables": "[]",
  "creationTime": "2026-09-08T10:00:00",
  "creatorId": "ab83a458-3dd2-4c3d-8691-121a01e9b75c",
  "lastModificationTime": "2026-09-08T10:00:00",
  "lastModifierId": "ab83a458-3dd2-4c3d-8691-121a01e9b75c",
  "isDeleted": false,
  "deletionTime": null,
  "deleterId": null
}
```

注意：`outputVariables` 当前是保存 JSON 数组的字符串，不是原生数组。

实例化成功后，前端应使用响应中的 `id` 作为新工作流 ID，然后调用：

```http
GET /api/app/workflow/{id}/source
```

加载新流程的脚本、修订号和画布内容进入编辑器。

### 可能的业务错误

- 项目 ID 为空。
- 新工作流名称为空或超长。
- 模板不存在或已删除。
- 模板中的工作流图无效。
- 模板引用的算子契约已经失效。
- 工作流图校验未通过。
- 项目变量编译未通过。

实例化失败时不会增加模板使用次数，也不会保留不完整的新工作流。

## 9. 删除模板

```http
DELETE /api/app/workflow-template/{id}
```

### 请求示例

```bash
curl -X DELETE "https://server.example.com/api/app/workflow-template/1b46b1a7-1bc6-4ad2-9a9a-9023256829ba" \
  -H "Authorization: Bearer ${TOKEN}"
```

### 成功响应

返回 2xx 且没有业务响应体。模板采用软删除；已经从模板创建的项目工作流不受影响。

## 10. 错误响应

失败响应使用 ABP 通用错误结构：

```json
{
  "error": {
    "code": null,
    "message": "请输入新工作流名称。",
    "details": null,
    "validationErrors": null
  }
}
```

参数校验错误示例：

```json
{
  "error": {
    "code": null,
    "message": "Your request is not valid!",
    "details": "The following errors were detected during validation.",
    "validationErrors": [
      {
        "message": "The Name field is required.",
        "members": ["name"]
      }
    ]
  }
}
```

常见 HTTP 状态：

| 状态码 | 说明 | 客户端处理建议 |
| --- | --- | --- |
| 400 | JSON、GUID 或字段校验失败 | 显示 `error.message`，必要时展开 `validationErrors` |
| 401 | 未登录或令牌失效 | 清除本地登录态并跳转登录页 |
| 403 | 当前用户无操作权限或业务请求被拒绝 | 显示 `error.message` |
| 404 | 模板或来源工作流不存在 | 刷新模板/工作流列表 |
| 409 | 并发或数据状态冲突 | 刷新数据后重试 |
| 500 | 未处理的服务器异常 | 记录请求信息并提示稍后重试 |

客户端不要依赖固定的错误文案判断业务状态，应以 HTTP 状态码为主，并将 `error.message` 展示给用户。

## 11. 前端 TypeScript 对接示例

```ts
import axios from 'axios'

const api = axios.create({ baseURL: '/' })

api.interceptors.request.use((config) => {
    config.headers.Authorization = `Bearer ${accessToken}`
    if (tenantId) config.headers.__tenant = tenantId
    return config
})

export interface WorkflowTemplateBrief {
    id: string
    name: string
    graphData: {
        nodes: unknown[]
        edges: unknown[]
    }
}

export interface SaveWorkflowTemplate {
    workflowId: string
    name: string
    category: string
    description?: string
}

export async function listWorkflowTemplates() {
    return (await api.get<WorkflowTemplateBrief[]>('/api/app/workflow-template')).data
}

export async function saveWorkflowAsTemplate(input: SaveWorkflowTemplate) {
    return (await api.post('/api/app/workflow-template', input)).data
}

export async function overwriteWorkflowTemplate(
    templateId: string,
    input: SaveWorkflowTemplate,
) {
    return (await api.put(`/api/app/workflow-template/${templateId}`, input)).data
}

export async function instantiateWorkflowTemplate(
    templateId: string,
    projectId: string,
    name: string,
) {
    return (
        await api.post(`/api/app/workflow-template/${templateId}/instantiate`, {
            projectId,
            name,
        })
    ).data as { id: string; projectId: string; name: string }
}

export async function deleteWorkflowTemplate(templateId: string) {
    await api.delete(`/api/app/workflow-template/${templateId}`)
}
```

## 12. 推荐对接流程

### 12.1 保存当前流程为模板

1. 保存当前工作流，确保后端工作流内容是最新版本。
2. 调用 `POST /api/app/workflow-template`。
3. 使用响应中的模板 `id` 更新本地模板列表。

### 12.2 从模板创建工作流

1. 调用模板列表接口并让用户选择模板。
2. 让用户选择目标项目并输入新工作流名称。
3. 调用 `POST /api/app/workflow-template/{id}/instantiate`。
4. 保存响应中的新工作流 `id`。
5. 调用 `GET /api/app/workflow/{id}/source` 加载新工作流。
6. 用户修改相机、标定项目、产品模型、ROI、阈值等项目相关参数。
7. 用户按需要增加或删除其他功能节点。
8. 调用现有工作流保存接口保存修改。
